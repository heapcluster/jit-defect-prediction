# 蛋神的蛋-1 在线预测能力对齐

> 负责人：蛋神的蛋｜优先级：P1｜关联：产品价值 10 分、演示验收

## 一句话任务

把已交付的 **25 个模型全部接进在线预测**（现在只接了 expert 8 个），并修好「详情显示未预测」「进度切页面就丢」两个 bug。

## 为什么做

课程 §1 要求模型模块"不少于 8 种预测模型"，我们实际交付了 25 个（expert 8 / semantic 8 / fused 8 / e2e 1）。但现在对外展示 25 个、线上只能预测 8 个，演示时点一个 semantic 模型就报错，等于把交付量变成了 bug。必须把口径对齐。

## 你要做什么

1. **盘点权重**：逐个看 `data_model/pipelines/{expert,semantic,fused,e2e}/models/` 下哪些模型有权重、能否加载，理清「可在线 / 仅离线」。
2. **接入在线预测**：改 `backend/app/model_registry.py`，把 semantic / fused / e2e 的权重也加载进来，让 25 个模型都能预测；确实无法加载的，在接口返回明确原因，不允许 500。
3. **修详情 bug**：`backend/app/api/commits.py` 的 `commit_detail` 目前只查默认模型的 prediction，改成按与列表一致的 `model_name` 查询。
4. **修进度 bug**：`frontend/src/views/RiskList.vue` 的同步进度是组件内状态，切路由就丢，改成全局状态（或进页查询 `/api/sync/status` 恢复）。
5. **自己验证**：本地把 25 个模型逐个点一遍预测、切页面看进度、列表进详情核对，确认功能通过。

## 交付物

- 25 模型可在线预测的代码改动。
- 两个 bug 的修复。

> 说明：**不需要你留存截图或测试记录**，自己跑通、功能通过、答辩时能讲清楚就行；证据归档由测试/文档环节负责。

## 什么算合格（验收清单）

- [ ] `/api/models` 列出的 25 个模型都能选中并实际预测成功；确实无法加载的给出明确提示（不是 500）。
- [ ] 列表显示概率的条目，点进详情显示的是同一模型的概率，不再"未预测"。
- [ ] 预测/同步中切到别的页面再回来，进度仍在或能恢复。
- [ ] 不破坏 `/api/models` 返回结构。
- [ ] 你自己跑通并**能讲清楚**：25 个模型怎么接入的、两个 bug 的根因与修法。

## 不要做什么

- 不改模型训练/交付流程，只做"接入"。
- 不伪造预测结果。
- 不动 `/api/models` 的响应结构。

## 依赖与协作
