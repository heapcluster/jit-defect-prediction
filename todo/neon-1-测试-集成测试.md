# neon-1 集成测试

> 负责人：neon｜优先级：P0｜关联：测试实践 25 分

## 一句话任务

以运行时 `/openapi.json` 为准，对**所有实际 API 端点**做「正常 / 缺参 / 非法参 / 边界值」四类场景测试，补跨模块链路和并发场景。

## 为什么做

集成测试也占 25 分：接口覆盖率 7、场景完整性 7、断言有效性 5、跨模块链路 3、数据文档 3。课程明确要求覆盖当前系统真实存在的接口，不能拿示例 `/api/upload`、`/api/history` 凑数。

## 你要做什么

1. **建端点清单**：从 `/openapi.json` 拉出当前全部端点（commits、commits/{hash}、predict、sync、sync/status、models、trends、figures、health、health/live、health/ready），逐个登记。
2. **每端点四类场景**：正常、缺参、非法参、边界值，各写用例。
3. **业务断言**：断言状态码、响应包络、字段类型/范围、业务逻辑，不能只看请求成功。
4. **跨模块链路**：至少一条"特征抽取 → 模型推理 → 落库 → API 查询 → 前端展示"的真实链路。
5. **并发场景**：至少一个并发请求场景并在报告里说明。
6. **留证据**：接口测试报告（端点清单、通过/失败数、异常与复现）、联调截图/录屏，填 `docs/common/integration-log.md`。

## 交付物

- 集成测试代码 / Postman 集合。
- 接口测试报告（列端点和结果）。
- 前后端联调截图或录屏。
- 填好的 `integration-log.md`。

## 什么算合格（验收清单）

- [ ] 端点覆盖率 100%（7 分）。
- [ ] 每个端点四类场景齐全（7 分）。
- [ ] 断言覆盖状态码、结构、字段范围、业务逻辑（5 分）。
- [ ] 至少一条完整跨模块链路（3 分）。
- [ ] 正常/异常数据集与文档清楚、数据脱敏（3 分）。
- [ ] 联调记录注明测试提交与环境。

## 不要做什么

- 不测不存在的接口。
- 不把"请求成功"当通过。
