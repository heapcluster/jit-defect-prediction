# neon-4 缺陷与 PR 管理

> 负责人：neon｜优先级：P1｜关联：过程实践 40 分

## 一句话任务

把测试中发现的缺陷用 Issue / 飞书缺陷记录逐个登记并跟踪到关闭；所有 PR 合并前至少有 1 位非作者审阅且留痕。

## 为什么做

课程 §4 要求"使用缺陷管理工具""PR 合并前至少一位非作者成员审阅，审阅意见保留在平台"，§5.4 要求缺陷至少记录现象、复现条件、优先级、处理状态和关联提交/change。目前仓库这些过程记录基本为空，是过程分的明显缺口。

## 你要做什么

1. **缺陷登记**：每条缺陷记 Issue（或飞书缺陷表）：现象、复现步骤、预期与实际、优先级、状态、关联提交/change。
2. **跟踪闭环**：跟踪到修复 → 复测 → 关闭，保留复测记录。
3. **PR 审阅**：合并前至少 1 位非作者审阅并留意见；不再用"临时关掉分支保护"的方式强合。
4. **关联证据**：缺陷与 PR、commit、OpenSpec change 互相关联。

## 交付物

- 缺陷清单（Issue / 飞书缺陷记录）。
- PR 审阅记录。

## 什么算合格（验收清单）

- [ ] 每条缺陷字段齐全（现象/复现/优先级/状态/关联提交）。
- [ ] 缺陷状态可追踪，有修复与复测记录。
- [ ] 关键 PR 有非作者审阅意见留痕。
- [ ] 缺陷与提交/change 能对上。

## 不要做什么

- 不补造审阅记录。
- 不把未修复的缺陷标成已关闭。
