# 蛋神的蛋 — 工程化与容器化

> 任务编号：DS-1｜负责人：蛋神的蛋｜板块：工程化｜优先级：P1
> 依赖：无（可与 DS-2/DS-3 并行）｜关联评分：软件开发过程实践（40）

## 目标

让系统具备可复现的一键部署方式，并提供模型/特征的插件式扩展能力。

## 依据（docs/common 原文）

> 系统主要功能模块：……工程化（Git 分支规范 + 代码评审；CI/CD流水线、插件化等）。——《docs/common/project-requirements.md》

> Sprint 1：……（可选）配置自动化流水线CI/CD，在提交或PR时执行构建和自动化测试。——同上

## 范围

**做：**
- 容器化：后端、前端、MySQL 组成的可一键启动运行方式，换机器可复现。
- 插件化：模型/特征可外部注册扩展，附扩展说明。
- 交付说明：启动方式、依赖、环境变量清单。

**不做：**
- 不改业务逻辑与接口契约（`docs/api/*`、`docs/database/*`）。
- 不改 CI 流水线脚本（归 sober，见 S-1）。
- 不提交模型权重、数据集、`.env` 或密钥。

## 当前未完成

CI 已存在；容器化与插件化均未落地。

## 输入

- 现有 `backend/`、`frontend/` 依赖与启动方式。
- `infra/schema.sql`（5 表建表脚本）。
- 模型交付清单与特征列序约定。

## 输出（交付物）

| 交付物 | 形式 | 说明 |
|---|---|---|
| 容器化运行方案 | Dockerfile / compose 等 | 能起全栈 |
| 插件扩展机制 | 代码 + 说明文档 | 新增模型/特征不改核心 |
| 启动说明 | Markdown | 环境变量与步骤 |

## 依赖与前置

- 前置：`infra/schema.sql` 可执行；模型目录可访问。
- 协作：CI 侧校验与产物归档由 **sober** 负责。

## 验收标准

- [ ] 在干净环境可一键启动全栈。
- [ ] `GET /api/health` 返回 `code:0`、`db:up`。
- [ ] 新增一个模型/特征不需要修改核心逻辑。
- [ ] 交付物中不含任何密钥或大文件。

## 约束（用 agent 执行）

- 只动容器化与插件相关文件，不越界改业务代码。
- 不修改契约文档与接口结构。
