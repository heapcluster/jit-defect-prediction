## 分配原则

- 按能力分配：代码与单元测试归蛋神的蛋；集成/系统/验收/调度与项目管理（周报/看板/讨论）归 neon；仓库 docs/ 治理（断链/规范/OpenSpec 归档）与测试文档归 sober；飞书两文档按文档拆分 —— 《产品需求文档》归 lsh（`L-4`）、《产品设计文档》归 lsh（`L-5`）；公开数据集 / Demo 归 lsh。
- 一份文档一个任务、一个负责人；`L-4` 与 `L-5` 按文档边界拆分，不重叠。
- 编号连续、顺序按 DS → N → S → L 升序；历史编号变动见「编号变更记录」。
- 一份任务只有一个负责人，不重叠；跨人依赖写在"依赖与前置"里。
- 未完成项才进本目录，已完成项不重复。

## 完成定义（DoD）

- 每项任务有交付物与可核对的验收标准。

- 归档 change 后 `openspec/specs/` 与当前产品一致。
