# neon-3 验收测试

> 负责人：neon｜优先级：P0｜关联：测试实践 20 分、产品验收

## 一句话任务

以用户视角逐条核对 OpenSpec Scenario 与系统实际功能，记录「通过 / 失败 / 未执行」，并由你本人撰写验收方案和验收报告、签字。

## 为什么做

课程 §5.4 要求"对每个核心功能给出正向验收和至少一个异常/无效输入验证"，§6.2 验收测试占 20 分。验收是"用户能不能用"的最终确认，不能拿单元/集成测试代替。

## 你要做什么

1. **列 Scenario**：从 `openspec/specs/` 当前规格里逐条摘出 Requirement / Scenario。
2. **对照功能**：每条到页面上实际点一遍——风险排序是否可用、解释或无归因状态是否清楚、能否区分"尚未预测"与系统错误。
3. **现场记录**：每条记通过 / 失败 / 未执行，附实际结果与截图。
4. **人工写文档**：验收方案（角色、场景、步骤、通过标准、参与者）与验收报告（逐场景结果、未满足项、处置决定、签字日期），**必须你本人写并签字**（AI-R5）。
5. **缺陷追踪**：发现的问题用 GitHub Issue / 飞书缺陷记录登记并跟踪。

## 交付物

- 验收方案（人工撰写 + 签字）。
- 验收报告（逐场景结果 + 签字）。
- 演示记录与截图。

## 什么算合格（验收清单）

- [ ] 覆盖当前全部核心 Scenario，逐条有实际结果。
- [ ] 每条记录通过 / 失败 / 未执行，不模糊。
- [ ] 每个核心功能有正向验收 + 至少一个异常/无效输入验证。
- [ ] 方案/报告由你本人撰写并签字。
- [ ] 失败项有缺陷记录与处置结论。

## 不要做什么

- 不把"计划"写成"已通过"。
- 不遗漏"尚未预测"与"系统错误"的区分验证。
