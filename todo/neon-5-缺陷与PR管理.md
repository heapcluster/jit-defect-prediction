# neon — 缺陷与 PR 管理

> 任务编号：N-5｜负责人：neon｜板块：过程管理｜优先级：P1
> 依赖：N-2/N-3/N-4 的测试发现｜关联依据：项目协作规则

## 目标

建立缺陷记录与 PR 审阅流程，形成可核验的过程证据。

## 依据（docs/common 原文）

> 项目需使用缺陷管理工具（项目管理工具通常支持缺陷管理）。
> 使用Pull Request协作，合并前应至少有一位非作者成员审阅；审阅意见及修改记录保留在Git平台中。——《docs/common/project-requirements.md》

## 范围

**做：**
- 维护缺陷记录：现象、复现条件、优先级、处理状态、关联提交/change。
- 落实 PR 审阅并留痕。
- 核对仓库审阅配置与流程一致。

**不做：**
- 不修改代码修复缺陷（归蛋神的蛋）。
- 不制定缺陷记录模板（归 sober，见 S-4）。

## 当前未完成

## 输入

- 四类测试的发现。
- PR 清单与审阅人。

## 输出（交付物）

- 缺陷记录。
- PR 审阅记录。

## 依赖与前置

- 前置：测试已产生缺陷。
- 协作：修复找 **蛋神的蛋**；模板找 **sober**。

## 验收标准

- [ ] 每条缺陷可追溯（现象/复现/优先级/状态/关联提交）。
- [ ] 每个 PR 有非作者审阅痕迹。

## 约束（用 agent 执行）

- 缺陷记录写真实复现，不编造。
