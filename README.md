# JIT 缺陷预测系统

在 **提交（commit）粒度** 预测一次代码提交是否引入缺陷，输出风险概率并排序，供代码评审员优先审阅高风险提交。

| 项 | 内容 |
|---|---|
| 课题 | 即时软件缺陷预测（JIT — Just-in-Time Defect Prediction） |
| 课程 | 2026-2027-1 软件开发与测试综合实训 |
| 小组 | 想到什么取什么 |
| 数据源 | Apache ActiveMQ（单仓库，固定在某一版本） |
| 系统定位 | **建议性预警**，不做 CI 强制拦截 |

**核心链路**

```
ActiveMQ 仓库 → 抽提交信息 → SZZ 打标 → Kamei 14 项特征
   → 按时间切分训练 → 模型文件 → 预测接口 → 前端三个页面
```

## 一、分工

| 线 | 目录 | 干什么 | 交出什么 | 负责人 |
|---|---|---|---|---|
| 数据与模型 | `data_model/` | 拉数据、SZZ 打标、抽 Kamei 14 项特征、训 2–3 个模型、评估 | 带标记样本集、特征表、模型文件、评估报告 | 组员一 |

## 三、开发环境

统一用 conda 环境 `workbuddy`（Python 3.12）。**不要各人自建环境**，版本对不齐会造出「本地能跑、别人跑不了」的假故障。

```bash
conda create -n workbuddy python=3.12 -y    # 只需一次
conda activate workbuddy
pip install ruff pytest httpx fastapi
```

各线依赖按需装进同一个环境。数据集、模型文件、密钥**一律不入库**。

---

## 四、三条硬规矩

1. **时间序切分**：训练集与检验集按提交时间先后切（前 70% 训练、后 30% 检验），**不许随机抽**。
   原因：`EXP`、`NUC` 等特征与时间相关，随机切分等于让模型提前看到未来，测出的准确率是假的。
2. **合并前必须由非作者审阅**：`main` 分支受保护，禁止直接推送。
3. **改代码同步改规格**：规格与代码不一致，视为缺陷。

## 六、范围边界（第一版）

**做**：单仓库 ActiveMQ、SZZ 打标（含自研简化版对照）、Kamei 14 项特征、2–3 个经典模型、两类评价指标（Effort-unaware + Effort-aware）、一条完整链路、接口的输入校验与鉴权。

**不做**：跨项目对比、8 种模型全做、深度学习、容器化部署、插件化嵌入代码平台。

**两项非功能要求**：性能（预测接口 95% 请求 < 500ms）、安全（接口鉴权 + 非法输入不泄露内部信息）。
