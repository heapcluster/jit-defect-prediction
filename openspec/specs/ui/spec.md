# ui Specification

## Purpose

规定当前七页 Web 界面的共同边界。每页的字段和交互细节分别以 `docs/web_page/` 为准，接口以 `docs/api/` 为准。

## Requirements

### Requirement: 七页导航与真实数据

前端 SHALL 提供数据存储、数据收集、数据清洗、模型训练、模型预测、预测评估和设置七个页面；风险分、评估指标与图 SHALL 读取后端接口，MUST NOT 在前端伪造数据或另算模型分数。页面定义见 `docs/web_page/`。

#### Scenario: 七页可访问

- **WHEN** 用户打开七个现行页面并且后端有对应数据
- **THEN** 每页展示对应接口返回的内容，预测页可进入所选提交的详情

#### Scenario: 后端无数据

- **WHEN** 查询成功但 `items` 或 `figures` 为空
- **THEN** 页面展示明确空态，MUST NOT 把空数据显示为请求失败或风险 0

### Requirement: 模型选择与错误态

模型选择 SHALL 以 `GET /api/models` 的已登记清单为准；详情的显式模型选择 SHALL 传入 `model_name`，错误状态 SHALL 保留后端业务码，按相应页面显示可理解的提示。前端 MUST NOT 写死当前交付模型数量。

#### Scenario: 选择非默认模型

- **WHEN** 用户从模型清单选择一个非默认模型并打开提交详情
- **THEN** 详情请求带所选 `model_name`，页面显示该模型的预测而不混用默认模型

#### Scenario: 详情提交不存在

- **WHEN** 后端对详情请求返回 40400
- **THEN** 页面展示不存在状态与返回列表入口，MUST NOT 把它当成一般网络错误

### Requirement: 统一组件与视觉规范

七个页面及其子页面 SHALL 共用 `frontend/src/styles/ui.css` 的设计令牌与共享组件；页面 MUST NOT 手写多选卡片、步骤块、结果面板或表单栅格的私有样式。

- 选择卡片：单选与多选统一使用 `ChoiceGroup`，结构固定为「勾选 + 标题 + 徽标 + 摘要 + 参数区」，选中态使用主色描边与浅主色底。
- 步骤引导：工具页顶部使用 `StepRail`，页面内使用 `StepSection`；已完成步骤折叠为单行摘要，可再次展开。
- 结果区域：任务进度、结果与结果文件 SHALL 合并为同一张卡片，区块之间用分隔线区分。
- 表单栅格：设置页与数据存储页共用 `.field-grid`，标签统一位于控件上方。

#### Scenario: 跨页复用同一多选交互

- **WHEN** 用户在数据清洗处理项、模型训练算法、预测评估指标或数据收集来源之间切换
- **THEN** 卡片的内边距、圆角、字号、摘要缩进与选中态保持一致，仅内容不同

#### Scenario: 查看已完成步骤

- **WHEN** 前置步骤已就绪
- **THEN** 该步骤默认折叠为一行摘要，用户可通过“展开”查看完整配置
