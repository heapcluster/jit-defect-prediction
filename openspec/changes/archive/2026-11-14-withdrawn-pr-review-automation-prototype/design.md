# 设计决策（pr-review-automation-prototype）

## D1 默认只读

- 决策：工作流使用 `pull_request_target`，只检出目标分支，令 `GITHUB_TOKEN` 仅有读取内容、PR 与检查状态的权限。
- 理由：PR 代码和正文均是不可信输入；原型不执行 PR 头代码，也不接触模型密钥。代价是首版不能发布审阅。

## D2 模型结论与发布分离

- 决策：使用 `head_sha/action/findings` JSON 作为待接入模型适配器的边界。发布必须同时有 CLI `--publish` 和配置开关，工作流均关闭。
- 理由：模型服务尚未选定，不能以确定性规则代替代码审阅，也不能把“无输出”误当通过。

## D3 批准采取失败关闭门禁

- 决策：差异缺失、超限、截断、提交变化、CI 未成功、结论与证据不符时均跳过；同一提交只发布一次。
- 理由：自动批准的误判成本高于跳过；请求修改也必须有指向变更文件与实际补丁的证据。

## D4 正式发布另行设计

- 决策：未来若启用模型服务和自动审阅，另建可信发布通道，并先确认机器人审阅身份能满足非作者审批规则。
- 理由：直接给现有 PR 触发工作流加写权限、执行外部分支代码会扩大攻击面。
