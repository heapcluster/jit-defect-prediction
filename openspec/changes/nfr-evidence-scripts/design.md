# 设计：性能与安全证据脚本

## D1 占位模型先跑、真模型重跑替换

真 `.pkl` 交付时间挂在模型线身上，而看板任务 10 已「进行中」、Sprint 0 于 9/25 结束。取两阶段：

- 阶段一（现在）：本地训一个小 DecisionTree（14 维随机特征、二分类）pickle 进临时 MODEL_DIR，跑通压测链路并留证，证据标注「占位模型（待真 .pkl 重跑）」；
- 阶段二（.pkl 交付后）：重跑追加真模型证据，旧证据保留 —— 答辩能展示「证据随交付演进」，比删旧换新更可信。

占位证据的 p95 数值**不代表**真模型性能，只证明脚本与链路可用；达标判定以阶段二为准。

## D2 脚本独立于应用代码

两脚本只做 HTTP 客户端（httpx + 环境变量 BASE_URL/API_TOKEN），不 import `app.*`：

- 提案与脚本的评审/合入不与 #30 串联（#30 未合时脚本仍可评审、可对着本地 feat 服务跑）；
- 代价：接口路径/错误码在脚本里硬编码一份 —— 与契约三 §4 的口径一致即可，契约变更时随 change 同步脚本。

## D3 证据位置与形态

`backend/scripts/evidence/<日期>-<主题>.md` 进仓库（handbook §9 允许 `backend/`）：含日期、模型来源、命令、关键输出表格。不强制截图（课程接受「脚本 + 输出结果」）；若答辩需要视觉元素再补图。

## D4 分位数口径

p95 = 100 次耗时升序后第 95 位（1-based）的值，不用平均值、不用 p95 插值库函数之外的口径；脚本输出同时给 p50/p99/max 供对照。与飞书设计文档名词解释「95 分位」定义一致。
