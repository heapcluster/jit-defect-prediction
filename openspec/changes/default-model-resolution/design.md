## Context

PR #186 首次 CI 的失败包含八条预测与错误码回归。原因是候选来自数据库历史模型名，而推理要求模型已加载。当前工作区有修复草稿，但尚未完成最终全量回归；本设计待评审，不视为已合入或已验收。

## Goals / Non-Goals

**Goals:**
- 读写缺省模型共用解析入口，候选实际可推理。
- 空库、已卸载历史模型及空注册表的行为可用测试自证。
- 同步不遗漏有效默认模型的缺行提交。

**Non-Goals:**
- 不变更八模型名单、14 维特征、阈值、表结构或前端交互。
- 不补整个历史库所有模型缺口，不处理永久失败项重试策略。
- 不把 #184/#185 代码混进本分支，不操作演示库。

## Decisions

### D1 已加载集合是默认候选边界

`champion.resolve(session)` 只遍历运行时注册表；不使用 model 表或 prediction 的 DISTINCT 名字作为可执行候选。数据库仅回答候选是否已有行。模型表可能包含卸载前的历史元数据，直接取名字会把服务端缺模型误判为客户端 40001。

### D2 保留有数据降级，但空库不再分叉

已配置/按现行 D6 解析的注册表冠军有行时直接使用；无行时选有行的已加载模型中版本序最大者；没有这类模型时返回注册表冠军。predict 不再另行实现空库回退。注册表为空返回无可用模型，写端固定 50000。

替代方案是“配置冠军后永不按数据降级”；它更容易解释，也能避免冠军切换后迟迟得不到数据，但会改变本 PR 已提出的产品行为，暂不在这次 CI 修复中静默改用。

### D3 同步判据按在线模型集合，而不是按默认模型

评审指出：只检查默认模型时，“默认模型有行、其余在线模型缺行”的提交仍会被跳过，`predict_commit_all_models` 永不被调用，全模型落库落空。故判据改为“集合内每个已加载模型都有行才算完成”。代价：历史库（8.4 万行只有 xgb_v1）在 catchup 时会把大批提交判为待预测，靠 `SYNC_CATCHUP_LIMIT` 分批消化，每批一次现算 + 全部在线模型打分；永久失败项（如 merge 提交）会每轮重试并计入 `skipped`。这是评审明确要求的口径，接受该代价。注册表为空时退回有效默认模型单模型判据，避免“集合为空 → 全部判缺”的退化。

### D4 测试夹具真实表达模型状态

普通查询样本使用注册表实际加载的 fixture 模型，分数、日期和条数不变；未加载的高版本历史模型另设回归，显式查询它应仍有效。推理幂等测试需明确覆盖“第一次插入”和“再次更新”，不能因预置行而丢掉首次插入路径。

### D5 用 ADDED 而不是 MODIFIED 承载预测侧口径

change `on-demand-commit-prediction`（进行中，2 项未勾，负责人同为 backend）已 MODIFIED `predict-api / 在线预测入口`，本 change 若再 MODIFIED 同一 Requirement，`infra/check_spec_references.py deltas` 会判冲突、CI 直接红。故预测侧口径写成 ADDED 的独立 Requirement，并在 delta 里点名“归档 on-demand 时须把旧句对齐”。备选是归档那个 change——它未验收完，不能为了消解冲突而提前归档。

### D6 活规格不由本 PR 直接改

首版曾直接编辑 `openspec/specs/query-api/spec.md`，属绕过 change 流程；已回退到 main 版本，改动全部由本 change 的 delta 承载，归档时再落活规格。契约三 `docs/backend/api-spec.md` 属“现行契约文档”而非 openspec 活规格，按 #179 的先例在本 PR 内同步。

## Risks / Trade-offs

- 冠军缺数据时发生降级 → 响应回显真实模型，测试固定降级顺序；此规则仍待评审确认。
- 查询默认不再自动选未加载的历史模型 → 显式指定历史模型仍可查询；作为可观察行为变更登记，不称纯重构。
- 首版直接修改了活规格 → 应用阶段按 delta 同步并核对与主线的差异，不能留下两份不同规则。
- `on-demand-commit-prediction` 同时 MODIFIED“在线预测入口” → 保留其现算场景；合入前与其维护方合并规格归属，不绕过冲突门禁、不私自归档对方 change。

## Migration Plan

不做数据库迁移。完成测试与规格协调后更新 #186，继续请求 sober-hub/jolly326 评审；不自合并。回退代码时保持预测历史不删除，新增行仍遵循原 `(commit_hash, model_name)` 唯一键。
