## ADDED Requirements

### Requirement: 公开缺陷数据集加载

系统 SHALL 支持加载并保存至少一个公开 JIT 缺陷数据集，作为现有单仓库（ActiveMQ）样本之外的补充数据源；加载后的数据 MUST 对齐现有 `commit` / `commit_label` / `commit_feature` 的字段口径，MUST NOT 另立一套字段名。

#### Scenario: 正常加载公开数据集

- **WHEN** 指定一个受支持的公开 JIT 数据集路径
- **THEN** 系统解析为与现有 schema 对齐的记录，统计条数与正负比例并落盘保存，可被特征/训练流程读取

#### Scenario: 数据集缺字段

- **WHEN** 公开数据集缺少本系统必需字段（如提交时间）
- **THEN** 加载器报出缺失字段清单并终止该批加载，不产生半成品数据

### Requirement: 公开数据集固有问题治理

针对公开 JIT 数据集的已知缺陷，系统 SHALL 在加载阶段给出可核验的处理或标注：① 标签粒度粗（仅有/无缺陷、无缺陷类型）——保留二分类标签并在元数据中标注「无缺陷类型」，MUST NOT 伪造类型；② 以 Java 项目为主——记录数据集的语种分布，非 Java 样本单列统计；③ 数据质量（不完整 / 不准确 / 不一致）——按高质量数据集评价方法输出缺失率、重复率、时间序一致性检查报告。

#### Scenario: 输出质量报告

- **WHEN** 完成一个公开数据集加载
- **THEN** 产出一份质量报告，含缺失率、重复率、语种分布、标签粒度说明，作为验收证据

#### Scenario: 标签粒度标注

- **WHEN** 数据集仅含二分类标签
- **THEN** 元数据标注「标签粒度 = 二分类（无缺陷类型）」，且不向模型注入虚构的类型标签

### Requirement: 与现有基线的关系（不改动基线）

本能力为**数据源扩展**，SHALL NOT 替换或修改现有 ActiveMQ 数据管线与交付模型；公开数据集仅用于对照实验与数据质量分析。

#### Scenario: 基线不受影响

- **WHEN** 加载公开数据集后重跑现有流程
- **THEN** 现有 `commit` / `commit_label` / `commit_feature` 与交付 `xgb_v1` 的输出不变
