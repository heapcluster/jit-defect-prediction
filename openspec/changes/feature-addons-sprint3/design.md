# 附加功能 — 设计要点

## 缺陷可视化定位
- 数据源：复用 07_predict_all.py 产出的 `prediction_result.csv` 与 SHAP 归因结果。
- 前端：提交详情页在「风险分 + SHAP 归因」区下方新增「定位」子页，按文件聚合 SHAP 绝对值，
  可下钻到具体代码行（行级高亮依赖 `data_model/` 提供的行级归因，若仅特征级则先展示特征→文件映射）。
- 边界：行级数据缺失时降级为特征级，并在页面标注「行级数据待补」。

## 高质量修复建议
- 检索：在 `data_model/` 新增脚本，按缺陷关键词 / 修复语义从已标记样本集检索历史修复提交。
- 输出：对当前高风险提交返回 Top-K 参考修复模式（提交摘要 + 改动文件模式），不自动改代码。
- 边界：仅作建议，定位为「建议性」，与系统整体「预警不拦截」一致。

## 公开数据集加载与质量治理（G1-3）
- 定位：**数据源扩展**，与 ActiveMQ 基线并列，不替换现有管线。
- 加载：新增加载器把公开 JIT 数据集解析为与 `commit` / `commit_label` / `commit_feature` 对齐的记录；缺必需字段则报错终止，不产半成品。
- 质量治理：输出缺失率、重复率、语种分布、时间序一致性报告；标签粒度粗（无缺陷类型）在元数据中如实标注，不伪造类型。
- 边界：仅用于对照实验与数据质量分析，公开数据集不进入交付链，不改交付模型。
