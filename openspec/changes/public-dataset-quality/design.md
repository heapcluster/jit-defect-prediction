# 公开数据集加载与质量治理 — 设计要点

> 只记技术决策与取舍，不重复 proposal 的内容。关联：`docs/model/methodology-references.md`、`docs/design/addons.md` §3、`docs/design/sprint0-scope.md`。

## D1：为什么公开数据集的定位是「验证 + 治理 + 对照」，不是「换交付数据」

课程附加功能 (3) 要求「保证系统能加载保存现有公开的软件缺陷数据集」。字面上容易误解为「把交付数据换成公开数据集」——**不是**。

依据 Kamei et al. 2013：JIT 预测**跨项目不可迁移**。所以公开数据集的价值不在「让我们的模型测其他仓库」，而在三件事：

| 价值 | 说明 |
|---|---|
| **验证管线通用性** | 证明「克隆→抽取→SZZ→特征→切分→训练」这套管线能处理不同来源、不同语言、不同格式的数据，而不只是对 ActiveMQ 这一份数据硬编码 |
| **质量治理示范** | 逐条回应课程 (3) 的三缺陷，产出可核验的质量报告 |
| **对照实验素材** | 与 ActiveMQ 基线并列，用于说明「不同来源数据的质量差异有多大」 |

**硬边界**：不进交付链、不入库、不替换 ActiveMQ 基线、不把公开数据集的模型塞进后端。

## D2：候选数据集与选择标准

选择标准按优先级：
1. **字段完备性** —— 必须有 commit 标识、标签、时间戳；缺任一则无法入 change
2. **语种多样性** —— 优先含非 Java 项目（回应 (3)-②）
3. **许可证可引用** —— 须记录来源、许可证、获取日期
4. **体积可控** —— GB 级先评估再决定全量/抽样

> **阻塞前置**：当前网络代理不通，**无法验证候选数据集的可下载性**。tasks §0 的第 1 号任务就是验证；不通过则按 D7 降级。**不许在未验证的情况下把具体数据集名写进报告。**

## D3：加载器设计与字段映射

- 新增 `data_model/20_load_public_dataset.py`，产出与契约一 `commit` / `commit_label` 对齐的记录。
- **缺必需字段（commit 标识 / 标签 / 时间戳）→ 报错终止，不产半成品**。用默认值填充会让下游把「缺失」当成「无缺陷」，是静默污染。
- 字段名不一致时输出**字段映射表**；口径冲突显式登记，**不静默对齐**（例如公开数据集的 `bug` 列是「修复提交」还是「引入提交」，必须分清）。
- 元数据落盘：来源、许可证、获取日期、原始体积、抽样方法。

## D4：质量治理四项指标（逐条回应课程 (3)）

| 课程问题 | 治理动作 | 输出 |
|---|---|---|
| ① 标签粒度太粗 | 标注「有无缺陷类型」；有则保留类型字段并输出分布，无则元数据明确写「无缺陷类型」 | 标签粒度 + 类型分布 |
| ② 主要针对 Java | 统计「数据集 × 语言 × 提交数 × 占比」 | 语种分布表 |
| ③ 数据质量问题 | 缺失率 / 重复率 / 字段一致性 / 时间序一致性 | 四项指标 + 异常样本清单 |

- 重复记录的「**标签冲突**」子项**单列，不静默去重保留其一**——同一 commit 两个相反标签，保留任一个都是造假。
- 时间序不一致（无法解析 / 早于仓库首个提交）**单列，不静默剔除**。

## D5：与 ActiveMQ 并列而非替换

- ActiveMQ 基线与现有管线**一行不动**：`data_model/models/[models]` 段、契约三接口、契约二 14 项列名与顺序均无变化。
- 任何基于公开数据集的结论**必须标注**「基于公开数据集 X，与 ActiveMQ 基线并列对照」，不得表述为替换了交付数据。

## D6：抽样纪律

数据集体积过大时按 `committed_at` **分层等距抽样**，禁随机。理由同 ActiveMQ 切分：随机抽样会让样本的时间分布失真，且不可复现。抽样方法、样本量、层级边界写入报告。

## D7：降级路径（下载不到怎么办）

若 §0 验证后公开数据集**全部不可达**，本 change 降级为：

1. **加载器 + 质量评价框架照常交付**（代码与规格不缩水）；
2. 用 **ActiveMQ 自有数据**跑一遍质量评价，自证框架可用（含「标签粒度=二值、无缺陷类型」「语种=Java 单一」两项，正好复现课程 (3) 指出的问题）；
3. 报告中**如实写明「未能获取公开数据集及原因」**，附 §0 的探测结果作证据。

**宁可降级并如实说明，也不虚构数据。** 课程明确「不写指标口号」「只写实测结果与可验收方法」。

## D9：与文献数字对照（可选，但价值高）

若获取到的是 **JIT 深度学习标准 benchmark**（DeepJIT / CC2Vec 使用过的项目，如 OpenStack、Qt），则在它上面训一个模型，与**已发表结果**做量级对照。

**价值**：这是「本组管线在公开 benchmark 上能复现文献量级结果」的直接证据，比自说自话强一个量级。答辩「测试工作概述与结论」一环可用。

**三条纪律**：
1. **仅限标准 benchmark**。未获取到则不强求，**不许为凑对照选用非标准数据集**。
2. **口径差异必须标注**。文献的工作量代理、划分方式、特征集、模型若与本组不同，对照表 MUST 逐项标注，不得直接并列数字暗示同等条件。
3. **对照结论用于佐证管线可用性**，不用于宣称「达到 SOTA」。

## D8：变更文本表示与语义特征线共用

公开数据集的代码变更统一表示为「变更文本」（文件路径 + 变更类型 + 增删行 + 提交信息首行），与 `semantic-feature-mainline` D3 **同一套构造**。两条线各写一套必然漂移，共写一套才能对比。
