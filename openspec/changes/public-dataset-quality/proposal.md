# 公开缺陷数据集加载与质量治理（回应课程附加功能 (3)）

> Sprint 2 启动 ｜ 起草 2026-10-13 ｜ 起草人 蒋励（模型线负责人）
> 关联契约：`docs/design/data-fields.md`（契约一）、`docs/model/feature-columns.md`（契约二）
> 关联变更：本 change **顶替** `feature-addons-sprint3` 中的 G1-3。

## Why

课程《项目要求》可选附加功能第 **(3)** 条（2026/10/12 新增）原文：

> 要保证系统能加载保存现有公开的软件缺陷数据集，但现有即时软件缺陷数据集存在几个突出问题：比如
> **1）标签粒度太粗**，往往只包含有无缺陷，并没有缺陷类型信息；
> **2）主要针对 Java 项目，其他编程语言的开源项目较少**；
> **3）数据质量问题**（数据不完整、不准确、不一致等，可参照高质量数据集评价与构建方法应对）。

任课教师 2026-10-13 指导：模型线路需要调整，**不能采用老旧的方案**。

> **先说清本 change 不做什么（避免误解）**：加载公开数据集**不是**「让我们的模型能测其他仓库」。
> 依据 Kamei et al. 2013，JIT 预测**跨项目不可迁移**——一个模型换仓库即失效。所以公开数据集的定位是三件事：
> ① **验证管线通用性**（能处理不同来源、不同语言的数据）；② **质量治理示范**（逐条回应课程 (3) 三缺陷）；
> ③ **对照实验素材**（与 ActiveMQ 基线并列）。
> **不进入交付链、不替换 ActiveMQ 基线、不把公开数据集的模型塞进后端。**

**本组当前状态恰好完整复刻了这三条缺陷**：
| 课程指出的问题 | 本组现状 |
|---|---|
| ① 标签粒度太粗（只有有无缺陷，无缺陷类型） | ✅ 复刻：`commit_label.is_bug_inducing` 只有 0/1，无缺陷类型 |
| ② 主要针对 Java，其他语言少 | ✅ 复刻：单一仓库 ActiveMQ（Java） |
| ③ 数据质量问题 | ⚠️ 未评估：从未用「高质量数据集评价方法」系统评估过 |

也就是说，课程点名的三个问题，**我们一个不落全中了**。这不是巧合——单仓库 + SZZ 代理打标就是 2013 年前后 JIT 数据集的典型构造方式。

## What Changes

1. **公开数据集加载器**：能加载并保存现有公开 JIT 缺陷数据集，解析为与 `commit` / `commit_label` / `commit_feature` 对齐的记录；**缺必需字段则报错终止，不产半成品**。
2. **三维度质量治理**（逐条回应课程 (3)）：
   - **① 标签粒度**：如实标注数据集「有无缺陷类型」；有类型则保留类型字段，无类型则在元数据明确写「无缺陷类型」，**不伪造**。
   - **② 语种分布**：统计并报告各数据集的编程语言构成，用于支撑「突破 Java 单一语种」的论证。
   - **③ 数据质量**：按高质量数据集评价口径输出缺失率、重复率、字段一致性、时间序一致性报告。
3. **与 ActiveMQ 基线并列，不替换**：公开数据集用于对照实验与质量分析，**不进入交付链、不改交付模型**。
4. **多语言证据**：若加载的数据集含非 Java 项目（如 OpenStack/Python、Qt/C++），在报告中明确给出语种分布，作为对 (3)-② 的直接回应。

## Capabilities

- `public-dataset`：公开 JIT 数据集加载、三维度质量治理、与 ActiveMQ 基线并列对照。规格见 `specs/public-dataset/spec.md`。

## 影响与边界

| 项 | 内容 |
|---|---|
| 影响目录 | `data_model/`（新增 20 数据集加载器、21 质量报告脚本）、`docs/model/`（口径与报告）、`data_model/reports/`（质量报告） |
| 触及 `docs/design/sprint0-scope.md` 边界？ | **是**。原文把「公开数据集」列为可选；本 change 将其**提升为承诺范围**，须同步改该文件 |
| **不做什么** | ① **不替换** ActiveMQ 基线与现有管线；② **不伪造**缺陷类型标签；③ **不进入交付链**（不入库、不改交付模型、不改接口）；④ 不在本 change 内做跨语言模型训练（那是 `semantic-feature-mainline` 的事）；⑤ **不修改**契约二既有 14 项列名与顺序 |
| 数据边界 | 公开数据集落盘为独立文件（`data_model/data/public/<name>/`），带来源与许可证元数据；**不入库** |
| 新增依赖 | 公开数据集本身（体积可能较大，须先评估）；无新增 Python 包 |
| **阻塞前置** | **公开数据集的可下载性尚未验证**（当前网络代理不通，无法访问 GitHub）。本 change 的第 1 号任务就是验证可下载性；验证不通过则整体降级为「加载器 + 质量报告框架 + 用现有 ActiveMQ 数据自验」，并在报告中如实说明 |

## 风险与应对

| 风险 | 应对 |
|---|---|
| **公开数据集下载不到**（代理/网络/链接失效） | 第 1 号任务专门验证；不通过则降级为「加载器框架 + 用 ActiveMQ 数据做质量自评」，报告如实写明「未能获取公开数据集及原因」，**不虚构数据** |
| 数据集体积过大（GB 级） | 先评估体积再决定全量/抽样；抽样须按时间序分层，禁随机 |
| 公开数据集的标签口径与我们的 `is_bug_inducing` 不一致 | 加载器做字段映射并输出映射表；口径冲突显式登记，不静默对齐 |
| 不同数据集的代码变更表示格式不一（diff / 文件快照） | 统一为「变更文本」表示（与 `semantic-feature-mainline` D3 同一套构造），保证两条线可对比 |
| 许可证/署名问题 | 元数据记录来源、许可证、获取日期；报告注明 |
