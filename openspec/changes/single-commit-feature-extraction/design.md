# 设计决策

1. 单条与批量共用 `scan_history`、`HistoryIndex`、`compute_raw`、`apply_contract` 和修复提交判据，避免第二套 14 维算法悄悄漂移。输入限定为本地仓库 HEAD 可达的非合并提交，缺失或合并提交显式失败。
2. 单条入口输出提交元信息、按契约排序的 `features` 和 `vector`。命令行只写一行 JSON 到标准输出，错误写标准错误；不触碰批量 CSV/报告。
3. 当前 `scan_history` 是全量 Git 历史扫描，适合证明计算能力但不适合直接嵌入 500ms 请求。后端接入前应设计预热/缓存或增量历史索引，并以真实 Camel 仓库压测后决定运行方式；不得把本入口的存在等同于在线时延达标。
