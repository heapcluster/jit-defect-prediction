# 语义特征提升为模型线主线（Kamei 14 降为基线对照）

> Sprint 2 启动 ｜ 起草 2026-10-13 ｜ 起草人 蒋励（模型线负责人）
> 关联契约：`docs/model/feature-columns.md`（契约二）、`docs/backend/api-spec.md`（契约三）、`docs/design/data-fields.md`（契约一）
> 关联变更：本 change **顶替** `feature-addons-sprint3` 中的 G1-4（预训练语义特征建模），该条从「可选附加 · Sprint 3 · 立项不实现」移出。

## Why

课程《项目要求》可选附加功能第 **(4)** 条（2026/10/12 新增）原文：

> 早期的即时软件缺陷预测方法是基于专家特征（即经典的 Kamei 14 维代码变更度量元）的，但**现在主流方法是利用预训练模型直接从源代码提取深层语义特征**，然后构建预测模型。

同文档 PS 引 **Kamei, Shihab, Adams, Hassan et al., *A Large-Scale Empirical Study of Just-in-Time Quality Assurance*, IEEE TSE 39(6): 757–773, 2013** —— 该文是 JIT 领域的奠基工作，但其技术路线**全部建立在专家特征（变更度量）之上**，正是附加功能 (4) 所称的「早期方法」。

任课教师 2026-10-13 指导：模型线路需要调整，**不能采用老旧的方案**。

**当前模型线的实际状态**：8 个预测模型全部构建在 Kamei 14 专家特征之上，语义特征（G1-4）排在 Sprint 3 且仅立项不实现。也就是说，**当前交付的模型线 100% 属于「早期方法」**，与课程定性直接冲突，也无法在答辩「关键架构/技术决策设计」一环自证。

### 论文方法论 vs 本组现状（读完论文后的差距定位）

| Kamei et al. 2013 的方法/结论 | 本组现状 | 差距 |
|---|---|---|
| 用变更度量（即 Kamei 14）在 change 粒度建 JIT 模型 | ✅ 已实现，8 模型 / 两类指标 | 无 |
| **Effort-aware 评估**：JIT 的价值在于「只审一小部分变更即发现大部分缺陷」 | ✅ 已实现（`P_norm` + 同预算重排） | 无 |
| **项目内可用、跨项目不可迁移** | ⚠️ 只做单仓库 Apache Camel，未把「跨项目不迁移」作为显式结论记录 | 小差距 → 本 change 补登记 |
| **特征重要性/消融分析**（论文有系统的特征效力讨论） | ❌ 未系统做过 | 差距 → 本 change 补做 |
| **从源代码提取深层语义特征** | ❌ 无（G1-4 未实现） | **最大差距 → 本 change 的主目标** |

## What Changes

1. **范围调整**：G1-4 由「可选附加」提升为**模型线主线交付**，Sprint 2（第 7–9 周，10/23–11/13）启动；Kamei 14 保留但**降为基线对照组**，不再是唯一主线。
2. **语义特征路线（2026-10-13 二次修正）**：
   - **主路线（全量或近全量）**：**CodeBERT / GraphCodeBERT**（代码专用预训练模型，文献主流方向）。先跑 **100 条基准测试**定时限——按全量提交 × 约 3 个改动文件（量级为**数万条序列**）、`codebert-base` CPU 单条约 50–150ms 估，量级是**小时级而非天级**，此前「几十小时」的判断过于悲观。算力不足时抽样并如实标注配置。
   - **弱基线（可选）**：`all-MiniLM-L6-v2`（通用句向量，**非代码专用**）**降为「标注清晰的弱基线」或直接砍掉**。域不匹配——用自然语言编码器编码代码 diff；文献一律采用代码专用预训练正是为了这个。
   - **修正记录**：初版曾把 MiniLM 设为「打底全量」、CodeBERT 设为「抽样增强」，与文献主流方向相反，本次订正。
3. **三类设置对比实验**（沿用 `semantic-feature` spec 已有口径）：仅 Kamei 14 专家特征 / 仅语义特征 / 二者融合；同一切分、同一测试集、同一套指标（Effort-unaware + effort-aware）。
4. **补两项论文方法论工作**：① 专家特征消融与重要性分析；② 跨项目不可迁移的显式登记（作为单仓库设计的论证依据）。
5. **评测协议对齐文献标准**（2026-10-13 新增，详见 `design.md` D9）：补 CE@20% / Recall@20% / Popt / ALPA；`P_norm` 保留但标注「自造变体」；补 Wilcoxon signed-rank 显著性检验与显式基线。
6. **依赖隔离**：语义特征装在独立 conda 环境 `jit-defect-prediction`，**不污染**现有 `jit-defect`（87 + 59 条测试依赖它）。
7. **规格与看板同步**：`feature-addons-sprint3` 的 G1-4 条目移出；看板新增 Sprint 2 行。

## 风险与应对

| 风险 | 应对 |
|---|---|
| `torch` 安装体量大、可能影响主线测试环境 | 独立 conda 环境 `jit-defect-prediction`；主线 87 + 59 条测试继续用 `jit-defect` |
| CodeBERT CPU 全量耗时超预期 | 先跑 100 条基准测试定时限；超预期则抽样并如实标注，**不谎报全量** |
| CodeBERT 表示能力不及预期 | 如实报告；三类对比表本身就是交付物，「语义不占优」不是失败 |
| Sprint 2 内跑不完全量 | 语义特征优先保证；消融与显著性可延至 Sprint 3，但**三类对比表必须在 Sprint 2 末出** |
| 语义特征指标不如专家特征（完全可能） | 如实报告。**这不是失败**——课程要的是「做过主流方法并有证据」，三类对比表本身就是交付物 |
