# 模型训练与交付 — 设计决策

## Context

样本集与特征表已全量产出（`szz` 正样本比例 38.98%），训练从零开始。约束：契约二 v1.0 已冻结（列序、口径不可再改）；数据线边界是「不建库表」；交付方式 A+C 已裁定（见 proposal 裁定一、二）。本文件只记技术取舍，动机与范围见 proposal.md。

## Goals / Non-Goals

**Goals:**

- 切分、训练、评估、导出四步全部可复现（固定随机种子、版本固定、命令可重放）
- 交付物让后端线**零猜测**接入：文件路径、特征顺序、依赖版本一次给全

**Non-Goals:**

- 超参自动搜索、模型融合、特征筛选实验（proposal 已列不做）
- 数据库写入（灌库在后端线）
- 契约正文改动（SHAP 只回填契约三「待确认」一节）

## Decisions

1. **切分实现：全局排序 + 位置切分，断言兜底** —— 按 `committed_at` 升序排序后取前 70% 位置切，切完立刻断言「检验集最早 > 训练集最晚」。备选「按日期字符串找分界点」被否：边界日期上有同秒多提交时归属二义。断言是兜底不是装饰 —— AGENTS.md 红线第 1 条要求这个性质成立，而不是「希望它成立」。

2. **主标签 szz，szz_lite 只出对照表** —— proposal 裁定二。取舍点：szz_lite 更快，但 27.74% vs 38.98% 的差异说明它粒度粗到会改变模型学到的边界；与文献可比性优先。对照表（分歧条数 + 抽样）已由 `reports/szz_labeling_stats.md` 承载，训练侧不重复做。

3. **模型选型：逻辑回归（线性基线）/ 随机森林 / XGBoost** —— Kamei 原文 8 种里取 3 个代表性谱系：线性、Bagging 树、Boosting 树，足撑「2–3 个」且谱系不重叠。LR 还顺带解决「14 项特征已取对数、量纲已压」的适配问题。最终个数（2 还是 3）在实现时按时间预算定，规格只卡下限 2。

4. **新依赖：scikit-learn / xgboost / shap，版本钉死进 requirements.txt** —— 与既有 pandas/numpy/GitPython 并存。SHAP 与 xgboost / sklearn 的版本兼容性是主要耦合点，装一次跑通后就锁版本，不追新。

5. **Effort-aware 指标取 P_opt（Kamei 原文口径）** —— 与「结果要与文献对比」的总原则同源；IFA/EPA 作为备选记录在报告脚注，不做双口径双报告。

6. **C 方案交付为 `prediction_result.csv` 而非数据线写库** —— proposal 裁定一。理由：保住数据线「不碰库表」的既有边界；代价是后端多一个灌数步骤，且 `predicted_at` 由数据线生成时必须统一 UTC（契约一表三口径），交接时双方各校验一次字段。

7. **全量预测用训练好的模型对全部 11,050 条样本推理，含检验集** —— 趋势看板要展示全历史风险分布，所以不排除检验集；页面上不区分「训练时见过与否」，这是趋势展示不是指标报告，两回事。

8. **随机种子显式固定并写进复现命令** —— RF 与 XGBoost 都有随机成分；种子作为命令行参数有默认值，进 `docs/data-pipeline.md` 的复现命令序列。

## Risks / Trade-offs

- [SZZ 标签本身带噪声（标准行级 SZZ 不过滤）] → 评估数字解释时注明「与打标方法同源」，不与文献数字硬比绝对值；报告里放标签质量已知局限（D5 排除项）
- [SHAP 实时计算可能击穿 500ms 非功能要求] → 先实测留证据；不达标走契约三变更流程与后端线商量（预计算 / 降维解释），不静默换算法
- [时间序切分后检验集正样本比例可能偏离全集] → 报告同时报全集与检验集的正样本比例，防止「检验集 60%+」这种口径误导评审
- [xgboost / shap 在 Windows + Python 3.12 的装包问题] → requirements 钉版本后先在 `jit-defect` conda 环境验证装通，再进复现命令
- [.pkl 跨环境加载受 sklearn/xgboost 版本影响] → 交付清单同时给后端一份「推理环境依赖版本」，与本线 `requirements.txt` 钉同一组版本号

## Open Questions

- 模型最终做 2 个还是 3 个 —— 实现时按 Sprint 0 余量定，规格下限已卡 2
- `predicted_at` 取「预测运行时刻」还是「模型训练完成时刻」—— 倾向前者（契约字面口径），实现时在后端灌库前双方确认一次即可，不影响规格
