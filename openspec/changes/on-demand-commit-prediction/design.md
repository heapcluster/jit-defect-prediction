# 设计决策

1. `SOURCE_REPO` 仅来自服务端环境变量，避免把任意本地路径变成公开 API 输入。未配置时维持已灌库提交的旧行为；配置但路径失效时固定 50000，内部只记服务日志。
2. 后端以模块加载方式调用模型线 `extract_single_commit`，不复制 14 项算法；列序仍由 `config.FEATURE_COLUMNS` 与冻结契约决定。只有提交或特征行缺失才现算，已有行不重复扫描历史；`commit`/`commit_feature`/`prediction` 在同一次会话中落库。
3. 详情、列表和趋势均以所选 `model_name` 为准；未指定时共用已加载注册表中的默认模型。详情不跨模型自动回退；调用方切换模型时须在详情请求中显式传 `model_name`，避免将另一模型的风险分误认为当前模型的分数。
4. 模型线当前单条入口仍扫描完整 Git 历史，首个新提交的时延与 500ms 目标未验证。后续在真实 Camel 副本上做预热/缓存设计和 100 次 p95 压测；失败则按契约登记并提变更，不静默降低解释能力。
