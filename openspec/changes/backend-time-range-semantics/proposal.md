# Proposal: backend-time-range-semantics

## 为什么

Issue #61（P1）：风险列表与趋势接口的时间范围筛选**每次丢结束日当天**——前端 `el-date-picker` 送纯日期串 `2026-07-26`，后端 `_parse_time` 解析为当天 `00:00:00`，查询 `committed_at <= end` 闭区间，三者相乘把结束日整天（除整点）排除；趋势周下钻每周丢 1/7、与看板 `commit_count` 对不上，10/23 端到端演示会露。根因是**契约三从未定义区间语义**（闭/开、纯日期串如何解释），单修代码不补契约，下次还踩。

## 改什么

- 契约三 `api-format.md` 升 **2.0**（口径补充，按 writing-norms §3.3「改口径 → 1.0 步进」）：§3 两处参数表与新增「区间语义」注写明——闭区间 `[start, end]`；纯日期串 start = 当天 00:00:00.000000、end = 当天 23:59:59.999999（**结束日含全天**）；带时间分量按原样；带时区先转 UTC。
- 后端 `_parse_time(value, param, role)`：`role="end"` 且纯日期串 → 当天收尾；`start` 保持 00:00:00（评审明确「不能一刀切」）。`commits` 与 `trends` 两接口同参数同修。
- 全仓引用点同步 1.4 → 2.0（backend 7 处 docstring、`openspec/specs/query-api` 3 处、`docs/contracts/README.md` 状态表与说明行）。

## 影响谁

- 后端线（本 change）：解析与查询、测试、契约与引用同步
- 前端线（另线跟进，PR #60）：周下钻送纯日期串在新语义下天然正确；**月粒度** `periodToRange` 目前送「次月 1 日」作 end，新语义下会多收结束日全天，需改送当月最后一日 —— 跨线待办登记在本 change tasks，不在本 PR 改前端
- 契约消费方：区间语义从「未定义」变为「闭区间 + 结束日含全天」，行为变化仅 end 纯日期串一类输入

## 不做什么

- 不改 `min_risk` / `model_name` / 分页语义
- 不动 #37/#38 的排序与阈值提案（另案，缺裁定未开工）
- 不改前端代码（前端线 #60 内跟进）
