# 设计决策

1. **清单仍是唯一加载入口。** 后端继续遵守 `delivery-model-allowlist` 的清单校验和列序门禁；本变更只扩大批准后的清单，不回退为扫描目录中所有 `.pkl`。所以旧 change 的“三模型目录有额外权重只加载三项”场景仍成立；清单扩至八项后才按八项加载。
2. **分期切换，不倒置验收。** 先评审 OpenSpec 与契约变更，再由模型线交付 8 权重、后端补依赖和加载证据、前端同步选项。未完成 8/8 加载、每模型预测与性能验证前，现有三模型演示保持原口径。部分权重损坏时服务继续启动是运行时降级，不是交付验收通过。
3. **解释能力与预测能力分离。** 树族和线性模型沿用现有解释器；`svm_v1`（RBF）、`mlp_deep_v1`、`tabnet_v1` 提议按现行 `predict-api` 不支持解释器场景返回 `explanation=[]`，前端用已有空解释文案。这样不把 KernelSHAP 的秒级耗时放入 500ms 请求路径。若共签否决此选择，本 change 在 apply 前改版。
4. **性能不靠改标准获得通过。** 契约三的 p95 < 500ms、n=100 对每个上线模型分别验证；`perf_loop.py` 当前没有 `--model-name`，因此每轮用仅声明单个待测模型的隔离 `MODEL_DIR` 测试，证据必须记模型名、权重摘要、环境、命令与 p95。正式八模型目录还需一次 8/8 启动与切换集成测试。
5. **不新增模型列表接口。** 当前前端静态 `MODELS` 与交付清单同步，后端仍以实际加载清单为准。若未来要动态发现模型，另开 change；本次不让前端凭目录或训练报告猜测可用项。
