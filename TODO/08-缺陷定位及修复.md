# 任务 8：缺陷定位及修复

- **类型**：核心功能（图片功能 8）
- **状态**：部分实现（启发式定位与建议已有，完整源码视图缺失）
- **前置依赖**：任务 5、7
- **后续依赖**：任务 9

## 目标

在提交详情中展示源码，标出可疑代码行，并结合预测与解释结果给出有依据的修复建议。

## 功能定义（开发交接）

**模块职责**：以提交对应的源码和 diff 为对象，结合任务 5 的预测结果和任务 7 的解释结果，输出可疑代码行排序、证据说明和修复建议；本模块负责定位与建议生成，不自动修改代码。

**独立运行方式**

- 提供独立命令或 API：输入仓库、提交哈希和可选的预测/解释结果，输出源码视图、可疑行列表和修复建议。
- 没有预测或解释结果时，可退化为基于代码上下文和 diff 的定位，但必须标明证据来源不足。
- 页面只负责展示源码、行标记和建议，不应成为定位计算的唯一入口。

**输入契约**：仓库路径、提交哈希、源码文件或 diff、任务 5 的预测结果、任务 7 的解释结果、行级评分配置、Top-N 参数。

**输出契约**：完整源码目录和文件内容；文件路径、行号、可疑度、排名、证据列表；结构化修复建议和参考依据。

**可配置项**：行级评分权重、Top-N 显示数量、是否展示完整源码、建议来源（模板/LLM/历史修复）、是否生成补丁预览。

**状态要求**：无源仓库、文件不存在、文件过大、二进制文件、LLM 失败等情况必须返回明确状态，不影响提交级预测结果。

**解耦要求**：源码读取、行级评分和建议生成拆成独立服务；任务 9 的插件和 CI 调用本模块输出，不复制启发式规则或提示词。

## 当前状态

- 已使用 SHAP 贡献较高的特征作为提交级定位线索，见 `backend/app/services/commits.py:57-71`。
- 已用 `git show --unified=0` 抽取真实 diff 新增行，见 `backend/app/diff.py:1-18`。
- 文件/行打分考虑文件类型、修改方式、hunk、控制流和安全相关关键词。
- 前端展示文件路径、行号、行内容、可疑度颜色和图例。
- 修复建议由模板或 OpenAI 兼容 LLM 生成，并附带同仓库历史修复提交。
- 当前只展示 diff 新增行，不是完整源码文件浏览。
- 行级分数是启发式结果，不是独立训练的行级缺陷概率。

## 待实现内容

1. **源码浏览**
   - 提供按提交哈希查看完整源码文件的能力，而不只是新增 diff 行。
   - 支持目录树、文件搜索、文件内容分页和指定行跳转。
   - 源码必须从任务 2 配置的目标仓库对应提交版本读取，保证版本一致。
   - 仓库不可用、文件过大、二进制文件等情况返回明确状态。

2. **行级定位服务**
   - 定义行级可疑度模型或统一评分服务，输入包括提交风险概率、任务 7 的解释结果、diff 类型、代码上下文和历史缺陷信息。
   - 输出文件路径、行号、可疑度、排名和证据列表。
   - 明确区分“提交级风险概率”和“行级可疑度”，避免界面误导。
   - 支持将 SHAP/LIME 的高贡献特征映射到对应文件或代码变更。

3. **前端定位交互**
   - 在完整源码视图中标出可疑行，支持按可疑度排序和颜色深浅区分。
   - 点击可疑行可查看评分依据、相关特征、解释结果和关联提交。
   - 支持在 diff 视图与完整源码视图之间切换。
   - 保留现有图例和空态处理。

4. **修复建议增强**
   - 修复建议必须引用当前提交的可疑文件和具体行，避免泛泛而谈。
   - 合并历史修复提交、LLM 结果和规则模板，输出“问题说明、建议修改、风险提示、参考依据”四部分。
   - 可生成补丁预览，但默认不自动应用、不自动提交。
   - 对 LLM 不可用情况保留模板回退，并标明建议来源。

5. **测试与文档**
   - 增加源码读取、版本一致性、行级评分、解释映射和修复建议结构测试。
   - 覆盖无源仓库、文件不存在、超大文件和 LLM 失败场景。
   - 补充定位与修复 API、页面交互和评分口径文档。

## 验收标准

- 用户可在提交详情中浏览该提交的完整源码目录和文件内容。
- 可疑代码行被标出，点击后能看到评分依据和解释证据。
- 修复建议明确引用当前文件和行号，并包含参考依据。
- 无源仓库或读取失败时有明确提示，不影响提交级预测结果。
- 默认不会自动修改代码或创建提交。
- 行级定位与提交级风险在界面上有清晰区分。
