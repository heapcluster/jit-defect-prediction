# TODO 00：重构说明与开发执行要求

- **文档性质**：重构背景说明 + 开发执行要求
- **适用对象**：开发人员蛋神
- **优先级**：最高，高于当前 `docs/` 下所有旧设计文档
- **权威输入**：需求图片、`TODO/01-数据库存储.md` 至 `TODO/09-多种形态拓展.md`
- **当前结论**：现有代码和大部分设计文档基于对老师需求的错误理解，必须按最新功能描述重构

## 1. 为什么必须重构

老师的要求是：图片中的前 8 个功能点都应当能够作为独立模块拿出来运行、配置和验收；第 9 项“多种形态”只是拓展方向，用于把已经稳定的核心能力接入独立客户端、IDE 插件和 CI/CD。

当前项目把前 8 个环节实现成了一条固定流水线：

> 固定仓库 → 固定采集 → 固定清洗/特征 → 固定训练 → 固定预测 → 固定评估/解释/定位 → Web 展示

这条链路虽然能演示，但不符合老师要求的“八个环节可独立运行”。问题不是某一两个接口缺字段，而是需求理解、设计文档、代码结构和历史产物都围绕旧口径形成，必须整体纠正。

### 1.1 需求理解错误

旧理解：

- 只要最终 Web 页面能展示风险、解释和定位，就算完成。
- 采集、清洗、训练、评估等只要能在命令行整体跑通即可。
- 配置写在 `.env`、代码常量或前端常量中即可。
- 默认模型、阈值、XAI 技术、定位规则都可以固定。
- `docs/` 中的旧产品边界就是最终契约。

正确理解：

- 功能 1-8 是八个独立模块，每个模块都要有自己的输入、输出、配置、状态和验收方式。
- 页面只是调用模块能力的展示入口，不能成为模块执行的唯一方式。
- 仓库、清洗步骤、算法、超参数、阈值、XAI 技术、定位参数都必须可配置。
- 配置、任务状态、数据集版本、模型版本和结果版本必须持久化。
- 功能 9 是前八项完成后的封装与拓展，不是当前固定流水线的别名。
- 当 `TODO/01` 至 `TODO/09` 与旧 `docs/` 冲突时，以 `TODO/` 为准。

### 1.2 当前代码的写死问题

## 2. 重构目标

重构完成后，系统应当具备以下形态：

1. **模块独立**：功能 1-8 均可单独启动、单独配置、单独测试、单独验收。
2. **配置外置**：所有影响结果的仓库、步骤、算法、超参数、阈值、XAI 技术、定位权重均来自配置或数据库，不写在业务代码中。
3. **状态持久**：任务状态、配置、数据集版本、模型版本、预测结果版本和解释结果版本均可查询。
4. **契约统一**：每个模块都有明确输入契约和输出契约；Web、CLI、CI 和插件调用同一能力实现。
5. **旧产物可丢弃**：旧模型权重、缓存和图集不再作为系统运行的隐含前提；需要时可由新训练流程重新生成。
6. **文档与代码一致**：`docs/` 是重构后的设计契约，不得继续保留旧固定流水线说法。

## 3. 给开发人员蛋神的执行要求

### 3.1 第一阶段：修正所有设计文档

必须先完成文档修正，再按新文档改代码。文档修正范围包括 `docs/` 下全部 Markdown，特别是以下分组：

- 产品边界：`docs/README.md`
- API：`docs/api/*.md`
- 数据库：`docs/database/*.md`
- 功能点：`docs/function_point/*.md`
- 模型卡片：`docs/model/e2e/*.md`、`docs/model/expert/*.md`、`docs/model/fused/*.md`、`docs/model/semantic/*.md`
- 页面：`docs/web_page/*.md`
- 公共课程要求：`docs/common/project-requirements.md`
- 公共测试要求：`docs/common/test/*.md`
- 测试与验收：`docs/想到什么取什么/**/*.md`

每类文档必须补上：

- 模块职责和不负责的范围。
- 独立运行入口，CLI/API/任务三选一或组合。
- 输入契约、输出契约、配置项。
- 状态、版本和持久化要求。
- 与其他模块的边界，不依赖页面点击或内存状态。
- 新验收标准。

必须删除或改写以下旧说法：

- “固定 `SOURCE_REPO`”。
- “当前关系库为五张表”。
- “阈值写死 `.env`”。
- “默认模型取 `version_key` 最大者”。
- “批量预测统一走 `/api/sync`”。
- “指标只读 `model_metrics.csv`”。
- “仅 expert 线有解释”。
- “不是独立行级模型”。
- “不作为 PR 强制门禁”；应改为“默认建议模式，不阻断；严格模式可按阈值阻断”。

### 3.2 第二阶段：按最新文档重构代码

必须按任务 1 到任务 8 的顺序推进，不允许继续在旧固定链路上叠加补丁。

- **任务 1**：先完成数据库、配置持久化、模型工件和算法库基础能力。所有模块后续只能通过仓库接口访问数据。
- **任务 2**：把仓库配置、收集任务、数据集展示和导出做成独立能力，去掉仓库环境变量固定依赖。
- **任务 3**：把清洗和预处理做成操作注册表 + 处理链配置 + preview/apply + 前后变化统计。
- **任务 4**：把训练封装为任务，支持算法多选、超参数、训练状态、工件登记和多模型比较。
- **任务 5**：把预测拆成单条/批量/数据集预测，提供模型加载、卸载、重载和默认模型配置。
- **任务 6**：把评估做成独立服务，按阈值和指标列表动态计算，不再只读旧 CSV。
- **任务 7**：建立 XAI 解释器注册表，至少支持 SHAP 与 LIME，输出统一解释结构。
- **任务 8**：提供完整源码浏览、行级定位服务、证据说明和修复建议；不自动修改代码。
- **任务 9**：前八项完成并验收后再做独立客户端、VS Studio 插件、Eclipse 插件和 CI/CD 分析步骤。

每个模块重构完成的定义：

- 有独立入口，能从 CLI 或 API 单独运行。
- 有配置文件或数据库配置项，关键参数不在代码中写死。
- 有输入契约、输出契约、错误码和空态处理。
- 有任务或结果状态，状态可持久化。
- 有单元测试和独立验收用例。
- 前端页面只调用模块能力，不承载业务计算。

### 3.3 第三阶段：清理旧模型文件和历史产物

允许删除的旧产物包括：

- `data_model/pipelines/*/models/*.pkl`：旧专家、语义、融合线权重。
- `data_model/pipelines/e2e/models/codebert_e2e_v1/` 下的旧 `model.safetensors` 和 tokenizer 产物。
- `data_model/data/semantic_embeddings.npz`、`data_model/pipelines/semantic/data/semantic_embeddings.npz`。
- `data_model/data/` 和各 `pipelines/*/data/` 下由旧流程生成的 CSV 缓存和 `prediction_result.csv`。
- `backend/static/figures/` 下旧静态图副本。
- `data_model/pipelines/*/reports/figs*` 下旧图集，待新评估流程可重新生成后删除。

删除规则：

1. 不要在重构开始前直接删除；先确认新流程能重新生成或不再需要。
2. 删除前在 `docs/` 或变更记录中写明删除原因、影响范围和恢复方式。
3. 文本清单 `feature_order.txt`、`manifest.txt`、`load_manifest.txt` 暂时保留，待新模型工件表可完整替代后再迁移。
4. `model_metrics.csv` 在新评估服务可产出等价数据前暂时保留。
5. 不得删除源码、测试、需求图片、`.codebuddy/` 目录或未确认用途的课程材料。

### 3.4 第四阶段：验收

重构完成前，必须逐项提供证据：

- 八个核心模块分别可独立运行的命令或 API 示例。
- 每个模块的输入、输出、配置、状态和版本说明文档。
- 配置保存到数据库后，重启服务仍可恢复。
- 新训练模型可登记并被预测模块加载，不依赖旧 `.pkl`。
- 阈值、指标和 XAI 技术可在页面切换，并影响结果。
- 缺陷定位能浏览完整源码并标出可疑行。
- CI/CD 和插件作为拓展能力调用同一分析内核，不复制业务逻辑。
- 旧产物清理记录。
- 全量测试通过。

## 4. 禁止事项

- 禁止继续宣称“当前五张表就是最终数据库设计”。
- 禁止在代码里新增加固定仓库、固定算法列表、固定阈值、固定解释器。
- 禁止用页面按钮作为模块唯一入口。
- 禁止只在旧 `/api/sync` 上继续叠加逻辑来冒充模块重构。
- 禁止复制一套新的指标计算、解释或定位算法，必须收敛为统一服务。
- 禁止在未确认可重建前删除旧权重和缓存。
- 禁止删除 `.codebuddy/` 目录。
- 禁止把任务 9 的插件/CI 当成前八项模块尚未独立时的补丁。

## 5. 完成判定

只有同时满足以下条件，才算本次重构完成：

1. `TODO/01` 至 `TODO/08` 的验收标准全部通过。
2. `docs/` 下不存在与最新 TODO 冲突的旧设计描述。
3. 代码实现与修正后的 `docs/` 一致。
4. 旧模型、缓存、图集等历史产物完成清理或有明确迁移记录。
5. 功能 9 的拓展至少定义了统一分析内核契约，后续插件和 CI 可直接复用。

在这些条件达成前，当前项目只能视为“旧理解下的可运行原型”，不能视为老师要求的最终系统。
