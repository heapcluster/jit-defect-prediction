# 任务 1：数据库存储

- **类型**：核心功能（图片功能 1）
- **状态**：待实现（当前部分具备）
- **前置依赖**：无
- **后续依赖**：任务 2、4、5、6、8、9

## 目标

让数据库不仅保存预测链路数据，还能统一管理缺陷数据集、用户信息、用户配置、已训练模型和算法库，并保证用户配置在进程异常关闭或重启后可恢复。

## 功能定义（开发交接）

**模块职责**：作为全部功能共享的持久化与配置中心，统一管理数据集、用户信息、用户配置、已训练模型工件和算法库；本模块只负责存储、查询、版本和配置恢复，不承担采集、训练、预测等业务计算。

**独立运行方式**

- 建表脚本和迁移脚本必须能脱离 Web 服务单独执行：空库初始化、旧库升级、重复执行都要通过。
- 配置、数据集、模型工件、算法库查询接口可以单独启动和测试，不依赖采集、训练或预测结果。
- 前端设置页通过接口读写配置，不能把 `.env` 或前端常量作为唯一配置来源。

**输入契约**：用户记录、配置键值、数据集元数据、模型工件元数据、算法定义、迁移脚本。

**输出契约**：标准化数据库结构；用户配置快照；数据集、模型、算法查询结果；迁移执行结果。

**可配置项**：默认数据集、默认模型、缺陷阈值、风险等级阈值、默认 XAI 技术、页面偏好。

**持久化要求**：所有配置必须落库；后端、容器或进程异常关闭后重启，配置可由接口恢复。API Key、密码等敏感信息不得入库。

**解耦要求**：其他模块只通过仓库接口访问数据，不直接散写 SQL 或依赖其他模块的内存状态；表结构变更必须同步更新 `infra/schema.sql`、迁移脚本和 ORM 模型。

## 当前状态

- 已有 MySQL 五张表：`commit`、`model`、`commit_feature`、`prediction`、`model_figure`，见 `infra/schema.sql:5-72`。
- 已保存提交元信息、Kamei 14 维特征、SZZ 真标签、模型元数据、风险分和图索引。
- `commit.author_name`、`commit.author_email` 是提交作者信息，不是系统用户信息。
- 运行时配置已下线：阈值写在 `.env` 和前端常量中，见 `backend/app/models.py:3-7`、`frontend/src/utils/thresholds.js:1-3`。
- 模型权重文件不在数据库中，当前只登记模型元数据。
- 算法以代码注册表和 `model.algo` 字符串存在，没有可查询、可管理的算法库。

## 待实现内容

1. **扩展数据模型**
   - 增加用户表，至少包含用户标识、显示名、角色、状态、创建时间。
   - 增加用户配置表，保存阈值、默认模型、默认数据集、解释技术、页面偏好等键值配置。
   - 增加数据集元数据表及数据集与提交的关联表，支持任务 2 和任务 5 的数据集选择。
   - 增加模型工件表，登记权重路径、校验值、文件大小、训练任务、状态、版本和适用特征版本。
   - 增加算法定义表，记录算法名、所属模型线、支持的超参数、启用状态和说明。

2. **数据库迁移**
   - 为新增表提供可重复执行、向后兼容的迁移脚本，不破坏现有五张表。
   - 保留 `infra/schema.sql` 作为干净环境建表真源，并确保迁移后的结构与之一致。
   - 增加迁移冒烟测试：空库初始化、旧库升级、重复执行均可通过。

3. **配置持久化接口**
   - 提供用户配置的读取、单键更新、批量更新和删除接口。
   - 配置写入后立即生效；后端重启、容器重启、异常关闭后能读取原有配置。
   - 对未知配置键、非法值类型和越权访问返回明确错误。

4. **模型与算法资产接口**
   - 提供数据集、模型工件、算法定义的查询接口。
   - 模型状态至少区分“可用、加载失败、已下线”。
   - 算法库信息供任务 4 的训练表单使用，不在前端重复硬编码算法清单。

5. **最小管理界面**
   - 提供用户配置查看与修改入口，可放在现有页面抽屉或新增设置页。
   - 展示已登记数据集、模型工件和算法库的基本信息。

## 验收标准

- 在干净数据库执行建表和迁移脚本成功，现有功能不受影响。
- 创建用户并保存一组配置，停止并重启后端后配置仍然保持。
- 通过接口能查询数据集、模型工件和算法库，且数据与数据库记录一致。
- 前端不再依赖写死的默认模型、阈值配置作为唯一来源；至少能读取持久化配置。
- 数据库中不保存 API Key、密码明文等敏感信息。
- 相关测试覆盖建表迁移、配置读写和重启恢复。
