# 任务 9：多种形态拓展

- **类型**：拓展功能（图片功能 9，任务 1-8 完成后再做）
- **状态**：待规划（当前仅 Web SPA 形态）
- **前置依赖**：任务 1-8
- **后续依赖**：无

## 目标

在核心能力稳定后，将预测、解释、定位与修复能力封装为可复用内核，并拓展到独立 IDE/桌面端、VS Studio 插件、Eclipse 插件和 CI/CD 流程，使提交事件可以自动触发分析并生成报告。

## 功能定义（开发交接）

**模块职责**：把任务 1-8 的核心能力封装成统一分析内核，并以独立客户端、VS Studio 插件、Eclipse 插件和 CI/CD 步骤等多种形态交付；本模块只负责适配、包装和事件触发，不重新实现任何核心算法或业务规则。

**独立运行方式**

- 核心分析内核提供独立命令和容器入口：输入提交范围、模型、阈值和报告配置，输出统一格式报告。
- 各插件和客户端通过内核 API/CLI 调用能力，可独立安装、独立配置服务地址和凭证。
- CI/CD 通过同一命令或镜像执行分析；Web 页面、插件和流水线生成的结果结构必须一致。

**输入契约**：仓库和提交范围、模型配置、阈值、XAI 技术、定位配置、报告格式、事件载荷、服务地址和凭证。

**输出契约**：JSON/Markdown/HTML 分析报告；风险、解释、可疑行和修复建议的结构化结果；报告链接或流水线附件；触发任务状态。

**可配置项**：目标端点、认证方式、报告格式、分析范围、严格模式开关、失败策略、事件去重窗口、是否阻断合并。

**状态要求**：事件载荷必须验签；同一事件只分析一次；失败可重试；令牌不得写入日志和报告；默认建议模式不阻断合并，只有显式开启严格模式才按阈值阻断。

**解耦要求**：所有载体只调用统一分析内核；禁止在插件、客户端或 CI 脚本中复制预测、解释、定位和修复建议逻辑。

## 待实现内容

1. **核心分析能力解耦**
   - 将“获取提交 → 特征 → 预测 → 解释 → 定位 → 修复建议 → 报告”封装为独立服务或 CLI。
   - 定义稳定输入输出契约，例如提交范围、模型、阈值、XAI 技术和报告格式。
   - Web、插件和 CI/CD 均调用同一内核，避免多套实现。
   - 支持离线模式和在线模式。

2. **独立 IDE/桌面端**
   - 提供可独立安装或启动的客户端，支持打开本地 Git 仓库、选择提交、运行完整分析链路并查看报告。
   - 复用任务 8 的源码浏览和定位结果。
   - 明确一期技术选型，例如 Electron/Tauri 或轻量 CLI + Webview，需审核后确定。

3. **VS Studio 插件**
   - 提供插件原型：在编辑器中查看提交风险、特征解释、可疑行和修复建议。
   - 支持调用本地服务或远程 API，并安全保存服务地址和令牌。
   - 明确支持的 VS Studio 版本和发布方式。

4. **Eclipse 插件**
   - 提供插件原型：展示风险列表、提交详情、解释和定位结果。
   - 与 VS Studio 插件共享同一后端接口和报告格式。
   - 明确 Eclipse 版本、打包和发布方式。

5. **CI/CD 集成**
   - 提供可作为流水线步骤执行的命令或容器镜像。
   - 对指定提交范围生成结构化报告和可读报告附件，例如 JSON、HTML 或 Markdown。
   - 默认采用建议模式，不阻断合并；通过配置可开启严格阈值门禁。
   - 明确失败策略：分析服务异常、模型不可用、仓库不可访问时是警告还是失败。

6. **提交事件触发**
   - 支持 Git hook、Webhook 或流水线事件触发预测解释与定位修复。
   - 同一事件只触发一次分析，支持去重和失败重试。
   - 分析结果写回数据库并生成可查看报告链接。
   - 事件载荷必须验签，令牌不得写入日志或报告。

7. **测试与文档**
   - 每种形态至少提供一个可运行示例和截图/录屏验收材料。
   - 增加 CLI 契约测试、插件接口测试和 CI 报告生成测试。
   - 补充各形态安装、配置、权限、故障排查和取消门禁的说明。

## 验收标准

- 核心分析内核可通过命令或容器独立运行，并输出统一报告。
- 独立客户端能打开本地仓库并完成一次完整分析。
- VS Studio 与 Eclipse 插件均能展示风险、解释、定位和修复建议。
- CI/CD 示例流水线能在提交后生成报告附件。
- 默认不阻断合并；开启严格模式后才按阈值阻断。
- 提交事件触发具备验签、去重、重试和日志脱敏。
- 各拓展形态不破坏现有 Web 系统。
