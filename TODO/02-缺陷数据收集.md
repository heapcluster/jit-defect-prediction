# 任务 2：缺陷数据收集

- **类型**：核心功能（图片功能 2）
- **状态**：待实现（当前部分具备）
- **前置依赖**：任务 1
- **后续依赖**：任务 3、5

## 目标

支持用户在页面上指定仓库并发起缺陷数据收集，展示收集后的数据集，保存到数据库，并能导出为 CSV 或 Excel。

## 功能定义（开发交接）

**模块职责**：把指定 Git 仓库转换为可查询、可导出的缺陷数据集，负责仓库配置、提交采集、SZZ 标注、特征提取、样本入库和导出；本模块只产出原始数据集，不做后续清洗变换、训练或预测。

**独立运行方式**

- 提供独立命令或任务入口，例如“传入仓库路径/URL、分支和时间范围，输出一个数据集版本”，不依赖页面点击或固定 `SOURCE_REPO`。
- 提供独立 API：创建收集任务、查询任务状态、查询数据集、导出数据集。
- 现有五个离线脚本应被封装为可复用服务，Web 入口和 CLI 入口调用同一实现。

**输入契约**：仓库路径或 URL、分支、采集时间范围或提交范围、是否拉取远端、数据集名称、去重策略。

**输出契约**：数据集版本记录；提交、特征、标签和划分标记；收集任务状态与统计；CSV/XLSX 导出文件。

**可配置项**：仓库地址、分支、时间范围、提交范围、HEAD 校验、增量/全量模式、导出字段范围。

**状态要求**：任务状态至少包含排队中、运行中、成功、失败、已取消；失败时保留可读日志，支持重试；重复运行同一配置不得产生重复提交。

**解耦要求**：本模块产出的数据集版本交给任务 3 处理；不在本模块内写死清洗规则、训练算法或模型路径。

## 当前状态

- 离线采集链已具备：`01_extract_commits` → `02_szz_labeling` → `03_extract_features` → `04_build_dataset` → `05_split_dataset`。
- 在线同步入口已有：`POST /api/sync`、`GET /api/sync/status`。
- 风险列表可展示提交、作者、时间、风险等信息，并支持按架构、模型、时间范围触发同步。
- 仓库固定由 `SOURCE_REPO` 环境变量指定，前端没有仓库输入入口。
- 没有 CSV/Excel 导出接口或下载按钮。
- `data_model/evaluation/export_sql.py` 导出的是 MySQL 初始化 SQL，不是图片要求的 CSV/Excel。

## 待实现内容

1. **仓库配置与数据集创建**
   - 提供仓库路径或 URL、分支、时间范围、提交范围等输入项。
   - 对仓库路径和 URL 做安全校验，避免任意命令执行和越界目录访问。
   - 支持创建数据集记录，保存来源仓库、分支、HEAD、采集时间、样本数和状态。
   - 同一仓库重复采集时支持增量更新和去重，不破坏已有标注结果。

2. **收集任务管理**
   - 将现有采集脚本封装为可复用服务或幂等任务，不复制特征口径。
   - 返回任务状态、进度、成功数、失败数和错误信息。
   - 收集失败时保留可诊断日志，并允许重试。
   - 收集完成后自动写入任务 1 定义的数据集表和关联表。

3. **数据集展示**
   - 提供数据集列表与详情，至少展示名称、来源仓库、时间范围、样本数、正负样本比例、创建时间和状态。
   - 支持查看数据集中的提交样本及其特征、标签、是否属于测试集。
   - 支持按数据集筛选风险列表和后续预测目标。

4. **数据导出**
   - 增加导出接口，支持按数据集、时间范围、模型、风险等级等条件筛选。
   - 支持 CSV 导出，字段包含提交元信息、特征、标签和可选预测结果。
   - 支持 XLSX 导出；如后端缺少依赖，需补充 `openpyxl` 等依赖并锁定版本。
   - 设置正确的文件名、编码和 `Content-Disposition` 响应头；中文不乱码。
   - 前端增加“导出 CSV / 导出 Excel”按钮。

5. **文档与测试**
   - 更新采集、API 和页面文档，明确在线收集与离线脚本的边界。
   - 增加接口测试、任务状态测试、导出格式测试和大数据量分页导出测试。

## 验收标准

- 用户可在页面输入仓库并成功发起收集，无需修改 `.env`。
- 收集完成后，数据集和提交样本可在页面查询，数据库中有对应持久化记录。
- 同一条件下重复收集不会产生重复提交。
- 导出的 CSV 和 XLSX 文件可正常打开，字段完整、中文不乱码、筛选条件生效。
- 收集失败时页面显示明确错误原因，任务可重试。
- 现有 Camel 固定数据集链路仍可运行。
