## 职责

三个页面：风险列表（按风险高低排序、可筛选、可翻页）、提交详情（缺陷概率 + 为什么判为高风险）、缺陷引入趋势看板（按周或按月）。

## 交付物

页面、图表、联调记录。

**低保真原型与交互设计在飞书《产品需求文档》六、交互原型图**（不在仓库）；页面与接口的字段映射在 `docs/pages.md`。

## 目录结构（按这个放，不要新建同级目录）

| 路径 | 放什么 |
|---|---|
| `frontend/src/views/` | 三个页面，一个页面对应一个文件 |
| `frontend/src/api/` | 接口请求封装（集中在一处，不要散在各页面里） |
| `frontend/src/components/` | 复用组件（ECharts 封装等） |

## 技术栈与启动

Vue 3 + Element Plus + ECharts。

```bash
cd frontend
npm install
npm run dev          # 开发服务，默认 5173
```

- 后端地址走**本地代理**（`/api` → `http://localhost:8000`），不要把它硬编码进页面。
- 依赖加进 `package.json`，`package-lock.json` 一并提交；`node_modules/` 已被 `.gitignore` 排除。

## 页面 ↔ 接口 ↔ 字段

**唯一的对照表是 `docs/pages.md`** —— 每个页面用接口的哪些字段、三态与错误码怎么处理，都在那里。接口本身的定义以 `docs/contracts/api-format.md` 为准。

| 页面 | 接口 | 字段映射 |
|---|---|---|
| 风险列表 | `GET /api/commits` | `docs/pages.md` 第 2 节 |
| 提交详情 | `GET /api/commits/{commit_hash}` | `docs/pages.md` 第 3 节 |
| 趋势看板 | `GET /api/trends` | `docs/pages.md` 第 4 节 |

**只有这三个页面。** 第四个（模型管理、用户设置之类）不做 —— 课程没要求，且会稀释前三个页面的完成度。

## 七条通用约定（违反即联调事故）

1. **字段名与契约完全一致**，前端不做改名或驼峰转换：后端给 `risk_score`，变量就叫 `risk_score`。
2. **概率由前端转百分比显示**；后端返回 `0.0` ~ `1.0` 的小数。
3. 时间转本地时区展示（接口给的是 ISO 8601 带时区）。
4. 响应包络统一，只判 `code === 0`。
5. **三态必须有**：加载中 / 空数据 / 请求失败。「空数据」不是错误 —— 两者的文案与后续操作完全不同。
6. 按错误码区分处理，不把服务端 `message` 原样甩给用户当技术细节；`40100`（令牌失效）不重试，提示重新登录。
7. 图表统一 ECharts，不混用其他图表库。

**高风险阈值（`risk_score ≥ 0.5`）只在 `docs/pages.md` 第 5 节定义一处**，三个页面统一用，不要各页各写一个数。

## 边界

- **不直连数据库、不自己算指标** —— 风险概率与聚合结果都来自接口。
- 接口不够用时**先提契约变更**，不要临时改字段名或自己拼数据。
- 只在本目录内写代码。
