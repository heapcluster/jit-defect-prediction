## 3. 口径与边界（避免数字被误读）

1. 统计范围是 `--cov=app`（后端应用代码）；**不含** `backend/scripts/`（压测 / 安全 / 灌库脚本，其产出由本目录另四份 `perf-*.md` / `security-*.md` 验证）与 `backend/tests/`。
2. 未覆盖行已逐段读代码核对，**都是可命名的具体缺口**，不是统计噪声：

| 模块 | 未覆盖段实际是什么 | 为什么没覆盖 |
|---|---|---|
| `app/db.py` 42% | 22-25 `get_engine()` 建真连接（含 `DATABASE_URL` 缺失→50000）；37-39 `init_db()`；43-53 `_assert_indexes()` **索引自检全段**；57-67 CLI `main()`；71 `__main__` | 测试用 `configure_engine()` 注入 SQLite 内存库，绕过 `get_engine()`/`init_db()`；`python -m app.db init` 这条 CLI 路径无任何测试。**索引自检是「建表即校验唯一索引」的唯一防线，当前零覆盖** |
| `app/ingest.py` 58% | 36-44 `_upsert_labels`；48-60 `_upsert_features`；64-72 `_upsert_predictions`；109-115 CLI `main()`；119 `__main__` | `backend/tests/test_ingest.py` 只测了 `commits` 一种（幂等 + 缺键回滚 2 条）；labels / features / predictions 三种灌库路径零覆盖 |
| `app/api/predict.py` 87% | 70-80 `IntegrityError` 并发双插回落为 update 的分支 | 幂等保护的异常路径，需要「同一 `commit_hash`+`model_name` 并发双插」的夹具才触发，现有单测走不到 |
| `app/model_registry.py` 86% | 44-45 模型目录不存在→warning 返回；49-52 `joblib.load` 失败→`continue`；69-73 XGBoost `get_booster().num_features()` 分支及其异常；137 `_first_row` 的 list 分支；157-159 SHAP 解释失败→降级空数组；187 自带 `_jit_background` 分支 | 降级/异常路径需要「坏模型文件、缺目录、解释器抛错」三类夹具；交付包里的真模型只走正常路径 |
| `app/api/trends.py` 97% | 22 月粒度 `_period()` 返回 `YYYY-MM` 的分支 | `grep -rn month backend/tests/` **零命中** —— 月粒度聚合至今没有后端测试（前端 PR #60 已在用 month 响应） |
| `app/errors.py` 91% | 33 `ok()` 包络辅助函数；58-59 未处理异常兜底 handler（50000 + 只写日志） | `ok()` 各路由未调用（直接构造包络）；兜底 handler 需要「路由内抛非 AppError 异常」的用例 |

3. **本 PR 不设 CI 门禁**（没加 `--cov-fail-under`）：阈值与门禁入口由 PR #72（lint→test→build CI）统一定，避免两处各定一套。
4. PR #62（时间区间语义，新增 6 条用例）合入后 `app/api/commits.py` 的行数与覆盖会变；本机在该分支 head `9073cea` 实测全套 **45 条 → 45 passed，TOTAL 84%**（600 stmts / 95 miss），结论不变。

## 4. 后续（Sprint 2 按此顺序补，前两条是本轮量出来的真缺口）

| 优先级 | 缺口 | 补法 | 归属 |
