# 接口通用约定

本文件是响应结构、错误码、鉴权、分页与异步任务的唯一真源；模块文档只写各自的端点与字段。

## 1 基础

- 前缀 `/api`，请求与响应均为 JSON；上传使用 `multipart/form-data`。
- 时间使用 ISO 8601，带时区偏移。
- 所有接口按当前会话用户处理数据，不接受前端传 `user_id`。

## 2 鉴权

- 登录成功后由服务端下发 `Set-Cookie: jit_session=<opaque>; HttpOnly; SameSite=Lax; Path=/`。
- 会话记录存 MySQL `user_session`：Cookie 只含原始令牌，服务端保存其 SHA-256 摘要。
- 会话有效期 7 天，不做滑动续期；登出删除会话记录，旧 Cookie 立即失效。
- 除 `POST /api/auth/login` 与 `GET /api/health` 外，所有 `/api/**` 都需要有效会话。
- 每次请求同时校验会话未过期与账号 `status=active`。
- 会话缺失或失效返回 `401`，错误码 `40101`。
- 不提供 `X-API-Key` 等其他鉴权方式。

## 3 响应结构

```json
{ "code": 0, "message": "ok", "data": {} }
```

- 成功时 `code` 为 `0`，`data` 为业务数据；无数据时 `data` 为 `null`。
- `GET /api/health` 无需登录，返回 `{ "code": 0, "message": "ok", "data": { "status": "ok" } }`。
- 失败时 HTTP 状态非 2xx，`data` 为 `null`，`message` 为可直接展示的中文原因。
- 业务错误可在 `data` 中带明细，如不符列、非法行号。

## 4 错误码

| code | HTTP | 含义 |
|---|---|---|
| 40001 | 400 | 参数非法或取值越界 |
| 40101 | 401 | 未登录、会话失效或登录凭证错误 |
| 40401 | 404 | 资源不存在或不属于当前用户 |
| 40901 | 409 | 状态冲突（重复提交、不可保存、结果已失效） |
| 41301 | 413 | 上传文件超过大小上限 |
| 42201 | 422 | 上传文件字段校验失败 |
| 42901 | 429 | 已有运行中任务，拒绝新任务 |
| 50001 | 500 | 内部错误 |
| 50301 | 503 | 外部依赖不可用（平台接口、模型运行环境） |

- 资源不属于当前用户时统一返回 `40401`，不返回 `403`，避免泄露存在性。

## 5 分页

请求参数：`page`（从 1 开始，默认 1）、`page_size`（默认 20，最大 100）。

```json
{ "items": [], "total": 120, "page": 1, "page_size": 20 }
```

## 6 异步任务

- 启动类接口返回 `202`，`data` 为 `{ "job_id": "..." }`。
- 进度统一通过 `GET /api/jobs/{job_id}` 轮询，返回状态、当前阶段、总量与已完成量。
- 取消统一通过 `POST /api/jobs/{job_id}/cancel`，任务进入 `cancelled`，本轮未保存产物丢弃。
- 任务状态与流转见 [../约束/job-state.md](../约束/job-state.md)。

## 7 文件上传与下载

- 上传数据文件（CSV / Excel）总大小上限 100MB；模型文件（`.pkl` / `.pt`）上限 200MB；超限在读取请求体前拒绝。
- 上传文件落在 `temp/uploads/<user_id>/<file_id>/`，只作本次输入；页面重置、开始新流程或校验失败时清理。
- 同一页面可同时存在 `data` 与 `model` 两类上传（仅预测页），再次导入只替换同类；页面重置清理该页全部上传。
- 下载必须校验归属，非本人资源返回 `40401`。
- 导出文件名由用户填写，服务端只做非法字符校验；扩展名由 `format` 决定。
- 模型文件下载扩展名由 `model_artifact.format` 决定：`pkl` 返回 `.pkl`，`pt` 返回 `.pt`。
- CSV 导出统一 UTF-8 BOM、逗号分隔；Excel 首行为表头。

## 8 幂等

- 同一用户同一时刻只允许 1 个运行中任务；重复提交返回 `42901`。
- 保存数据集使用 `job_id` 幂等：同一任务重复保存返回已存在的数据集，不重复创建。

## 9 数据表输入校验

- 所有外部 CSV / Excel 与已保存数据集作为输入时，按对应字段契约逐列校验列名、顺序与数量。
- Excel 只读第一个工作表，首行作为表头。
- 缺列、多列、列序不符、表头为空或两线均不匹配时拒绝，返回 `42201`，`data.mismatch` 给出第一处不符列：`{ "column_index": 8, "expected": "nd", "actual": "num_dir" }`。
- 标签值非法时返回 `42201`，`data.invalid_rows` 给出前若干行号。
- 不允许部分导入、自动补列或跳过校验；校验失败不能进入下一步。
- 唯一例外：预测输入允许不含 `bug` 列，其余元数据与特征列必须完整匹配。
- 同一数据集或预测输入只允许一个 `project`（仓库）；出现多个 `project` 时拒绝，因为提交标识按仓库唯一。
- `commit_hash` 统一为 40 位小写十六进制；格式不符按 `42201` 拒绝。
- 已保存数据集在保存前已完成校验；再次作为输入时仍按当前字段契约重新校验。

## 10 保存与自动入库

- 数据集、模型、预测结果、评估历史只在用户主动点击「保存到数据库」时写入。
- 预览、执行、导出、刷新页面、重新登录都不自动入库。
- 页面进度自动保存到 `user_page_state`，但不属于业务数据资产。
- 保存为单请求内的顺序写入；同一用户同一时刻只允许一个保存请求（前端按钮防重），不做并发控制与补偿任务。
- 保存失败返回错误码，由用户重试；不设计断点续传或后台补写。

## 11 提交标识命名

| 场景 | 字段 | 含义 |
|---|---|---|
| 外部 CSV / Excel 列，导入与导出 | `commit_id` | Git 提交哈希 |
| JSON 接口字段 | `commit_hash` | Git 提交哈希 |
| 表 `commit` / `commit_feature` | `commit_id` | 内部 UUID 主键 |
| 表 `commit` / `dataset_commit` / `prediction` | `commit_hash` | Git 提交哈希 |

- 除直接透传的外部表数据外，JSON 接口一律用 `commit_hash`；数据库内部 `commit_id` 不得出现在接口响应中。
- 路由参数 `/commits/{commit_hash}` 同样指 Git 哈希。
- `commit_hash` 统一转小写后存储、比较与作为主键。

## 12 标识格式

- 服务端生成的业务 ID 为「类型前缀 + 32 位小写十六进制」，总长不超过 36：`u_`（用户）、`ds_`（数据集）、`job_`（任务）、`eva_`（评估）、`art_`（模型文件）、`fig_`（图表）、`cmt_`（提交内部主键）。
- `session_id` 为令牌的 64 位十六进制摘要，不带前缀。
- `file_id` / `model_ref` 是临时标识，只存在于当前页面生命周期，格式由服务端生成，前端只透传。
- ID 对前端不透明；除服务端生成默认名称外，前端不得解析或拼接 ID。
