> 课程要求「技术架构应服务于实际产品，建议三层架构/微服务架构」。

## 1. 三层架构

```
┌─────────────────────────────────────────────┐
│ 表现层（前端） Vue3 + ElementPlus + ECharts     │  三页面
├─────────────────────────────────────────────┤
│ 接口层（后端） FastAPI + 鉴权 + 错误码包络       │  四接口
├─────────────────────────────────────────────┤
│ 数据层                                       │
│   ① MySQL：commit/label/feature/prediction    │
│   ② 模型文件 data_model/models/*.pkl（A+C）    │
│   ③ 数据线脚本 data_model/*.py（不直连库）     │
└─────────────────────────────────────────────┘
```

## 2. 主要组件

| 组件 | 职责 | 线 |
|---|---|---|
| 前端三页面 | 风险列表/提交详情/趋势看板 | 刘帅华 |
| FastAPI 路由 | commits/predict/trends 四个接口 | 吕建江 |
| model_registry | **模型插件注册表**：加载 `.pkl` + SHAP 解释（8 种模型可插拔，见 `engineering.md` §4） | 吕建江（跨线 A） |
| MySQL | 四张表读写 | 吕建江 |
| 数据线脚本 | 抽取/SZZ/特征/训练/全量预测 | 蒋励 |
| 协作规范 / 模板 / CI-CD / 插件化 | 工程基线（见 `design/engineering.md`） | 苏哲勋 |

## 3. 外部依赖

- Camel 仓库（固定 `camel-4.23.0`）—— 数据来源，不入库。
- GitHub（协作/PR/Issue/OpenSpec）、飞书多维表格（看板/周报）。
- 本地代理 `127.0.0.1:7890`（git 直连 github 用）。

## 4. 跨线依赖顺序（铁链）

```
工程与协作 ──规范/模板──▶ 全员
数据与模型 ──模型文件/特征定义──▶ 后端 ──接口──▶ 前端
```
任一环卡住全线停摆；Sprint 0 重心打通数据链路。

## 5. 系统定位（三个限定词）

提交粒度（非文件/行/需求）｜ 建议性预警（只排序不 CI 拦截）｜ 单仓库（只 Camel）。
