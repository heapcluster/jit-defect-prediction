## 2. 🚀 后续工作开展方式（每次改设计的标准动作 · 必须走 OpenSpec）

1. **先提 change**：设计变更 = 需求变更，必须提 OpenSpec change（propose→apply），不要直接改飞书文档不记规格。
2. **仓库侧先落设计稿**：在 `design/` 对应文件改，蒋励统稿；飞书《产品设计文档》变更日志加一行（如 L3）。
3. **图生成标注**（课程硬要求）：所有 AI 生成的图，图旁必须记一行：
   `> 生成方式：<工具名+模型> ｜ 提示词：<原样粘贴>`（见 `diagrams.md` 每图下方）。
4. **同步下游**：设计字段变了 → 通知对应线同步 `api-spec.md` / `feature-columns.md` / `pages.md`（字段一致铁律）。
5. **审阅 + 回写**：设计 PR 由非作者成员审阅；看板置完成 + 周报记证据。

## 3. 🚫 你的红线

- **不重复飞书**：用户/场景/MVP/竞品在飞书 PRD，本包只放技术设计（架构/库表/图/非功能/原型指针）。
- **字段一致**：设计里的库表字段名 = `database.md` = 后端 `db.py` = 前端展示，零漂移。
- **图可追溯**：每张图必须有生成方式标注，否则课程判定为不合规。
- **冻结点**：Sprint0 边界（`sprint0-scope.md`）内的「做/不做」不得随意扩，要扩先提 change。
