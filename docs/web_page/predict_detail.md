# 预测详情页（PredictDetail）

模型预测下的独立页面　路由 `/predict/commit/:hash`（旧 `/commit/:hash` 重定向到此）　query `model_name|job_id`

## 1. 页面定位

- 目标：查看**此次 commit** 的提交详情与预测详情；在预测详情之后，提供针对该 commit 的预测结果解释与缺陷定位修复两个普通板块。
- 入口：模型预测页预测结果二维表的任意一行（携带 `commit_hash`、`model_name`、`job_id`）、直接访问提交 URL。
- 出口：解释与定位均在本页内作为普通板块完成，不跳转到独立页面；返回由浏览器历史决定。
- 不负责：批量预测编排、批量解释、批量定位、模型登记与训练；本页默认只读，只有显式点击才重算。
- 页面组织：单页内容区，按“提交与预测详情信息 → 预测结果解释 → 缺陷定位及修复 → 重新预测”纵向排列。
- 范围约束：解释和定位只针对当前 `commit_hash` 与当前 `model_name`，不展示批量解释 / 批量定位入口，不把批次产物当作解释或定位结果；UI 不刻意展示功能编号 ⑦ / ⑧。

## 2. 页面结构


## 3. 区域与组件

| 区域 | 内容 | 交互与约束 |
|---|---|---|
| 返回 | `← 返回` | 调用 `$router.back()`；404 时错误区提供回到列表入口 |
| 风险结论 | 风险百分比、风险标签、模型标签、SZZ 真标签 | 属于预测详情主体；未预测时隐藏百分比且不补 0；真标签三态为已确认有缺陷 / 已确认无缺陷 / 尚未标注 |
| 批次结果提示 | `job_id` 存在时读取批次预测产物并说明来源 | 只读取该 commit 对应的预测行；批次读取失败时保留库内详情并提示；不把整个批次展示为当前 commit 结果 |
| 提交与预测详情 | 提交 / 作者 / 时间 / 预测时间 / 判定结果 / 判定阈值 / 预测模型 / 信息 | 页面主体字段；后端把判定字段放在 `prediction` 中，页面合并到顶层展示；缺失字段显示“未提供”；`stale=true` 时显示“模型已更新，建议重新预测” |
| 影响判断的主要因素 | 14 项专家特征按五组只读展示 | 属于预测详情主体；分组为代码分布、规模、目的、历史、开发者经验；数值保留 4 位小数，缺失显示 `—`；原始字段名通过 tooltip 展示 |
| 预测结果解释 | 解释方式下拉、刷新按钮、结论、贡献条、空态 | 普通详情板块，不显示功能编号；只针对当前 `commit_hash` 与当前 `model_name`；技术列表来自 `GET /api/explain/techniques`；贡献按绝对值降序最多 8 条；方向和数值同时表达 |
| 解释生成 | [刷新解释] / [生成解释] | 无模型或被禁用时不可操作；解释请求使用 `explainEpoch` 丢弃过期响应；风险结果不随解释失败清空 |
| 缺陷定位及修复 | 入口按钮、定位摘要、行级可疑代码、修复建议 | 普通详情板块，不显示功能编号；只针对当前 commit；行级分档是服务端启发式优先程度，不是训练出的行级概率；点击后在本页内运行定位并展示结果，不跳转独立页面 |
| 行级展示 | 文件路径、优先程度、理由、新增行、分档图例 | ≥70% 优先检查，40–70% 建议检查，<40% 一般；截断时提示只展示最值得检查的部分 |
| 修复建议与参考 | 可执行建议与同仓库历史修复提交 | 仅当当前 commit 详情包含 `fix_references` 时显示；无历史项时显示空态 |
| 重新预测 | 架构 / 模型级联、[预测]、[立即重算] | 默认沿用本条预测模型；`force_recompute` 显式勾选才启用；成功后更新风险与详情并重新加载解释；401 时禁用写操作 |

## 4. 主流程

1. 用户从预测结果二维表点击某一行进入本页，URL 携带 `commit_hash`、`model_name`、`job_id`。
2. 页面按 `props.hash` 读取提交详情；后端详情接口需要模型名，页面依次从 `route.query.model_name`、批次结果、模型清单解析。
3. 带 `job_id` 时读取任务输出中的 `predictions.csv`，只取该提交这一行；若该提交不在展示库，仍可用批次结果显示风险结论。
4. 合并库内详情与批次结果；`prediction` 字段提升到顶层；设置批次来源提示。
5. 用户先查看风险结论、提交与预测详情、影响判断因素。这是页面主体。
6. 用户继续查看预测结果解释：有风险结果时加载解释技术列表并请求解释；下拉切换或点击 [刷新解释] 会重查；空结果时可点击 [生成解释]。
7. 用户继续查看缺陷定位及修复：若本页已有定位结果则直接展示行级与提交级摘要；否则点击 [运行定位并查看修复建议] 在本页内请求定位并展示结果。
8. 用户查看修复建议与历史参考；确认需要更新结果时，在页尾选择模型并显式点击 [预测]。
9. 路由参数 `hash` 或 `model_name` 变化时清空旧详情、解释与定位结果，避免组件复用时显示上一条提交。

## 5. 状态与反馈

| 状态 | 表现 |
|---|---|
| 加载中 | 6 行骨架；预测结果解释与缺陷定位及修复板块暂不渲染 |
| 提交不存在 | 错误提示 + [返回列表] |
| 服务错误 | 错误提示；500 类错误提供 [重试] |
| 未预测 | 隐藏风险百分比与解释区，不补 0 |
| 尚未标注 | 显示“尚未标注”，不当作无缺陷 |
| 批次结果不可用 | 保留库内详情，并提示批次读取失败 |
| 仅批次有结果 | 显示该 commit 的批次风险结果，并说明逐项解释需先生成单条预测 |
| 模型已更新 | 预测详情中显示“模型已更新，建议重新预测” |
| 解释中 | 解释按钮 loading，切换技术可重查 |
| 解释失败 | 预测结果解释板块显示原因，风险结论与预测详情保持 |
| 定位无结果 | 缺陷定位及修复板块显示“当前提交暂无定位与修复结果，可在上方运行定位。” |
| 鉴权失败 | 解释、定位与重新预测按钮禁用，提示重新登录 |
| 重新预测中 | [预测] 按钮 loading；成功后刷新风险、预测详情与解释 |

## 6. 接口映射

| 能力 | 接口 / 路由 |
|---|---|
| 提交预测详情 | `GET /api/commits/{commit_hash}?model_name=` |
| 批次任务详情 | `GET /api/jobs/{job_id}` |
| 当前 commit 的批次预测结果 | `GET /api/predict/outputs/{job_id}/{name}` |
| 模型清单 | `GET /api/models` |
| 重新预测 | `POST /api/predict` |
| 解释技术清单 | `GET /api/explain/techniques` |
| 生成 / 刷新解释 | `POST /api/explain` |
| 当前 commit 的缺陷定位及修复 | `POST /api/localize/run`、`GET /api/source/tree`、`GET /api/source/file` |
| 兼容地址 | `/commit/:hash` → `/predict/commit/:hash` |

## 7. 响应式与可访问性

- 风险结论、解释操作条、定位操作条和重新预测操作条使用 flex-wrap，窄屏自动换行。
- 提交与预测详情为两列信息行，窄屏保持标签与值可读；长提交信息与代码行可折行查看。
- 风险使用文字标签与百分比共同表达；解释贡献使用正负号和方向条；行级分档提供文字图例。
- 特征与解释项悬停显示原始字段名，中文名作为主要可读文本。
- 按钮、下拉和复选框均可键盘操作；当前代码行与贡献条仅作展示，不提供键盘编辑入口。
- 两个普通分析板块只用文字标题区分，不使用功能编号徽标或强调色块。

## 8. 验收清单

- [ ] 页面标题与主体内容是当前 commit 的提交详情与预测详情，不以功能编号作为页面重点。
- [ ] 页面主体先展示风险结论、提交与预测详情、影响判断因素。
- [ ] 提交与预测详情之后才展示“预测结果解释”和“缺陷定位及修复”两个普通板块。
- [ ] 解释与定位只针对当前 `commit_hash` 与当前 `model_name`。
- [ ] 页面不展示批量解释、批量定位入口，也不把批次产物当作解释或定位结果。
- [ ] 带 `job_id` 时只从批次产物中读取该 commit 对应行。
- [ ] 解释技术支持切换和刷新，最多展示 8 条贡献，过期响应不会覆盖当前结果。
- [ ] 解释失败不清空风险结论与预测详情，并能给出可读原因。
- [ ] 定位入口携带提交哈希与模型并在本页内运行，不跳转独立定位页；行级优先程度与提交风险概率明确区分。
- [ ] 修复建议与历史参考仅在当前 commit 详情提供时显示。
- [ ] 重新预测默认沿用本条模型，`立即重算` 需显式勾选。
- [ ] 401 时禁用解释、定位与重新预测写操作。
- [ ] `hash` 或 `model_name` 路由参数变化时会重新加载，不复用上一条详情。
- [ ] 窄屏下提交与预测详情、贡献条、特征值和代码行仍可阅读。
