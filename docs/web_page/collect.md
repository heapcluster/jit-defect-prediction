# 缺陷收集工具台（Collect）

实现状态：已实现　期次：一期

W3 已接线 `/collect` 两个子视图、真实 job 进度、CSV/XLSX/manifest 下载、显式导入及成员展示。测试为 AI 生成、尚未人工审核；截图与视觉验收单独记录，不把接口或 DOM 检查冒充截图证据。完整八功能导航编排仍属 W10。

## 一句话

独立收集工具：指定仓库路径/URL 与采集范围（可选上传提交清单文件圈定范围），运行收集 job，产出 `commits.csv`（§3.1）+ manifest，预览、下载（CSV/XLSX），可选导入库（commit/commit_feature/dataset）供提交详情与后续模块选用；库空、上游未跑也能完整运行。

## 入口与导航

- 本页为功能②（缺陷数据收集）tab「收集」，路由 `/collect`；页内子视图（子签）为「收集工具台」与「已收集数据集」，导航见 [README.md](README.md)。
- 本页是收集模块的唯一 Web 入口；CLI 与本页调用同一服务实现，同参数产出等价文件。
- 输出文件契约：[../file-contracts.md](../file-contracts.md) §3.1（commits.csv）、§3.9（manifest）。

## 控件与接口映射

| 控件 | 端点 | 说明 |
|---|---|---|
| 仓库路径/URL、分支、时间范围、模式、数据集名 | `POST /api/collect/run`（multipart 表单字段） | 仓库路径限定允许根目录；URL/路径安全校验，文件名不拼 shell |
| 提交清单拖拽上传 / 或选库中文件 [▾] | `POST /api/collect/run`（multipart 文件）；下拉清单 `GET /api/datasets` | CSV/XLSX 双入；库中文件仅是便利选项，非运行前提 |
| [运行] | `POST /api/collect/run` | 提交即返回 `job_id`，不同步等待 |
| 进度条 / [日志][重试][取消] | `GET /api/jobs/{id}`；`POST /api/jobs/{id}/retry\|cancel` | 五态 queued/running/success/failed/cancelled；日志读 `error_log`（脱敏） |
| 预览表 / 统计 | `GET /api/collect/preview/{job_id}`；统计读 jobs.output_ref_json.summary | 服务端只取前 20 行；完整文件另行下载，schema 按 §3.1 提示 |
| [CSV] [XLSX] | `GET /api/collect/outputs/{job_id}/{name}` | 下载本次已登记的对应格式文件，不用 query 临时转换；CSV 为 UTF-8 BOM，XLSX 同批生成 |
| [manifest] | `GET /api/collect/outputs/{job_id}/{name}.manifest.json` | §3.9：配置快照 + 输入/输出 checksum + 代码版本 |
| [导入库] | `POST /api/storage/import` | commit+commit_feature+dataset 幂等 upsert；风险列表/趋势需 predictions 导入后才有展示 |
| 已收集数据集展示区 | `GET /api/datasets` | 页内子视图只读展示已导入数据集版本列表；库空显示「暂无已导入数据集」与 [去①数据管理导入](storage.md)，不触发收集或其他业务计算 |
| [保存默认分支与模式] | `PUT /api/config/page_prefs`，随后重新 GET 配置 | 显式保存 collect_branch/collect_mode，保留其他偏好，重启恢复；不改已创建任务 |

## 交互流程

1. 填仓库路径/URL（或选择已有数据集仓库）→ 提交前按已读取的允许根目录、协议与 URL 格式做明显非法校验；前端不能解析符号链接或 DNS，后端仍须最终安全校验，非法不创建 job。
2. 可选上传提交清单（拖拽 CSV/XLSX）或从库中下拉选择，圈定采集提交范围；不上传则按时间范围全量/增量采集。
3. 配置分支、时间范围、增量/全量、数据集名 → [运行] 调 `POST /api/collect/run`（multipart）→ 返回 `job_id`。
4. 轮询 `GET /api/jobs/{id}` 展示五态进度（采集 → SZZ 标注 → 特征提取 → 构建 → 划分阶段）；进度收在全局 store，切路由不丢。
5. 成功后通过 preview 端点渲染前 20 行 + §3.1 schema 提示 + 样本统计；未打标 `is_bug_inducing` 显示「未打标」，不渲染 0。数据集成员接口同样使用 is_bug_inducing 与平铺的 14 个特征字段，不把已知标签错读成空值。
6. [CSV]/[XLSX]/[manifest] 经 `GET /api/collect/outputs/{job_id}/{name}` 下载；XLSX 单 sheet 主表，manifest 不入 sheet。
7. 可选 [导入库] 调 `POST /api/storage/import`，把本次输出导入 commit/commit_feature/dataset 表；成功提示「提交与数据集已入库，可供详情页与后续模块选用」；风险列表/趋势看板在预测结果导入后才展示本数据集；不导入不影响本次文件交付。
8. 切到页内子视图（子签）「已收集数据集」，经 `GET /api/datasets` 只读展示已导入数据集版本列表；库空显示「暂无已导入数据集」与 [去①数据管理导入](storage.md)。该展示区不承载业务计算、不作为收集工具运行前置，导入完成后可刷新查看。
9. 失败：job 置 failed，展示 `error_log` 脱敏文案 + [重试]；同配置重复运行增量去重，不产生重复提交、不破坏已有标注。

## 空态与错误

- 三态：加载中（骨架屏）/ 空（库空时下拉显示「暂无已导入文件，可直接上传」）/ 失败（错误文案 + 重试）。
- 非法输入：清单缺 `commit_hash` 列 / 错类型 / 公式注入单元格（`= + - @` 开头）/ 超大小上限 / 扩展名与魔数不符 → 40001 明确报错，不产半成品文件。
- 仓库不可达 / 分支不存在 / 时间范围为空集 → job failed，`error_log` 可读原因 + [重试]。
- 错误码：40001 参数与校验 / 40100 鉴权（禁用 [运行]）/ 40400 job 或产出不存在 / 50000 内部错误。
- 进程重启遗留 running 置 failed（「进程重启中断」），配置与任务状态可从库恢复。

## 验收

- 只上传输入（仓库参数 + 可选清单文件），库空、上游未跑，即可完成运行并下载 `commits.csv` + manifest。
- 非法文件（缺列/错类型/公式注入/超大小）明确报错，不产半成品。
- 输出 CSV 用 Excel 打开中文不乱码（UTF-8 带 BOM）；XLSX 可选产出且主表单 sheet。
- manifest 可下载，checksum 与输出文件逐一一致；含配置快照与代码版本。
- CLI 同参数运行产出等价文件（schema 逐列断言 + 关键数值断言，fixtures：`tests/fixtures/files/collect/`）。
- 同配置重复收集不产生重复提交；增量模式不破坏已有标注。
- 预览表 schema 提示与 §3.1 一致；未打标显示空态而非 0。
- [导入库] 后 commits/dataset 相关读端点可查到本数据集；风险列表/趋势页在预测结果导入前不展示本数据集，不作误导性承诺；不导入时展示页不受影响。
- 「已收集数据集」通过 `GET /api/datasets` 只读展示已导入数据集版本列表；库空文案与去①导入引导正确，且不影响收集工具台独立运行。
- job 五态进度可见、日志脱敏、失败可重试、运行中可取消。
