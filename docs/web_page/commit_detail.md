# 提交详情页（CommitDetail）

实现状态：部分　期次：一期

## 一句话

默认只读导入库中的单条提交、风险与 SZZ 标签，并提供「沿用库中结果 / 立即重新计算」两种明确选择；重新计算时页面并行编排单条 predict 与 explain，并设⑦解释、⑧定位及修复两个工具台入口（均归⑤子页），页面自身不实现任何算法。

## 入口与导航

- 功能⑤（模型预测）tab 内提交详情子视图（子签）；路由 `/commit/:hash` 保留并在该 tab 内展示，由 [风险列表](risk_list.md) 行点击或 [详情] 进入，携带列表所选 `model_name` 与返回筛选态。
- [打开解释工具台] 进入 `/explain?commit_hash=&model_name=`，完整技术选择、贡献排序与技术对比契约见 [explain.md](explain.md)。
- [打开定位工具台] 进入 `/localization?commit_hash=&model_name=`，完整源码、行级证据、建议与补丁预览契约见 [localization.md](localization.md)。
- 库空或缺少展示数据时可去 [数据管理](storage.md) 导入；顶部 [← 返回] 恢复风险列表状态。
- SZZ 来自自动标签，只读；本页没有人工标记入口。

## 控件与接口映射

| 控件 | 端点 | 说明 |
|---|---|---|
| 页面加载 / [沿用库中结果] | `GET /api/commits/{commit_hash}?model_name=` | 默认只读库中提交与预测；无预测行时 risk_score/predicted_at=null |
| 架构 / 模型 [▾] | `GET /api/models` | 两级级联；切换架构清空模型，不自动发起计算 |
| [立即重新计算] | 并行 `POST /api/predict` 与 `POST /api/explain`（均含 commit_hash/model_name，explain 另含 technique） | 单条预测同步返回并幂等落库；解释独立返回，不从 predict 响应取 explanation |
| predict / explain 独立状态 | 上述两请求；explain 异步时 `GET /api/jobs/{id}` | 单条 predict 不创建 job；explain 返回 job_id 时才轮询五态 |
| XAI 技术 [▾] | `GET /api/explain/techniques`；切换后 `POST /api/explain` | 初始值读 `default_xai`；兼容矩阵置灰不支持组合并给原因 |
| [对比解释] | 并行两次 `POST /api/explain`（不同 technique） | 至少两种技术并排，独立错误与版本元信息 |
| 风险等级 | `GET /api/config`（risk_high_threshold / risk_mid_threshold） | 展示分档不改 risk_score；decision_threshold 由预测服务使用 |
| SZZ / 14 项特征 / 定位摘要 | `GET /api/commits/{commit_hash}` | is_bug_inducing 三态；特征为 log 值；定位摘要含 level/notice/truncated |
| [打开解释工具台] | 路由 `/explain?commit_hash=&model_name=` | 在⑦解释子页运行完整技术选择与对比；详情页解释摘要不替代工具台 |
| [打开定位工具台] | 路由 `/localization?commit_hash=&model_name=` | 在⑧定位子页运行定位；详情页不新增定位计算按钮 |
| 修复建议摘要 | `GET /api/commits/{commit_hash}`（fix_references） | 仅展示真实参考与来源；完整四段式及补丁预览在定位工具台 |
| [去数据管理导入] | 路由 `/storage`；导入 `POST /api/storage/import` | 空库引导，不在详情页内嵌导入 |

## 交互流程

1. **默认沿用**：进入页面按路由 hash 和列表 model_name 调 `GET /api/commits/{commit_hash}`，渲染提交元信息、库中风险、SZZ、特征、摘要与定位信息，不调用 predict 或 explain。
2. 切换模型后，[沿用库中结果] 重新 GET 该模型的库中记录；无行显示「未预测」，不得显示 0。[立即重新计算] 始终作为独立、明确的另一操作保留。
3. **并行编排**：点击 [立即重新计算] 后同时发起 `POST /api/predict` 与 `POST /api/explain`，以 Promise.allSettled 等等价方式分别收束，独立展示 loading、结果与错误。predict 只负责风险概率、标签与版本，explain 只负责统一解释结构。
4. predict 成功后更新 risk_score、predicted_label、decision_threshold、model_version、feature_version 和 predicted_at，并按自然键幂等写库；explain 成功后按 |contribution| 排序展示贡献。任一失败不抹掉另一请求已成功结果。
5. 两结果都带模型与特征版本时先核对再合并视觉区块；版本不一致时分别标注，不宣称它们属于同一次计算。explain 若返回 job_id，则接入 jobs 五态进度，单条 predict 不显示伪 job。
6. XAI 下拉初始值来自 `GET /api/config` 的 default_xai，技术清单和兼容矩阵来自 techniques 接口。切换技术只调用 explain，不重新预测；不支持组合显示 reason_code 与说明。
7. [对比解释] 并行请求至少两种技术，以统一字段、排序与视觉样式并排展示；单列失败不影响另一列，summary 使用可用事实或确定性模板句。
8. SZZ 按 1/0/null 显示「引入缺陷 / 非缺陷 / 无 SZZ 标记」。风险高/中/低标签按配置阈值变化，概率本体不变。
9. 定位摘要只读详情接口已有结果，明确区分提交级风险与行级 suspicion。[打开定位工具台] 携带 hash/model，完整源码浏览、行级高亮、四段式建议和 patch_preview.diff 均在工具台完成。
10. [返回] 恢复风险列表两行筛选、页码与滚动位置；详情路由 hash 或已选模型变化时清理上一对象的解释和定位状态，避免串数据。

## 空态与错误

- 库空显示「尚未导入展示数据」与 [去数据管理导入]；提交不存在返回 40400 并提供 [返回列表]，不得伪装成未预测。
- 提交存在但所选模型无预测行时显示「未预测」，risk_score/predicted_at 留空，并保留 [立即重新计算] 与去导入两种路径。
- 无解释时保留解释区、summary 与具体 reason_code；不得用空数组造成无说明空白，也不得将解释失败改成风险 0。
- predict 失败而 explain 成功时保留解释及其版本，风险区显示预测错误；explain 失败而 predict 成功时显示新风险和解释错误，均可分别重试。
- 定位无源仓库、读取失败或结果截断时显示 notice/truncated，提交级风险仍可见；完整诊断跳转定位工具台。
- 40001 用于参数、模型或不支持组合；40100 禁用重新计算与解释写请求；40400 用于提交、模型或任务不存在；50000 给内部错误与重试。
- 任何后端图片或图 URL 均用带 X-API-Key 的 fetch 转 ObjectURL，并在替换、面板关闭或卸载时释放，不使用 `<img>` 直连鉴权地址。

## 验收

- 初次进入与 [沿用库中结果] 只调用只读详情，不触发 predict/explain；无预测行显示未预测而非 0，SZZ 三态正确。
- [立即重新计算] 同时发起 POST /api/predict 与 POST /api/explain，二者状态和错误独立；predict 响应不被当作解释来源。
- 单条预测幂等更新同一 (commit_hash, model_name) 记录；explain 异步时才使用 jobs 五态，页面不伪造 predict job。
- 两结果版本不一致时分别标注；任一请求失败不清空另一请求成功结果。
- XAI 技术切换和至少两技术对比生效，统一结构含 technique/model_version/feature_version；不支持组合给 reason_code，默认技术重启后保持。
- 贡献按 |contribution| 降序，summary 与失败原因可见；风险展示阈值来自配置且不改概率。
- 页面含明确 [打开解释工具台] 与 [打开定位工具台] 入口并携带 hash/model；⑦⑧可独立访问；定位摘要区分行级可疑度与提交级风险，无自动改码入口。
- 库空有去数据管理导入引导；返回列表恢复筛选；图片若存在均鉴权 fetch 并释放 ObjectURL。
