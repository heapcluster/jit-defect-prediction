# 功能点 00 登录与多用户

一句话：账号密码登录，每个用户只看得到、只操作得了自己的资产与配置。

## 1 范围

- 登录、登出、会话校验。
- 用户资产归属与可见性隔离。
- 页面进度的按用户持久化。

不负责：角色与权限分级、密码找回、账号注销、用户配额。

## 2 输入与输出

- 输入：用户名与密码；浏览器携带的会话凭据。
- 输出：会话 Cookie、当前用户信息、属于该用户的资产列表（数据集、清洗结果、模型、各阶段产物、配置、页面进度）。

## 3 流程

1. 未登录访问任意页面，跳转 `/login`。
2. 提交用户名与密码，校验通过后建立会话，进入数据存储页。
3. 所有接口按会话取当前用户，**不接受前端传 userId**；缺会话返回 401。
4. 查询、下载、删除、保存前校验归属；不属于当前用户的资源按不存在处理，返回 404，不泄露其存在性。
5. 登出销毁会话，回到登录页。
6. 已登录用户再次打开页面，直接恢复上次停留的页面与进度。

## 4 资产隔离口径

| 对象 | 归属 | 可见性 |
|---|---|---|
| 数据集（收集、清洗、导入清洗、测试集、预测结果） | 用户 | 仅本人 |
| 各阶段任务与产物文件 | 用户 | 仅本人 |
| 训练模型与模型文件 | 用户 | 仅本人 |
| 评估历史与图表 | 用户 | 仅本人；不属于数据存储页资产 |
| 用户配置 | 用户 | 仅本人 |
| 页面进度 | 用户 | 仅本人 |
| 算法库 | 系统 | 所有登录用户只读 |

- 不预置公共数据集与公共模型；新用户功能可用但资产为空，页面以空态引导去收集或训练。
- 用户之间完全不可见；没有共享、借用或转交。

## 5 会话与运行约束

- 口令按明文存储与比对，仅用于课程演示；接口不回传口令字段。
- 业务数据（数据集、模型、预测结果、评估历史）只在用户主动点击「保存到数据库」时写入；执行、预览、导出、刷新、重新登录都不自动入库。
- 页面进度按用户自动持久化，用于恢复操作现场，但不属于业务数据资产。
- 会话记录存 MySQL `user_session` 表，Cookie 只存原始令牌；有效期 7 天，登出删除记录后旧 Cookie 立即失效；会话失效后接口返回 401，页面回登录页。
- 账号由初始化命令创建（`python -m app.cli create-user`，密码交互输入，不写进命令历史）；登录页不提供自助注册。
- 同一用户同一时刻只允许 1 个运行中任务；不保证跨用户并发，也不做跨用户任务调度。

## 6 边界

- 不做角色区分，所有使用者权限相同。
- 不做跨用户共享、协作与转让。
- 不做密码找回、邮箱验证与账号注销。
- 不提供管理员后台。

## 7 验收

- 未登录访问任一页面被重定向到 `/login`，任一接口返回 401。
- 两个账号分别登录，各自的数据集、模型、产物、配置互不可见。
- 用 A 的会话请求 B 的资源，返回 404，且不提示该资源存在。
- 登出后原会话立即失效，返回登录页。
- 刷新或重新登录后，仍停留在上次页面并恢复该页进度。
