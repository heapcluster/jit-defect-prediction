# 功能点 02 缺陷数据收集

一句话：选一个公开仓库和一个分支，用专家特征或语义向量解析，输出经 SZZ 打标的缺陷数据集，可预览、导出，也可保存为个人数据集。

## 1 范围

- 仓库与分支选择：仅 GitHub、Gitee 的公开仓库。
- 解析方式二选一：Kamei 14 维专家特征；CodeBERT 768 维语义向量。
- 标准 SZZ 打标：issue → 修复提交 → 引入提交。
- 结果预览、导出 CSV / Excel、可选保存到数据库。

不负责：数据清洗、训练、预测、评估、解释；不导入外部文件。

## 2 输入与输出

- 输入：仓库 URL、分支名、解析方式。
- 输出：带 `bug` 标签的二维表产物（CSV / Excel 可导出）；保存时登记为当前用户的数据集。

## 3 流程

1. **校验地址**：仅接受 `github.com` / `gitee.com` 的公开仓库；平台由 host 判定。支持带或不带 `.git`、带或不带尾部斜杠，统一归一化。其他域名、私有仓库、地址不存在，表单就地报错，不启动任务。
2. **选分支**：通过平台接口获取分支列表；拉取失败给出可读原因，不进入下一步。
3. **选解析方式**：单选，默认专家特征。切换后说明各线产出的字段差异；已选仓库与分支时自动重新预检。
4. **预检与预估**：按当前解析方式统计提交数与 issue 数，给出一个预估耗时数值与档位（黄 / 红阈值取当前用户的配置）。用户可继续或取消。
5. **执行收集**：异步任务，展示进度与当前阶段（克隆、拉取 issue、SZZ 回溯、特征或向量计算）。样本为分支上全部非合并提交；只取平台标记为缺陷的 issue（GitHub `bug` 标签、Gitee `issue_type=bug`），其余 issue 不参与打标。
6. **预览结果**：分页二维表，只显示核心字段；显示样本总数与正负样本数。
7. **导出**：自定义文件名，可选 CSV 或 Excel；导出只是下载，不产生数据库记录。
8. **保存到数据库**：点击「保存到数据库」后登记为当前用户的数据集；未保存则结果只保留到重置或下一轮收集。

## 4 字段契约

### 4.1 专家线（Kamei 14 维）

元数据列固定为：`project`、`commit_id`、`commit_time`、`author_name`、`author_email`、`commit_message`。`project` 为仓库 `owner/repo`，`commit_id` 为提交哈希。

特征列顺序固定为：`ns`、`nd`、`nf`、`entropy`、`la`、`ld`、`lt`、`fix`、`ndev`、`age`、`nuc`、`exp`、`rexp`、`sexp`。

该顺序对应 Kamei 五维度分组：Diffusion（`ns`、`nd`、`nf`、`entropy`）、Size（`la`、`ld`、`lt`）、Purpose（`fix`）、History（`ndev`、`age`、`nuc`）、Experience（`exp`、`rexp`、`sexp`）。

标签列：`bug`，取值 `1` / `0`。

### 4.2 语义线（CodeBERT 768 维）

元数据列同上；向量列为 `f_0001` … `f_0768`，顺序与模型输出维度一致；标签列同为 `bug`。

### 4.3 兼容要求

- 14 项指标的名称与顺序以 Kamei 五维度标准为准（见 4.1）；开源实现的元数据列名并不统一，本项目固定为 4.1 的写法，导入外部数据集时按该表头校验。
- 导出列 `commit_id` 指 Git 提交哈希（库内 `commit_hash`），与内部主键 `commit.commit_id` 不是同一概念。
- 归属用户、仓库地址与分支、`label_method`、`fix_commit_hash`、`parent_hash` 等追溯信息只存数据库，不进入导出文件。
- 导出 CSV 使用 UTF-8 BOM，逗号分隔；Excel 首行为表头。

### 4.4 样本与标签口径（标准 SZZ）

- 样本集合为所选分支上的全部非合并提交，并排除分支根提交；不按关键词抽样。
- 只使用平台标记为缺陷的 issue：GitHub 取带 `bug` 标签的 issue，Gitee 取 `issue_type=bug`；其余 issue 不参与打标。
- issue → 修复提交的关联：优先使用平台 issue 时间线 / 关闭事件定位关联的 PR 与合并提交；同时解析 commit message 中的 `fix #<issue>` / `close #<issue>` / `resolve #<issue>` 作为兜底；两路结果按提交哈希去重。
- 同一 issue 关联多个修复提交时全部参与回溯。
- 标准 SZZ：由修复提交出发，用 `git blame` 回溯该修复提交删除或修改的行，命中的引入提交标 `bug=1`；其余样本标 `bug=0`。
- 同一提交被多个修复提交命中只记一次 `1`；`fix_commit_hash` 记录首个命中的修复提交。
- `label_method` 固定为 `szz`；标签、修复提交与父提交只存库，不导出。
- issue 数据不可用，或全部缺陷 issue 均未关联到修复提交时，任务失败并说明原因，不做关键词兜底；个别 issue 未关联时跳过，并在阶段统计中记录数量。

### 4.5 特征口径

专家线 14 项特征统一按「当前提交之前、同一分支内」的历史计算，不使用未来提交，避免标签泄漏：

| 特征 | 口径 |
|---|---|
| `ns` / `nd` / `nf` | 本次提交修改的子系统数 / 目录数 / 文件数 |
| `entropy` | 各文件修改行数占比的香农熵（log2） |
| `la` / `ld` / `lt` | 新增行数 / 删除行数 / 修改前文件总行数 |
| `fix` | 提交说明是否命中修复关键字 `fix` / `fixes` / `fixed` / `bug` / `bugs` / `repair` / `resolve` / `close`（大小写不敏感），命中为 1 |
| `ndev` | 修改文件的历史作者去重数，多文件取平均 |
| `age` | 修改文件最后一次变更距本次提交的天数，多文件取平均 |
| `nuc` | 修改文件的历史变更次数，多文件取平均 |
| `exp` | 作者在本仓库的历史提交数，全历史 |
| `rexp` | 作者在本仓库最近 90 天内的提交数 |
| `sexp` | 作者在本次涉及子系统内的历史提交数，按子系统全历史 |

- 缺失的历史值按 `0` 处理，不中断任务。
- 语义线使用 `commit message + diff` 文本，经本地 CodeBERT-base 编码，mean pooling 取句向量，`max_len=512`，输出 768 维；拼接时 message 在前、diff 在后，按 tokenizer 右截断到 512。

### 4.6 导出列与库表映射

| 导出列 | 库表字段 |
|---|---|
| `project` | `dataset.repo_name` |
| `commit_id` | `dataset_commit.commit_hash` |
| `commit_time` | `dataset_commit.committed_at` |
| `author_name` / `author_email` | `dataset_commit.author_name` / `author_email` |
| `commit_message` | `dataset_commit.message` |
| 14 项特征 | `dataset_commit.feature_json` |
| `bug` | `dataset_commit.is_bug_inducing` |

- 仓库地址、分支、`label_method`、`fix_commit_hash` 只存库，不参与导出。

## 5 结果保留

- 未保存的结果对当前用户可见，刷新、重新登录都不丢。
- 用户点击「重置」或发起新一轮收集时，上一轮未保存结果与产物一并丢弃。
- 已保存的数据集不受重置影响。

## 6 规模与中断

- 不设固定提交数上限；预检给出一个预估耗时数值，按阈值分档提醒。
- 预估公式：`预估秒数 = 30 + issue 数 × 0.05 + 提交数 × 单条耗时`，单条耗时专家线 0.3 秒、语义线 1.0 秒；页面展示时向上取整为分钟。
- 任务可取消；取消后不产生可保存的数据集。
- 仓库克隆按仓库共享缓存，不按用户重复克隆；必须克隆完整历史，禁止 shallow / partial clone，否则 `exp` / `rexp` / `sexp` 会失真。

## 7 边界

- 只支持公开仓库；私有仓库与自建 Git 服务不支持。
- 公开仓库无需登录，页面不要求填写 Token；平台接口限流时不启动任务，提示稍后重试。
- 不做关键词兜底打标；issue 数据不可用时任务直接失败并说明原因。
- 不预置公共数据集。
- 未重置时重新执行覆盖当前未保存结果；点击重置或开始新流程后再执行才产生新结果。只有再次点击「保存到数据库」时才覆盖已保存数据集：按 `collect|repo_name 小写|branch|line` 的 SHA-256 作为覆盖键，命中则更新原数据集，否则新建；仅重新执行不改动已保存数据。
- 收集只有点击「保存到数据库」才登记数据集；执行、预览、导出都不入库。
- 覆盖不改变已训练模型与已保存预测结果；覆盖后数据集内容更新，模型权重不变。
- 提交元数据写入全局共享表 `commit`，按 `(repo_name, commit_hash)` 幂等复用 `commit_id`；专家线特征写入 `commit_feature`；两者只增不删，删除数据集不清理。

## 8 验收

- 输入非 GitHub / Gitee 地址时表单报错，不产生任务。
- 切换解析方式后预估耗时按新模型线重新计算。
- 平台接口限流时表单给出稍后重试提示，不产生任务。
- 分支列表来自对应平台接口，选择后能进入下一步。
- 一次收集产出可预览、可导出的二维表，列名与顺序符合第 4 节契约。
- 导出文件包含正负样本，`bug` 列只有 0 与 1。
- 未点击保存时刷新页面结果仍在；点击重置后结果消失。
- 点击保存后，数据存储页出现该数据集，且其他用户不可见。
- 取消中的任务不再产出可保存的数据集。
