## 契约管什么、不管什么

**管**：跨线共用的名字 —— 数据表字段名、特征列名、接口字段名与错误码。

**不管**：各线内部的实现细节。后端用什么 ORM、模型线用什么归一化方法、前端用什么组件库，都不写在这里。**契约写多了就变成设计文档，维护不动。**

判断标准一句话：**这个名字，是不是有两条以上的线会写到代码里用到？** 是，进契约；不是，放各线自己的文档。

## 变更流程

1. 想改契约，先在 Issue 里提出，写清「改什么、为什么、影响谁」。
2. 通知受影响的两条线（契约表里「主要影响谁」那一栏）。
3. 双方同步改代码，同一个 PR 里一起合入 —— **不允许只有一方改**。
4. 更新被改契约的变更日志与版本号，并同步更新本文档的变更日志。

**悄悄改契约是事故**：改的那一方代码跑得通，另一方第二天编译不过，还得花时间排查是谁改的。

## 冻结的含义

「冻结」不等于不能改，而是：**改要走上面的流程，并且必须通知到人。**

冻结日期是「对外宣布日」，不是「最后可以反悔的一天」—— 结论一经写入，改动即需走变更流程。数据表字段与特征列名定在 9/18、接口格式定在 9/19（提前），是给协作者留的确认窗口。
