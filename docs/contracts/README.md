# 三条契约

> 版本 0.9（草案，未冻结）｜ 创建 2026-09-16 ｜ 负责人 蒋励 ｜ 审核 吕建江、刘帅华

## 这个目录是干什么的

三条线并行开工，靠的就是这三份契约。**契约不冻，两条线各自猜，最后一定返工。**

| 契约 | 文件 | 谁定 | 冻结时间 | 主要影响谁 |
|---|---|---|---|---|
| 数据表字段 | `data-fields.md` | 蒋励 + 吕建江 | 第 2 周末（9/18） | 模型线 ↔ 后端线 |
| 特征列名 | `feature-columns.md` | 蒋励 | 第 2 周末（9/18） | 模型线 ↔ 后端线 |
| 接口格式 | `api-format.md` | 吕建江 | 第 3 周中（9/23） | 后端线 ↔ 前端线 |

## 契约管什么、不管什么

**管**：跨线共用的名字 —— 数据表字段名、特征列名、接口字段名与错误码。

**不管**：各线内部的实现细节。后端用什么 ORM、模型线用什么归一化方法、前端用什么组件库，都不写在这里。**契约写多了就变成设计文档，维护不动。**

判断标准一句话：**这个名字，是不是有两条以上的线会写到代码里用到？** 是，进契约；不是，放各线自己的文档。

## 变更流程

1. 想改契约，先在 Issue 里提出，写清「改什么、为什么、影响谁」。
2. 通知受影响的两条线（契约表里「主要影响谁」那一栏）。
3. 双方同步改代码，同一个 PR 里一起合入 —— **不允许只有一方改**。
4. 更新本文档的变更日志与版本号。

**悄悄改契约是事故**：改的那一方代码跑得通，另一方第二天编译不过，还得花时间排查是谁改的。

## 冻结的含义

「冻结」不等于不能改，而是：**改要走上面的流程，并且必须通知到人。** 未冻结前的草案阶段，可以直接讨论着改。
