# 系统总览（Overview）

一句话：本系统以 commit 为单位，基于 Kamei 14 项提交级特征与语义特征预测代码变更引入缺陷的风险，输出**建议性**风险预警，不做 PR 强制门禁。

本文件是**唯一总纲**：范围、页面、数据流、数据与模型口径统一在此定义；其它文档只描述各自对象，冲突时以本文件为准并同步修订。

## 1. 系统定位与边界

- 输入：Git 仓库提交 / 公开数据集 / 已收集数据集。
- 输出：提交级风险分数与风险等级、解释、可疑代码定位建议、评估指标与图集。
- 性质：建议性预警，供开发者与评审参考；**不阻断合并**，不作为 PR 门禁。
- 数据来源：实时同步（`POST /api/sync`）或离线测试集初始化；离线数据不得冒充实时同步结果。

非目标（明确不做）：

- IDE / 插件 / CI-CD 等多种形态（设计图第 9 项不在 Web 系统范围）。
- PR 强制门禁与自动拦截。
- 数据存储页的文件导入（外部文件不提供页面导入入口）。
- 分布式训练、在线学习、多租户权限体系。

## 2. 页面范围

6 个顶级页面，2 个子页面，兼容路由重定向。

| # | 顶级页面 | 路由 | 职责 | 下游 |
|---|---|---|---|---|
| 1 | 数据存储 | `/storage` | 我的文件（数据集、产物、模型、算法库）与我的配置：查看、下载、删除、配置读写 | — |
| 2 | 数据收集 | `/collect` | 从 Git 仓库或公开数据集采集并标注提交 | 数据清洗 |
| 3 | 数据清洗 | `/clean` | 按处理项清洗数据，对比每步变化 | 模型训练 |
| 4 | 模型训练 | `/train` | 时间序切分，训练并对比一个或多个算法 | 模型预测 |
| 5 | 模型预测 | `/predict` | 选择模型与测试集，批量预测风险 | 预测评估 |
| 6 | 预测评估 | `/evaluate` | 按指标评估预测质量，查看模型性能 | — |

配置区位于数据存储页；`/settings` 重定向到 `/storage` 的配置区。

| 子页面 | 路由 | 归属 | 职责 |
|---|---|---|---|
| 提交详情 | `/predict/commit/:hash` | 模型预测 | 单次提交的风险、解释与定位结果 |
| 模型性能 | `/evaluate/models` | 预测评估 | 已登记模型的历史性能记录 |

兼容路由：`/collect/datasets` → `/storage?section=library`；`/model-performance` → `/evaluate/models`；`/commit/:hash` → `/predict/commit/:hash`。

## 4. 数据流

```text
Git 仓库 / 公开数据集
        │ 收集（collect）
        ▼
数据集 dataset ──► 清洗（clean）──► 清洗结果
        │                              │
        │                              ▼
        │                          训练（train）──► 模型 model / model_artifact
        │                              │
        │                              ▼
        └──────────► 预测（predict_batch）──► 预测结果 prediction
                                       │
                         ┌─────────────┼──────────────┐
                         ▼             ▼              ▼
                    评估（evaluate） 解释（explain）  定位（localize，同步）
                         │             │              │
                         └──── 产物落 temp/outputs/<job_id>/ ────┘
                                       │
                                       ▼
                         数据存储（产物库 / 数据链路）
```

- 工具之间**以文件交换**，不要求按顺序运行；数据库为空不影响任一模块独立运行。
- 主产物统一发布到 `temp/outputs/<job_id>/`（manifest + sha256），下载走 `GET /api/{module}/outputs/{job_id}/{name}`。
- 本页链路关系只来自 `job.chain_id` 与 `job.parent_job_ids`，不按文件名猜测上下游。

## 5. 数据库（12 张表）

建表唯一真源：`infra/schema.sql`；字段与索引以 `docs/database/` 为准。

| 表 | 职责 |
|---|---|
| `commit` | 提交元数据 |
| `commit_feature` | Kamei 14 项特征与标签 |
| `prediction` | 提交 × 模型的预测结果 |
| `model` | 模型登记 |
| `model_artifact` | 模型文件与训练任务关联 |
| `model_figure` | 评估图登记 |
| `dataset` | 数据集定义与统计 |
| `dataset_commit` | 数据集成员 |
| `job` | 六类异步任务的状态、进度与产出引用 |
| `algorithm` | 算法登记 |
| `user` | 用户 |
| `user_config` | 运行期配置（阈值等） |

任务口径：

- `job.kind` 六类：`collect` / `clean` / `train` / `predict_batch` / `evaluate` / `explain`。
- 五态流转：`queued` → `running` → `success` / `failed`；`running` → `cancelled`；`failed` → `queued`（重试）。
- 解释与定位是**同步产物**：`explain` 走任务，`localize` 不建 `job` 行，`job_id` 仅作产物批次标识，不可轮询。

## 6. 模型口径

- 两条模型线：`expert`（Kamei 14 维）与 `semantic`（768 维语义向量）。
- 每线注册 12 个算法，默认集合 8 个（`enabled`）：`lr`、`rf`、`xgb`、`lgbm`、`et`、`svm`、`mlp_deep`、`tabnet`。
- 实际交付 16 个模型（expert 8 + semantic 8），`data_model/evaluation/out/model_metrics.csv` 为 16 行指标。
- 在线加载：`MODEL_DIR` 下 `.pkl` 与 `feature_order.txt` 交付清单；清单外模型只作离线评估。
- 切分与特征：按 `committed_at` 升序前 70% 训练 / 后 30% 检验，禁止随机或分层打乱；expert 特征列序以 `feature_order.txt` 为唯一权威。

## 7. 数据存储页口径

- 单一页面承载五类数据与用户配置，分为我的文件、数据链路、算法库、我的配置四个区域。
- 我的文件：数据集、各阶段产物、已训练模型；统计 + 筛选 + 分页 + 查看抽屉（元数据、核心产物文件、数据集成员）。
- 数据链路：链路与节点展开，支持整链删除。
- 算法库：只读列出两条模型线的算法、默认标记与说明。
- 我的配置：五项用户配置，保存后立即生效，重开后自动恢复已保存值。
- 删除以链路为单位或删除单个数据集；链内资产被链路外引用时拒绝并列出引用方。
- `POST /api/storage/import` 仅为**内部自动登记接口**：清洗成功后由后端自动登记数据集，页面不暴露、不接受用户上传。

## 9. 文档口径

- `docs/` 只描述最新设计，不记录阶段划分与历史版本。
- 文档中不出现不存在或已不采用的能力（如页面文件导入、25 模型、四条模型线）。
- 设计以本文与对应对象契约为准；不一致时先改文档再改代码。

## 10. 变更规则

1. 改代码前先核对本文件与对应对象契约；功能变化先改文档并评审，再改代码。
2. 契约变更须显式记录（openspec change），并与对应 `docs/` 同步评审。
3. 数量类口径（表数、页面数、模型数、算法数）只在本文件与对应对象文档维护，其它文档引用不复写。
4. 不得提交数据集、权重、`.env` 或密钥；不得直接推送 `main`。
