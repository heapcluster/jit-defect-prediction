# commit_feature（复用 + 改动）

一行对应一次提交的 **Kamei 14 维**特征；是模型输入，也是明细表里"特征列"的唯一可读来源。

| 字段 | 含义 |
|---|---|
| commit_hash | 关联 `commit` |
| committed_at | 提交时间（冗余存，便于按时间筛选） |
| feature_version | 特征版本，`v1` = Kamei 14 维 |
| ns | 本次修改涉及的文件数 |
| nd | 本次修改涉及的目录数 |
| nf | 本次修改的文件总数 |
| entropy | 修改在文件间分布的熵（越小越集中） |
| la | 新增代码行数 |
| ld | 删除代码行数 |
| lt | 代码改动总量 = la + ld |
| fix | 是否为修复提交（0/1） |
| ndev | 曾修改过这些文件的开发者总数 |
| age | 文件自创建至今的存在时长 |
| nuc | 近期（如半年）修改过这些文件的开发者数 |
| exp | 作者历史经验（历史提交数） |
| rexp | 作者近期经验（近期提交数） |
| sexp | 作者在这些文件上的专属经验 |
| **is_test（新增）** | 是否检验集（时间序后 30%），`1` = 测试集，用于筛选"测试集" |

**说明**：
- 本表只承载 **Kamei 14 维**这一层可解释特征；语义 768 维、融合 782 维、e2e 文本**不落关系表**。
- 特征抽取是共享上游，四线提交都抽过这 14 维，故明细表对四线通用。
