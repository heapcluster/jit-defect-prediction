# commit_feature（复用表）

一行对应一次提交的 **Kamei 14 维**特征；是模型输入，也是明细表里"特征列"的唯一可读来源。

| 字段 | 含义 |
|---|---|
| commit_hash | 关联 `commit` |
| committed_at | 提交时间（冗余存，**测试集筛选与趋势分桶都靠它**） |
| feature_version | 特征版本，`v1` = Kamei 14 维 |
| ns | 本次修改涉及的文件数 |
| nd | 本次修改涉及的目录数 |
| nf | 本次修改的文件总数 |
| entropy | 修改在文件间分布的熵（越小越集中） |
| la | 新增代码行数 |
| ld | 删除代码行数 |
| lt | 代码改动总量 = la + ld |
| fix | 是否为修复提交（0/1） |
| ndev | 曾修改过这些文件的开发者总数 |
| age | 文件自创建至今的存在时长 |
| nuc | 近期（如半年）修改过这些文件的开发者数 |
| exp | 作者历史经验（历史提交数） |
| rexp | 作者近期经验（近期提交数） |
| sexp | 作者在这些文件上的专属经验 |
| **is_test（新增）** | 是否检验集（时间序后 30%），`1` = 测试集 |

**说明**：
- 本表只承载 **Kamei 14 维**这一层可解释特征；语义 768 维、融合 782 维、e2e 文本**不落关系表**。
- 特征抽取是共享上游，四线提交都抽过这 14 维，故明细表对四线通用；但**只有 expert 线的模型把这 14 维当输入**，其余线明细不展示特征列。
- **`is_test`（新增）** 标记检验集：`1` = 时间序后 30% 的测试集。前端测试集评估看板按 `is_test = 1` 筛选，不必再算时间边界。
- 切分仍按 `committed_at` 前 70% / 后 30%（红线：禁止随机切分）；`is_test` 只是切分结果落库的副本，不是另一种切分口径。
- `is_test` 与 14 维特征同源同版本（`feature_version`），由模型线 05 切分产物写入。
