# commit_feature（复用表）

一行对应一次提交的 **Kamei 14 维**特征；是模型输入，也是明细表里"特征列"的唯一可读来源。

| 字段 | 含义 |
|---|---|
| commit_hash | 关联 `commit` |
| committed_at | 提交时间（冗余存，**测试集筛选与趋势分桶都靠它**） |
| feature_version | 特征版本，`v1` = Kamei 14 维 |
| ns | 本次修改涉及的文件数 |
| nd | 本次修改涉及的目录数 |
| nf | 本次修改的文件总数 |
| entropy | 修改在文件间分布的熵（越小越集中） |
| la | 新增代码行数 |
| ld | 删除代码行数 |
| lt | 代码改动总量 = la + ld |
| fix | 是否为修复提交（0/1） |
| ndev | 曾修改过这些文件的开发者总数 |
| age | 文件自创建至今的存在时长 |
| nuc | 近期（如半年）修改过这些文件的开发者数 |
| exp | 作者历史经验（历史提交数） |
| rexp | 作者近期经验（近期提交数） |
| sexp | 作者在这些文件上的专属经验 |

**说明**：
- 本表只承载 **Kamei 14 维**这一层可解释特征；语义 768 维、融合 782 维、e2e 文本**不落关系表**。
- 特征抽取是共享上游，四线提交都抽过这 14 维，故明细表对四线通用；但**只有 expert 线的模型把这 14 维当输入**，其余线明细不展示特征列。
- **本表不加 `is_test` 之类的切分列**：模型线 `04_build_dataset.py` 明确把 `is_test / split / is_train` 列为禁止字段。测试集由时间边界界定，见下。

## 测试集怎么定（不落列）
- 测试集 = `committed_at >= runtime_setting.test_split_at` 的提交；边界是模型线交付时给出的时间戳，后端**只读不算**。
- 切分天然满足红线「按提交时间前 70% / 后 30%，禁止随机切分」，无需每行打标。
- `test_split_at` 缺失时，测试集相关接口 MUST 直接报参数缺失，MUST NOT 自行按 70% 估算——估算出的边界与训练用的边界差一条，指标就是假的。
