- **契约**：契约二 14 项特征列名与顺序、契约三错误码与性能靶子，改一处必须同步 `feature_order.txt` 与后端实现
- **门禁**：`check_spec_references.py links|deltas` 可跑、CI 必跑、误报率可控（门禁拦的是真问题，不是格式洁癖）
- **规格**：`openspec validate --specs --strict` 全绿；归档 change 的证据路径点得到实物

## 4. 原则（做取舍时按这个顺序）

1. **契约是硬边界，不是建议。** 字段/错误码/靶子一旦定下，改就是走 change，不能靠"这次先这样"绕过。
2. **规则要可执行。** 立规矩必须同时给检查手段（脚本/CI/模板），只写"请大家注意"的规矩等于没立。
3. **归档不掩缺口。** 带已知缺口归档可以，但状态行必须写明「哪些未执行、谁负责、什么条件回填」，且不计入完成数。
4. **门禁宁可少而准。** 一条稳定的检查胜过十条会误报的；误报会让人绕过门禁，等于毁掉门禁。
5. **文档只有一个权威位置。** 同一口径在别处只允许引用，出现第二份正文就删或降级为指针。
