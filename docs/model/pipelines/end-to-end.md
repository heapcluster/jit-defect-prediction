# 端到端 · Pipeline 说明

> 版本 1.1 ｜ 更新 2026-10-14 ｜ 主笔 蒋励 ｜ 审核 苏哲勋
> **一句话**：**不冻结 backbone**，直接在 commit 变更文本上 fine-tune CodeBERT / GraphCodeBERT，让特征提取与分类**联合优化**，输入只有变更文本、输出缺陷概率 —— 与另三条「两段式」pipeline 形态不同的一组对照。
> 状态：**⬜ 计划态 · 尚未立项** —— 脚本（`17_*`）不存在，本文只是口径约定；立项须走 openspec change（proposal → specs → design → tasks），不得先跑代码再补规格。
> 本文自包含：照本文即可立项与实现，不需要再翻别的文档。

## 1. 用途

1. **补齐第四类设置**：四类对比（仅专家 / 仅语义 / 融合 / 端到端）中的「一段式」组，用于回答「联合优化能否超过冻结提特征 + 经典分类器」。
2. **对齐课程说明的形态**：课程称「现在主流方法是利用预训练模型直接从源代码提取深层语义特征，然后构建预测模型」—— 端到端微调（DeepJIT / CC2Vec / LApredict / SimCom / JITLP 一类工作）是该说法的完整实现，本组作为形态对照。
3. **给前三条线一个上界参照**：若端到端明显不如两段式，本身就是一个可报告的结论（算力与数据量约束下的真实差异）。

## 2. 适用场景

| 场景 | 走本线？ |
|---|---|
| Sprint 有余量、要补形态对照（完整四类对比） | ✅ 本线 |
| 主线未跑通（Camel 数据链路 / 语义向量未落地） | ❌ 本线是探索项，不占关键路径 |
| 需要上线交付的模型 | ❌ 只出评估结论；切换交付模型须另开提案 |
| 算力仅为 CPU | ⚠️ 可做小规模验证，但结论必须标注 CPU/抽样，**不得谎报全量 GPU 结果** |

## 3. 核心处理步骤

| 步 | 动作 | 脚本（计划命令） | 输出 | 关键校验 |
|---|---|---|---|---|
| ⑩（复用） | 变更文本构造 | 复用 `10_semantic_text.py` 的产物 `pipelines/semantic/data/semantic_text_v2.csv` | 变更文本 | 不另造一份文本构造，避免两处口径漂移 |
| ⑰-1 | 分词与数据集装配 | `17_train_end_to_end.py --prepare` | `pipelines/e2e/data/e2e_dataset_v2.csv`（`commit_hash` + 文本 + 标签 + 切分归属） | 切分下标与 `data_model/data/split_szz_*.csv` 逐条一致 |
| ⑰-2 | fine-tune（不冻结 backbone） | `17_train_end_to_end.py --model codebert --line e2e` | `pipelines/e2e/models/codebert_e2e_v1.pkl` + 训练日志 | 早停 + 小学习率；测试集不参与调参 |
| ⑰-3 | 评估与形态标注 | `17_eval_end_to_end.py` | `pipelines/e2e/reports/end_to_end.md` | 两类指标齐全；标注设备/样本量/是否全量/截断统计 |

**备选对标**：`1D-CNN`（吃 diff token 序列、不吃特征向量）归入本类作对标，用于说明「非预训练的端到端」与「预训练微调的端到端」差异。

**前置依赖**：Apache Camel 数据链路（提交、标签、切分下标）与变更文本构造（⑩）先跑通。本线不依赖语义 768 维向量（那属于两段式），但**复用同一份变更文本与同一套标签、同一切分下标**，保证四类可比。

## 4. 输入

| 输入 | 来源 | 形态 |
|---|---|---|
| 变更文本 | 仅语义线 ⑩ 的产物 `pipelines/semantic/data/semantic_text_v2.csv` | 一行一次提交，文本为「路径 + 变更类型 + 增删行 + 提交信息首行」 |
| 缺陷标签 | 仅专家线 `data_model/data/commit_labels_szz.csv` | `is_bug_inducing` |
| 切分下标 | 仅专家线 `data_model/data/split_szz_{train,test}.csv` | **只读复用**，禁随机切分 |
| 预训练权重 | HuggingFace `codebert-base` / `graphcodebert-base` | 已离线预下载（`hidden=768`） |
| （不吃特征向量） | — | 本线**不使用** Kamei 14，也不使用冻结的 768 维向量 |

## 5. 输出

**目录约定（2026-10-14 起，四线隔离）**：本线产物**全部落在 `data_model/pipelines/e2e/`** 下
（`data/` 数据集、`models/` 模型文件、`reports/` 本线报告）。

| 产物 | 路径 | 入库？ | 去向 |
|---|---|---|---|
| 端到端数据集 | `pipelines/e2e/data/e2e_dataset_v2.csv` | ❌ | 本线训练用 |
| 模型文件 | `pipelines/e2e/models/codebert_e2e_v1.pkl` | ❌ | 仅评估，**不进交付链** |
| 评估报告 | `pipelines/e2e/reports/end_to_end.md` | ✅ | **第四类结论，单独一份** |
| 对比结论 | 作为第四类**另附**于 `data_model/reports/three_way_comparison.md`（历史沿用名，跨线共享） | ✅ | **不并进前三类同一张表** |

**命名纪律**：本线一切产物带 `e2e` 线名，**不许落到仅专家线的旧名上**（四线同名即互相覆盖）。

## 6. 关键配置项及其作用

| 项 | 计划取值 | 作用 |
|---|---|---|
| backbone | `codebert-base`（主）/ `graphcodebert-base`（对照） | 代码专用预训练模型；与仅语义线同一权重来源，保证「冻结 vs 不冻结」是唯一变量 |
| 冻结策略 | **全参数微调，不冻结任何层** | 本线与仅语义线的本质区别；冻结即退化为两段式 |
| 学习率 | 小学习率（如 2e-5 量级） | 防止预训练权重被小样本数据迅速破坏 |
| 训练轮数 / 早停 | 设 `max_epochs` + 早停（patience），验证子集**只从训练集内部**切 | 检验集始终更晚，不参与早停决策（禁时序泄漏） |
| 批大小 / 序列上限 | 按显存或内存设定；单文件文本超限**按行截断并记录统计** | ~2.3 万提交 × ~1.1 亿参数在 CPU 上偏紧，批大小与截断直接决定可行性与信息损失 |
| 分类头 | backbone 输出 + 线性分类头（输出缺陷概率） | 与另三线的 `predict_proba` 口径对齐 |
| 设备 / 样本量 | CPU / GPU、全量 / 抽样比例 | 报告必须如实标注，**不声称全量 GPU 结果** |
| 随机种子 | 固定并记录 | 保证可复现；未固定须在报告说明 |

**算力现实（必须写在立项理由里）**：Camel 约 2.3 万提交、backbone 约 1.1 亿参数，**全量微调偏紧**。可行路径：先小规模（如 100 条）基准计时 → 时间序分层抽样微调 + 如实登记；不得为凑全量而静默砍配置或谎报规模。

## 7. 与其他 pipeline 的边界与协作关系

| 对象 | 关系 | 具体内容 |
|---|---|---|
| 仅专家 `expert-only.md` | **上游依赖** | 取仓库副本、缺陷标签与切分下标；本线**不吃**它的 14 维特征表 |
| 仅语义 `semantic-only.md` | **并列对照 + 文本复用** | 两者同一 backbone；区别仅在**冻结与否**。本线复用其变更文本产物，但把「冻结提特征 + 经典分类器」换成「联合优化」 |
| 融合 `fused.md` | **并列对照** | 融合是 782 维两段式，本线是文本一段式；结论分开报，不并进同一张表 |
| 后端线 | **无直接交付** | 只出评估结论；若端到端更优，切换交付模型须另开「模型切换」提案，走契约三变更流程，**不得静默切换** |

**形态边界（必须对答辩讲清）**：本组当前形态是「预训练提特征 → 经典分类器」的**特征式混合**，端到端微调是**探索项**。完成端到端后也不得对外暗示「复现 SOTA」—— 单仓库、单切分、样本量有限的结论只能组内自比。

## 8. 红线

1. **未立项不写码**：脚本落地前必须已有 openspec change，并同步更新模型线方案中端到端的形态说明（D10 口径）。
2. **不得谎报全量 / GPU 结果**：无 GPU 标 CPU，抽样标抽样比例与分层方式。
3. **不得暗示复现 SOTA**；不得把端到端结论与前三类混在一张表里宣称「同一模型不同设置」。
4. **不得静默切换交付模型**；切换走提案 + 契约三变更流程。
5. **切分必须时间序**（与另三线同一切分下标），禁随机；测试集不参与早停与调参。
6. 未收敛、被截断、算力降级**全部如实登记**，不许静默当已收敛。
