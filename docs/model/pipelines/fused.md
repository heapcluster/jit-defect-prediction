# 融合 · Pipeline 说明

> 版本 1.1 ｜ 更新 2026-10-14 ｜ 主笔 蒋励 ｜ 审核 苏哲勋
> **一句话**：把仅专家线的 Kamei 14 维与仅语义线的 CodeBERT 768 维**左连接**成 782 维样本集，喂给与另两条线完全相同的 8 个分类器，检验「专家度量 + 预训练语义」混合是否优于任何单边。
> 状态：**⬜ 计划态** —— 脚本（`13` / `14`）尚未落地，本文是开工口径，不是已完成工作。
> 本文自包含：照本文即可实现与复查，不需要再翻别的文档。

## 1. 用途

1. **产出四类对比中的「融合」组**：782 维 = 14（专家）+ 768（语义），是三线对比（仅专家 / 仅语义 / 融合）里的第三组，也是离「主流混合形态」最近的一组。
2. **复用两条上游线的全部投入**：不新造特征、不新造模型类，只做一次连接 + 一次训练评估，是性价比最高的一组实验。
3. **检验一个具体假设**：专家特征的强归纳偏置与语义特征的表达力是否互补。**不预设谁赢** —— 维度高 ≠ 效果好，语义需更多标注数据，结论以实测为准。

## 2. 适用场景

| 场景 | 走本线？ |
|---|---|
| 检验「专家 + 语义」混合是否优于单边 | ✅ 本线 |
| 仅专家线或仅语义线尚未跑通 | ❌ 本线是两者的下游，上游不齐则无法开始 |
| 需要上线交付的模型 | ❌ 融合样本集 `feature_version=v2`，**不入库、不进交付链** |
| 只想单独评估语义特征 | ❌ 走 `semantic-only.md` |
| 端到端联合优化 | ❌ 走 `end-to-end.md`（那条不冻结 backbone，也不吃特征向量） |

## 3. 核心处理步骤

| 步 | 动作 | 脚本（计划命令） | 输出 | 关键校验 |
|---|---|---|---|---|
| ⑬ | 左连接生成样本集（一次连接、两线复用） | `13_build_fused.py --line fused` | `pipelines/fused/data/dataset_fused_v2.csv` | 连接键 `commit_hash`；**同切分下标断言**；缺失向量显式标注不填 0 |
| ⑭ | 训练 8 模型 + 两类指标 + 三线对比 | `14_compare_settings.py --line fused` | 本线：`pipelines/fused/reports/model_metrics_fused.md`、`model_matrix_fused.md`；跨线：`data_model/reports/three_way_comparison.md` | 8 模型齐全；与专家/语义两线同一切分、同一套指标 |

**前置依赖**：仅专家线的 `data/dataset_{szz,szz_lite}.csv` 与仅语义线的 `data/semantic_codebert_v2.csv` 都必须先在 Apache Camel 上跑通；任缺其一，本线不得开始。

**列序铁规**：融合表**前 14 列与契约二逐字一致**（列名 + 顺序），语义 768 列**追加在后**；契约二既有 14 项一字不动，融合只做追加。

**切分与指标口径**：与仅专家 / 仅语义两线完全一致 —— 同一份切分下标（`data/split_szz_*.csv`，只读不重切）、同一 8 模型池（复用 `model_registry`，不新造模型类）、同一套两类指标（Effort-unaware + effort-aware）、同一显著性检验方法。**任何一组换口径即视为不可比。**

## 4. 输入

| 输入 | 来源 | 形态 |
|---|---|---|
| 专家特征样本集（左表） | 仅专家线 `data_model/data/dataset_{szz,szz_lite}.csv` | 14 项专家特征 + `commit_hash` + 标签 |
| 语义向量（右表） | 仅语义线 `pipelines/semantic/data/semantic_codebert_v2.csv` | `commit_hash` + `sem_0 … sem_767` |
| 切分下标 | 仅专家线 `data_model/data/split_szz_{train,test}.csv` | **只读复用**，本线不重新切分 |
| （无其他外部输入） | — | 本线不直接读仓库、不重新打标、不提特征 |

## 5. 输出

**目录约定（2026-10-14 起，四线隔离）**：本线产物**全部落在 `data_model/pipelines/fused/`** 下
（`data/` 样本集、`models/` 模型文件、`reports/` 本线报告）；跨线汇总报告（三线对比）由共享脚本
产出到 `data_model/reports/`。

| 产物 | 路径 | 入库？ | 去向 |
|---|---|---|---|
| 融合样本集 | `pipelines/fused/data/dataset_fused_v2.csv`（782 维） | ❌（v2 不入库） | 本线训练用 |
| 模型文件 | `pipelines/fused/models/{model}_fused_v1.pkl` | ❌ | 仅评估，**不进交付链** |
| 指标报告 | `pipelines/fused/reports/model_metrics_fused.md` | ✅ | 证据 |
| 覆盖矩阵 | `pipelines/fused/reports/model_matrix_fused.md` | ✅ | 证据 |
| 消融 | `pipelines/fused/reports/feature_ablation_fused.md` | ✅ | 证据 |
| 三线对比汇总 | `data_model/reports/three_way_comparison.md`（历史沿用名，跨线共享） | ✅ | 与专家/语义共一份 |

**命名纪律**：本线一切报告名带 `_fused` 后缀，**不许落到仅专家线的旧名上**（`reports/model_metrics.md` 等名字归专家线，四线同名即互相覆盖）。

## 6. 关键配置项及其作用

| 项 | 取值 / 计划参数 | 作用 |
|---|---|---|
| 线名参数 | `--line fused` | 决定数据文件名与报告名同时带 `fused`；**只改数据不改报告 = 缺陷** |
| 连接方式 | **左连接**，以专家样本集为主表 | 保证样本量与专家线逐条可比；语义缺失的行不丢 |
| 连接键 | `commit_hash` | 与专家线、语义线三方对齐的唯一键 |
| 列序 | 前 14 项 = 契约二原文；`sem_0…sem_767` 追加在后 | 契约二第三节的副本 `feature_order.txt` 以前 14 项为准，追加不得插队 |
| `feature_version` | `v2` | 与 v1（纯专家）区分；升版本不覆盖旧版 |
| 缺失语义向量 | **显式标注，不填 0** | 填 0 会被模型当成「语义全零」的真实信号，静默污染对比结论 |
| 切分 | 复用 `data/split_szz_*.csv`，`13` 内置下标一致性断言 | 下标不一致 = 打回重切（Gate G3） |
| 模型池 | 与仅专家线相同的 8 个模型 | 三线可比的前提；不新造模型类 |
| 模型内部预处理 | 允许（如 `svm` 的标准化） | 契约只定义**落库数值口径**，训练时的标准化/筛选是模型线自由；但存盘值必须符合契约 |
| 维度 | 782 | 仍属高维小样本区间，过拟合风险与收敛情况须如实登记 |

## 7. 与其他 pipeline 的边界与协作关系

| 对象 | 关系 | 具体内容 |
|---|---|---|
| 仅专家 `expert-only.md` | **上游依赖（左表）** | 取样本集与切分下标；融合表前 14 列必须与其逐字一致 |
| 仅语义 `semantic-only.md` | **上游依赖（右表）** | 取 768 维向量；`13_build_fused.py` 由本线与语义线共用（`--line semantic` 出语义样本集、`--line fused` 出融合样本集），避免两处实现漂移 |
| 端到端 `end-to-end.md` | **并列对照** | 本线是两段式（提特征 → 经典分类器，782 维输入），端到端是一段式（不冻结 backbone，吃变更文本）；结论分开报 |
| 后端线 | **无直接交付** | v2 不入库、不进交付链；若融合更优，切换交付模型须另开提案走契约三变更流程，**不得静默切换** |

**边界要点**：本线不做特征工程（不提特征、不打标、不切分），只做连接与训练评估；三线共用的口径（切分 / 模型 / 指标 / 显著性）以仅专家线与模型线方案为唯一权威，本线不另立一套。

## 8. 红线

1. **同切分下标**：三套样本集必须落在同一份切分下标上；本线重新切分 = 打回重切。
2. **缺失向量显式标注、不填 0**。
3. **前 14 项键名与顺序一字不动**（契约二）；融合只追加语义列，不改专家列口径。
4. **不入库、不进交付链**；不得静默切换交付模型。
5. 只报一类指标 = 一票否决；`P_norm` 须标注「本组自造变体，非文献 `Popt`」。
6. 高维过拟合与未收敛情况**如实登记**，不许静默当已收敛；换库后旧仓库实测数字一律不引用。
