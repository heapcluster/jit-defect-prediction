# rf_v1 在线推理慢在哪：实测根因（D-14 裁定依据）

- 日期：2026-10-24
- 对象：`data_model/pipelines/expert/models/rf_v1.pkl`（交付包内权重，md5 与 `models/manifest.txt` 一致）
- 目的：D-14（`rf_v1` 的 `POST /api/predict` p95=713.8ms 超契约三 §2 的 500ms 靶子）三选一裁定前，先定位慢在推理还是解释，避免把可优化项误判成契约冲突。

## 1. 模型体量

| 项 | 值 |
|---|---|
| pkl 大小 | **279.4 MB** |
| joblib 反序列化 | 3.84 s（进程启动一次） |
| `n_estimators` | 300 |
| `max_depth` | `None`（不限制） |
| 树深（平均 / 最大） | 34.4 / 47 |
| 节点总数 | **3,660,998** |

形态是裸 `RandomForestClassifier`（`steps=none`，不是 Pipeline），`n_jobs=-1`。

## 2. 单次耗时拆分（同进程、14 维单条输入、RTX 无关）

| 环节 | 耗时 | 说明 |
|---|---|---|
| `predict_proba` | **53.5 / 60.6 / 86.0 ms**（三次） | 300 棵树遍历，占端到端不到 10% |
| `shap.TreeExplainer` 构造 | 359.8 ms | **已缓存**（`model_registry.get_explainer` 惰性构造，只在首次付） |
| `shap_values`（默认） | **781.8 ms** | 主因 |
| `shap_values(check_additivity=False)` | 799.2 ms | 关掉加性校验无改善，说明开销在路径遍历本身 |

## 3. 结论

`rf_v1` 端到端 p95=713.8ms 的主体是 **SHAP TreeExplainer 在 366 万节点、300 棵深 34 的树上的单次计算**，不是 `predict_proba`，也不是 explainer 构造（已缓存）。契约三要求 `POST /api/predict` 返回非空 `explanation`，所以这条成本无法通过"少算 SHAP"绕过。

即：慢的根因是**模型规模**（不受限深度导致 366 万节点），属于可收敛项，不是 RandomForest 固有不可解，也不是契约枚举本身有问题。

## 4. 复现方式

```bash
python - <<'PY'
import time, joblib, numpy as np
p = "data_model/pipelines/expert/models/rf_v1.pkl"
m = joblib.load(p)
inner = m.steps[-1][1] if hasattr(m, "steps") else m
print("trees", len(inner.estimators_), "nodes", sum(t.tree_.node_count for t in inner.estimators_))
X = np.random.RandomState(0).rand(1, 14)
t0 = time.perf_counter(); m.predict_proba(X); print("predict_ms", (time.perf_counter()-t0)*1000)
import shap
ex = shap.TreeExplainer(inner)
Xs = m.steps[0][1].transform(X) if hasattr(m, "steps") else X
t0 = time.perf_counter(); ex.shap_values(Xs); print("shap_ms", (time.perf_counter()-t0)*1000)
PY
```

环境：Windows 11 / Python 3.12.15 / scikit-learn 与 shap 按 `data_model/environment.yml`。绝对值受机器负载影响，但 `predict_proba : shap_values ≈ 1 : 10` 的比例在两台机器上一致（另一份旁证见 `backend/scripts/evidence/perf-2026-10-24.md` 的 rf 行 p50=653.0 / p95=713.8 / p99=751.0）。
