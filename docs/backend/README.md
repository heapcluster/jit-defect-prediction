## 2. 🚀 后续工作开展方式（每次接到任务的标准动作 · 必须走 OpenSpec）

1. **认领**：飞书看板把任务置「进行中」，或周会分配。
2. **判断要不要动规格**：改接口行为 / 加字段 / 改错误码 / 动库表 → **必须提 OpenSpec change**（propose），不要直接改码。
3. **提 change**：`openspec/changes/` 下 `propose` → 写 `design.md`+`tasks.md` → `apply`；后端常用 change：`predict-api`、`query-api`、`db-schema`、`nfr-evidence-scripts`。
4. **实现 + 同步规格**：改 `backend/` 代码时，**同步**对应 spec/契约文件；字段名与 `api-spec.md` 逐字一致（字段一致铁律）。
5. **自测**：本地起 `:8000`，跑 `tests/`；覆盖正常 / 边界 / 异常（如 40001、40400、50000 三态）。
6. **提 PR**：PR 描述写 change id / Issue 号；请求**非作者成员**（苏哲勋）审阅。
7. **合入 + 归档**：审阅修改后合入 main；change 任务全勾且有过测试/运行证据 → `openspec archive`。
8. **回写**：看板置「已完成」+ 周报记一行证据链接。

> ⚠️ 课程硬要求：**只勾 `tasks.md` ≠ 功能合格**，必须有运行/测试证据。**改需求只改码不改规格 = 缺陷。**

## 3. 🚫 你的红线

- **不碰**：特征定义（改走契约变更）、页面、模型训练代码（属 `model/`）。
- **字段零自创**：接口返回字段名必须与 `api-spec.md` / `feature-columns.md` 一致。
- **错误响应不回显**：路径/SQL/堆栈绝不进响应体（安全铁律，L4 要扩边界用例）。
- **非作者审阅**：你的 PR 由苏哲勋（或蒋励）审，不能自己合自己的。
