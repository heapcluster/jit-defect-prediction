## 2 · 验收范围与标准

四类验收共 20 条，按 §5.1 逐条只判「通过 / 不通过」。通过标准：核心项 100%、非核心 ≥90%、准确性达人工确认阈值、无致命 / 严重遗留、一般遗留 ≤3 且有计划、文档齐备、逐条取证齐备。

准确性口径说明：本轮把 `data_model/evaluation/out/model_metrics.csv` 汇总成 [`model-accuracy-evidence.md`](model-accuracy-evidence.md)，25 个模型 accuracy 在 0.834~0.864 之间（都高于课程示例的 80%），但 **recall 只有 0.26 左右**——也就是约七成真正引入缺陷的提交会被判成低风险。用哪个指标当验收口径、阈值定多少，必须由人定，我不代替拍板。

## 5 · 验收结论

**验收不通过。**

理由（任一即足以不通过）：

1. 20 条用例通过率 55%、核心 66.7%，未达「核心 100%、非核心 ≥90%」；
2. 4 条严重缺陷未修复——其中 BUG-01 会让新环境起不来、BUG-02 打掉模型性能页的核心内容、#226 让新提交的非 expert 线不可预测；
3. 准确性验收的阈值与口径未由人工确认，且 recall ≈0.26 与「预测缺陷」的业务目标存在明显张力；
4. A-01~A-20 逐条编号取证不齐，未组织真人现场演示；
5. 覆盖率 PDF、AI 用例人工审核记录等交付物仍缺。

结论按课程要求明确写成「验收不通过」，不使用「基本没问题」这类模糊表述。
