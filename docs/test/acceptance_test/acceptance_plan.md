> **撰写说明**：本文档由 AI 依据需求规格与仓库实测证据代为撰写（项目方 2026-11-13 授权，明确无需人工逐份撰写与签字），**未经人工签署**。按 [`../../common/test-assessment-guide.md`](../../common/test-assessment-guide.md) AI-R5，验收方案应由人工撰写，本文件存在评分风险，后续由人工复核修订。文中阈值凡涉及「人工确认」的，均如实标注待确认，不冒充已确认。来源：`[AI生成]`。

## 1 · 验收范围

验收对象为 JIT 缺陷预测 Web 系统的最终交付版本，从前端四页面到后端预测服务的完整系统，站在最终用户角度确认系统是否满足业务需求、可否交付。区别于系统测试的「找 Bug」导向，本轮核心是「确认可交付」。

| 验收类别 | 验收项 | 依据 |
|---|---|---|
| 功能验收 | 同步 → 预测 → 风险列表 / 详情 / 趋势 / 模型性能看板的业务闭环；需求覆盖率；预测准确性 | [`../../overview.md`](../overview.md)、[`../../common/project-requirements.md`](../../common/project-requirements.md) |
| 数据验收 | 数据完整性、前后端展示一致性、跨模块链路 | `overview.md` §端到端数据流、`docs/api/` |
| 界面验收 | 页面展示完整性、交互流程合理性、错误反馈友好性 | `docs/web_page/` |
| 文档验收 | 部署 / 启动说明、API 文档、四类测试交付物、缺陷遗留说明 | [`../../common/test-assessment-guide.md`](../../common/test-assessment-guide.md) §8 |

课程原文的「用户登录 / 数据上传 / 导出报告」是通用示例，本项目无这些功能，不纳入验收范围。

## 2 · 验收标准（量化）

| 类别 | 判定标准 | 阈值来源与状态 |
|---|---|---|
| 核心功能 | 核心（★）验收项通过率 **100%** | 课程 §5.1 |
| 非核心功能 | 通过率 **≥90%** | 课程 §5.1 |
| 缺陷预测准确性 | 标准测试集准确率 **≥80%**、召回率有实测记录 | **暂按课程 §5.1 示例值 ≥80% 拟定，由 AI 写入，须验收方人工确认后生效**；当前无标准测试集实测报告 |
| 数据一致性 | 同一提交、同一模型在预测响应 / 详情 / 列表三处风险值完全一致，一致率 **100%** | 项目数据契约，`T-IN-35` 已提供口径 |
| 界面完整性 | 四页面元素无缺失 / 错位 / 乱码，覆盖率 **100%**；浏览器至少 Chrome / Edge / Firefox **3** 个 | 课程 §5.1 / §4.1 |
| 缺陷遗留 | 致命、严重缺陷 **0** 个；一般缺陷 **≤3** 个且各有修复计划与影响评估 | 课程 §5.1 |
| 文档齐备 | 用户手册、部署说明、API 文档、四类测试交付物与 `prompts/` 归档 **100%** 齐备 | 课程 §5.1 / §8 |
| 用例结论 | 每条只填「通过」或「不通过」，不允许「部分通过 / 待定」 | 课程 §5.1 |
| 取证 | 每条用例有对应截图 / 录屏，编号可追溯 | 课程 §5.3 |

> **AI-R5 边界**：预测准确性阈值涉及是否接受系统交付的判断，上表 ≥80% 仅为课程示例值的整理，**未经人工确认，不得作为已生效的验收判据**；`acceptance_cases.md` 中 A-03 因此判不通过。

## 6 · 通过标准与判定口径

- 同时满足 §2 全部量化条件，且 20 条用例结论与取证齐备，方可给出「验收通过」。
- 任一核心项不通过、存在致命 / 严重缺陷遗留、或缺少逐条执行取证，结论为「验收不通过」，并列出不通过项与整改要求。
- 静态对照结果可作为**预验收**输入，但不替代现场演示与截图；课程红线：验收测试未实际执行、仅提交文档，该部分计 0 分。
- 结论只写「验收通过」或「验收不通过」，禁止「基本没问题」等模糊表述。
