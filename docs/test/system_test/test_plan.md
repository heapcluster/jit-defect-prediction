## 1 · 测试目的与依据

以黑盒方式验证 JIT 缺陷预测 Web 系统从前端页面、后端服务到模型推理的端到端全链路，确认用户可见功能可用、异常可收敛、非功能质量可度量，并为验收测试提供缺陷与证据输入。

依据：[`../../common/test-assessment-guide.md`](../../common/test-assessment-guide.md) §4；现行范围以 [`../../overview.md`](../overview.md)、`docs/web_page/`、`docs/api/` 为准。课程原文的「用户登录 / 数据上传 / 报告导出」是通用示例，本项目无这些功能，不纳入范围。

| 类别 | 范围 |

## 3 · 测试策略

1. **用例设计**：基于需求规格与页面 ↔ 接口对照表编写，每个功能点覆盖正常 / 异常 / 边界；等价类划分与边界值分析；反向用例占比 ≥30%；涉及预测结果准确性、数据一致性的用例标为重点（★）。
2. **用例规模**：功能 / 异常 / 边界 24 条 + 非功能 6 条，共 30 条，见 [`test_cases.md`](test_cases.md)。反向 15/24 = 62.5%，重点 5 条。
3. **执行方式**：真实环境黑盒走查 —— 浏览器四页面 + 真实 HTTP 请求 + 独立子进程构造异常（不移动真实权重、不影响主服务）；自动化脚本复现命令见 [测试交付总说明](../overview.md) §5。
4. **缺陷管理**：按 Bug ID、标题、级别（致命 / 严重 / 一般 / 轻微）、复现步骤、预期 / 实际结果、截图、状态、来源登记，跟踪到关闭，见 [`bug_list.md`](bug_list.md)。无法复现的观察列入「候选」，不计入缺陷数。
5. **AI 辅助边界**：用例初稿、性能脚本骨架可由 AI 生成，但核心业务断言、复现步骤、截图与结论须人工复核；本轮按项目方授权由 AI 代写文档，后续人工修订（AI-R3 / R4 / R5 风险已在各文档标注）。

## 6 · 风险评估

| 风险 | 影响 | 应对 |
|---|---|---|
| 模型权重与大体量产物不入库（`.pkl` / 语义表 / 文本表） | 干净检出下 semantic / fused / e2e 降级，25 模型在线矩阵只有 23/25 | #217 补生成步骤；#222 修复 CUDA 权重后跑 `online_models_matrix.py` 至 25/25 |
| 10 并发 × 10 请求 p95 = 694.0ms 超 500ms 判据 | 高并发下延迟劣化，原因未定位 | 复测并定位（模型懒加载 / 同机资源争用），见性能报告 §3 |
| 浏览器只覆盖 Chromium | 兼容性维度缺 2 个浏览器 | 补 Chrome / Edge / Firefox 逐页走查截图 |
| 真实 MySQL 与浏览器走查不能由 CI 代测 | 证据依赖人工现场执行 | 固定复现命令与环境，逐条留痕 |
| 证据 SHA 与最终交付提交不一致 | 历史绿灯不能当本次结果 | 按同一 SHA 重跑并更新全部产物 |
| AI 生成用例与文档未经人工审核签署 | AI-R3 / R5 扣分甚至该部分计 0 分 | 人工逐条复核、修订来源标注与结论 |
