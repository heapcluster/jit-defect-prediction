# 约束

描述执行时必须遵守的工程约束：写在哪、怎么放、怎么跑、怎样算完成。一个主题一篇。

## 主题

| 文件 | 内容 |
|---|---|
| `tech-stack.md` | 语言、框架、依赖管理、启动与构建命令 |
| `directories.md` | 仓库目录分层，新增文件应放的位置与命名 |
| `artifacts.md` | 产物路径、manifest、校验和、下载约定、模块间文件交换 |
| `job-state.md` | 任务类型、状态流转、取消与重试、轮询约定 |
| `enums.md` | 全系统枚举与值域的唯一真源 |
| `verification.md` | 验证命令、测试入口、完成定义 |

## 单篇模板

结论 / 适用范围 / 约束条目 / 校验方式

## 编写规则

1. 只写可执行的约束，不写理念；每条约束要能被命令、配置项或代码结构校验。
2. 跨包重复出现的机制（信封、任务状态、枚举、产物路径）只在本包定义一次，其它包引用。
3. 约束与实现不一致时，先确认约束是否仍成立，再改代码或改约束，不允许两边各说一套。
