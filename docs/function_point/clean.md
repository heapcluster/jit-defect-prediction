# 功能点 3 数据清洗与预处理

一句话：选择数据收集保存的数据集，配置常用清洗操作与预处理操作，生成清洗后数据集与每步前后差异，并支持全量分页预览和下载。

collected_commits 列契约、clean_dataset 列契约、manifest 契约；API 见 [`../api/clean.md`](../api/clean.md)；页面见 [`../web_page/clean.md`](../web_page/clean.md)。

## 1 职责

- 从数据收集已入库的数据集中选择一份，校验其 schema 与状态。
- 配置常用清洗操作与预处理操作；操作顺序和互斥参数由后端约束。
- 执行 `schema_validate`、重复处理、缺失处理、非法时间过滤、标签校验、基础预处理等步骤。
- 记录每步前后行数、删除行数、修改行数、标签分布与字段级变化明细。
- 用表格展示每步前后差异，不生成 PNG 变化图。
- 发布清洗后数据集，自动保存到数据集库，并提供 CSV / Excel 下载。
- 提供清洗后数据分页预览，支持浏览全量行与全部字段。

## 2 不负责

- 不做 SZZ、D5、Git 拉取；不重新打标。
- 不做 Kamei 14 维、语义向量、融合特征或模型特征构建。
- 不做 `log_transform`、`standardize`、`categorical_encode`、`feature_select` 等训练侧变换。
- 不做训练 / 测试切分；输出不得包含 `is_test`。
- 不写 `dataset` / `dataset_commit` 业务表；入库走 storage 导入端点。
- 不把 manifest、steps_stats 等内部记录包装成用户结果文件。

## 3 输入

Web 页面固定从「数据收集保存的数据集」中选择：

- `status=ready`；
- schema 符合 `collected_commits`；
- 来源为 Git 仓库收集结果；
- 通过 `GET /api/datasets` 获取候选数据集，通过 `dataset_id` 传给清洗任务。

API / CLI 仍可直接上传 `collected_commits.csv` 与同名 manifest，保持模块独立运行能力。

主表列严格采用 `collected_commits` 列契约（字段定义见 [`../database/commit.md`](../database/commit.md) 与 [`../api/storage.md`](../api/storage.md)）；不要求 14 维特征列。配置字段：

- `mode`：页面固定 `apply`；API / CLI 可使用 `preview`。
- `steps[]`：启用操作与参数；`schema_validate` 必须首项且启用。
- `output_name / dataset_name`：页面字段为“数据集 / 导出文件名称”，一个字段同时作为入库名称与下载文件基础名。

## 4 流程

1. 页面加载数据收集数据集候选与清洗操作元数据。
2. 用户在 01 选择数据集，查看信息卡；可展开前 20 行样本确认内容。
3. 切换数据集时保留输出名称，清空字段相关配置、结果、图表、预览和结果文件。
4. 用户在 02 分别配置“常用清洗操作”和“预处理操作”；参数只显示中文标签与中文选项。
5. 用户在 03 填写或修改数据集 / 导出文件名称，核对配置摘要；页面不设置对比图配置。
6. 用户在 04 点击 [开始清洗]，任务按“校验数据集 → 执行清洗 → 生成变化图 → 生成结果预览 → 完成入库”推进。
7. 后端按固定顺序执行处理链，记录每步统计与样本明细。
8. 后端自动生成两类变化图：每步前后数据集变化图、系统选定关键特征变化图。
9. 成功后清洗后数据集自动保存到数据集库；保存失败不影响文件下载。
10. 结果区展示分页预览，用户可在结果文件区下载清洗后数据集。

## 5 输出

用户可见核心产物只有一份：

```text
clean_dataset_<job_id>.csv     # 或 <output_name>.csv
```

下载：

- `format=csv`：直接返回规范主表；
- `format=xlsx`：下载时从同一 CSV 即时生成单 sheet XLSX，不落盘、不登记。

分页预览：

- `GET /api/clean/preview/{job_id}?page=&size=`
- 默认每页 20 行，支持浏览全量清洗后数据；
- 展示全部字段，前端横向滚动，不压缩列。

内部记录（不属于页面结果文件）：

```text
<stem>.manifest.json
clean_steps_stats_<job_id>.json
```

差异展示策略：

- 页面不提供“生成对比图”开关或列名多选；
- 后端在 `steps_stats` 中记录每步行数、缺失、重复、标签分布及字段级前后值；
- 结果区用表格展示这些差异，不生成 PNG 变化图；
- API / CLI 同样不接受 `chart_columns`。

## 6 约束

- `schema_validate` 必须第一步且不可关闭。
- 清洗操作必须先于预处理操作。
- 预处理只做数据格式与展示字段处理，不生成模型特征。
- 输出保持 collected_commits 列契约 原始列，可追加 `message_length`、`parent_count`、`commit_hour` 等基础列。
- 不输出 `is_test`；未打标保持 null。
- 结果文件区只展示「清洗后数据集」一个逻辑文件；内部记录不展示。
- Excel 格式在下载时生成，避免 CSV / XLSX 双份冗余。
- 相同输入与配置，主表、统计和图数值一致。

## 7 验收

- 页面为四步：选择数据集、清洗与预处理配置、确认输出与配置、运行。
- 页面没有独立的“生成对比图”步骤，也没有对比图开关或列多选。
- 结果区用表格展示每步前后差异与字段级变化，不生成 PNG 变化图。
- 01 只列数据收集保存的可用数据集，不提供手动上传。
- 选择数据集后显示完整信息卡，并提供前 20 行样本查看入口。
- 数据集切换时保留输出名称，清空字段相关配置、结果、差异、预览和结果文件。
- 02 显示“常用清洗操作”和“预处理操作”两个用户可见分组。
- 操作名、参数标签和选项全部中文化，不暴露 `strategy`、`keep`、`iqr` 等原始字段。
- 预处理不生成模型特征，不提供训练侧变换。
- 03 使用单一“数据集 / 导出文件名称”字段，默认 `<原数据集名>清洗后`。
- 03 配置摘要不出现列选择或变化图配置。
- 04 运行按钮占满整行，进度按五个用户语言阶段展示。
- 清洗后数据预览支持分页浏览全量行，展示全部字段，默认每页 12 行。
- 结果文件区只有一个「清洗后数据集」逻辑文件；下载菜单只有 CSV 与 Excel。
- manifest / steps_stats 等内部记录不出现在结果文件区。
- 成功后自动保存到数据集库，保存状态在结果摘要中显示；保存失败不影响下载。
- 历史清洗结果只在 `/storage` 产物库查看、下载与删除。

## 8 边界

clean 只负责“把数据集整理成更适合后续查看、分析与训练的格式”。它与训练之间不共享运行状态，只通过清洗后数据集与 manifest 交接；是否使用清洗结果作为训练输入由用户在训练页选择。
