# 数据同步

**一句话**：把 Git 源仓库的提交「取下来 → 抽特征 → 打分 → 入库」。它支撑前端 **风险列表的「补齐」按钮**，是系统里唯一会触发计算的能力。

## 对应前端功能
| 页面 / 入口 | 用这个功能点的哪部分 |
|---|---|
| 风险列表「补齐」按钮 | 选线 → 选模型 → 选时间 → 确认，异步补算该范围 |
| 风险列表「补齐缺口」按钮 | 按条数追最新 |
| （运维/演示） | 手动触发增量或补齐到 HEAD |

## 各层职责
| 层 | 职责 |
|---|---|
| 模型线 | 提供单条现算特征 + 推理能力 |
| 后端 | `POST /api/sync`（按条数 / 按 line / 按 model_name / 按时间区间）与 `catchup` 拉取并补算；`GET /api/sync/status` 状态；`GET /api/sync/stream` SSE 进度（当前前端未接） |
| 数据库 | `commit` / `commit_feature` / `prediction` 写入 |

## 分工口径
- 本功能点是**唯一**会触发计算的能力。列表（`/api/commits`）、趋势（`/api/trends`）全部只读已入库结果。
- 前端「查询」不补算，「补齐」弹窗才补算，且**异步**：提交即返回，靠 `/api/sync/status` 轮进度。
- 同一时刻只允许一个同步任务（服务端串行锁），并发请求返回「已在同步中」。

## 验收
- 增量 / 补齐同步幂等：同一批重复提交不产生重复行；
- 状态可查、进度可订阅；异步任务在请求返回后继续跑，前端不靠超时判断成败；
- 按 `line` / `model_name` / `start_time` / `end_time` 补算时，边界外提交与未选中的线/模型 MUST NOT 被算进来；
- 单条现算耗时以实测为准（P50 ≈ 108 秒），验收文档与页面文案不得写成秒级。
