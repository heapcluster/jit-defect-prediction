# 提交风险预测

**一句话**：给一次提交算出缺陷概率并落库。它支撑前端 **风险列表、提交详情、趋势看板、模型性能看板** 四个页面的「分数从哪来」。

## 对应前端功能
| 页面 / 入口 | 用这个功能点的哪部分 |
|---|---|
| 风险列表 | 用查询栏的架构 → 模型两级级联 + 独立时间范围查已存分数（刷新走同步范围行，见 sync） |
| 提交详情 | 展示选中模型的 `risk_score` + `predicted_at` + 14 维特征 + 解释因子 + SZZ 真标签 |
| 趋势看板 | 按选中模型聚合出提交数与高风险数两条趋势 |
| 模型性能看板 | 多维表格里所选模型的 `risk_score` 列（概率），随模型切换刷新 |

## 两条路径（不要混）
| 动作 | 干什么 | 耗时 | 入口 |
|---|---|---|---|
| **查已存** | 按架构 → 模型两级级联 + 独立时间范围读 `prediction` 里已有的分数；模型性能表另读测试集 14 维与 SZZ 真标签 | 毫秒级 | `GET /api/commits`、`GET /api/commits?with_features=1&is_test=1`、`GET /api/commits/{commit_hash}`、`GET /api/trends` |
| **补算** | 对库里没有的提交现场抽特征 + 推理并入库 | **P50 ≈ 108 秒/条**（实测） | `POST /api/sync`（前端「刷新」，按架构/模型/时间区间）、`POST /api/predict`（单条） |

前端「查询」只走第一条；补算（`POST /api/sync`，按架构 / 模型 / 时间区间）才走第二条，且**必须异步**：提交即返回，靠 `/api/sync/status` 轮进度。

## 各层职责
| 层 | 职责 |
|---|---|
| 模型线 | 训练并交付模型（四方案 25 模型，先 expert 8 在线），提供现算能力 |
| 后端 | 读取路径只查 `prediction`；写入路径 `POST /api/predict` / `/api/sync` 现算并落库（幂等） |
| 前端 | 风险列表 / 趋势 / 模型性能统一用架构 → 模型两级级联 + 独立时间范围（前两级数据源 `GET /api/models`）；详情用架构 → 模型级联；未预测的提交显示为缺行，不显示风险 0 |

## 验收
- 给定 commit + `model_name` 能返回风险分；风险等级（高/中/低）由前端按 `risk_score` 与阈值常量判定（与后端 `.env` 的 `HIGH_RISK_THRESHOLD` / `MID_RISK_THRESHOLD` 同值，见前端 `utils/risk.js`）；接口不返回等级、不返回阈值；
- 未预测的提交在列表与模型性能表里表现为**缺行**、在详情里表现为 `risk_score` / `predicted_at` 为 `null`，前端必须显示「未预测」而非风险 0；
- 详情返回 `predicted_at`（选中模型的预测时间）与 `is_defect`（`1` / `0` / `null`）；未打标的提交不得显示成非缺陷；
- 补算幂等：同一提交重复请求不产生重复行；
- 补算异步：前端不靠超时判断成败，靠 `/api/sync/status`；
- 页面文案与测试报告里的耗时数字一律用实测值，不得沿用旧的「4 秒」。
