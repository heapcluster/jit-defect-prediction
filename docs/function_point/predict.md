# 提交风险预测

纵向功能点：给一次提交算出缺陷概率并落库，供列表、详情、趋势与测试集评估消费。跨模型线、后端、前端。

## 两条路径（不要混）
| 动作 | 干什么 | 耗时 | 入口 |
|---|---|---|---|
| **查已存** | 按**选中模型 + commit 时间区间**读 `prediction` 里已有的分数 | 毫秒级 | `GET /api/commits`、`GET /api/commits/{hash}`、`GET /api/trends` |
| **补算** | 对库里没有的提交现场抽特征 + 推理并入库 | **P50 ≈ 108 秒/条**（实测） | `POST /api/sync`（按条数或按时间区间）、`POST /api/predict`（单条） |

前端「查询」只走第一条；「补齐缺口 / 补齐这段时间」才走第二条，且必须是后台任务 + 进度查询。

## 各层职责
| 层 | 职责 |
|---|---|
| 模型线 | 训练并交付模型（四方案 25 模型，先 expert 8 在线），提供现算能力 |
| 后端 | 读取路径只查 `prediction`；写入路径 `POST /api/predict` / `/api/sync` 现算并落库（幂等） |
| 前端 | 风险列表 / 提交详情展示选中模型的 `risk_score` 与判定；未预测的提交要看得见、点得动补算 |

## 验收
- 给定 commit + `model_name` 能返回风险分，判定与运行时阈值一致；
- 未预测的提交在列表里表现为**缺行**、在详情与明细里表现为 `risk_score = null`，前端必须显示「未预测」而非风险 0；
- 补算幂等：同一提交重复请求不产生重复行；
- 页面文案与测试报告里的耗时数字一律用实测值，不得沿用旧的「4 秒」。
