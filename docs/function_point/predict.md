# 提交风险预测

**一句话**：给一次提交算出缺陷概率并落库。它支撑前端 **风险列表、提交详情、趋势看板** 三个页面的「分数从哪来」。

## 对应前端功能
| 页面 / 入口 | 用这个功能点的哪部分 |
|---|---|
| 风险列表 | 按「线 → 模型 + 时间区间」查已存分数；看到缺口点「补齐」触发补算 |
| 提交详情 | 展示选中模型的 `risk_score` + 14 维特征 + 解释因子 |
| 趋势看板 | 按选中模型聚合出风险度折线 |

## 两条路径（不要混）
| 动作 | 干什么 | 耗时 | 入口 |
|---|---|---|---|
| **查已存** | 按线 → 模型 + 时间区间读 `prediction` 里已有的分数 | 毫秒级 | `GET /api/commits`、`GET /api/commits/{commit_hash}`、`GET /api/trends` |
| **补算** | 对库里没有的提交现场抽特征 + 推理并入库 | **P50 ≈ 108 秒/条**（实测） | `POST /api/sync`（选线/模型/时间区间/按条数）、`POST /api/predict`（单条） |

前端「查询」只走第一条；「补齐」弹窗（选线 → 选模型 → 选时间 → 确认）才走第二条，且**必须异步**：提交即返回，靠 `/api/sync/status` 轮进度。

## 各层职责
| 层 | 职责 |
|---|---|
| 模型线 | 训练并交付模型（四方案 25 模型，先 expert 8 在线），提供现算能力 |
| 后端 | 读取路径只查 `prediction`；写入路径 `POST /api/predict` / `/api/sync` 现算并落库（幂等） |
| 前端 | 风险列表两级选择器（line → model）+ 查询；未预测的提交给「补齐」入口；趋势看板同样支持线/模型切换 |

## 验收
- 给定 commit + `model_name` 能返回风险分，判定与 `.env` 写死阈值一致；
- 未预测的提交在列表里表现为**缺行**、在详情与明细里表现为 `risk_score = null`，前端必须显示「未预测」而非风险 0，并给「补齐」入口；
- 补算幂等：同一提交重复请求不产生重复行；
- 补齐异步：前端不靠超时判断成败，靠 `/api/sync/status`；
- 页面文案与测试报告里的耗时数字一律用实测值，不得沿用旧的「4 秒」。
