# 文档写作规范（common 包权威）

> 合并自原 `docs/writing-norms.md`（已并入本文件）v1.2 ｜ 主笔：蒋励 ｜ 审核：苏哲勋
> 课程把「技术设计文档」列进 40 分过程实践维度，且要求需求变更同步 OpenSpec 记录。

## 1. 命名规则

- 仓库文档：全小写、单词间 `-`、一律 `.md`、一文件一主题、不放日期（导出件除外）、目录说明用 `README.md`。
- 禁止：`新建文档.md` `临时.md` `草稿.md` `xxx_final_v2.md` 中文名。
- 飞书：周报 `工作周报-日期`；PRD `产品需求文档`；设计 `产品设计文档`；看板 `JIT 缺陷预测 · 项目看板`。

## 2. 注释格式

| 层 | 写什么 |
|---|---|
| 文件头 | 干什么 + 输入/输出/怎么跑 + 坑 |
| 函数 | 参数/返回/异常/为什么 |
| 行内 | 只写「为什么」 |

- Python 公开函数必有 docstring；文件头含 输入/输出/运行命令；中文注释。
- JS/Vue：每个组件顶部写「用接口的哪些字段」；三态必须注释标明。
- SQL：建表逐表一行说明；字段名照契约一不自创。
- 不写：复述代码、注释掉的死代码、无责任人的 TODO（写 `# TODO(谁, 日期): `）。

## 3. Markdown 排版

- 一级标题只有一行；`##` ≤10 个；每份文档开头有文件头 `> 版本 X.Y ｜ 更新 ｜ 主笔 ｜ 审核`；末尾有变更日志（日期/版本/变更人/主要变更）。
- 主笔与审核写真人名，审核≠主笔。
- 表格用于可枚举对照；命令给可复制完整命令。

## 4. 版本号

- 小改/加章节/改口径 → 0.1；整体重构 → 1.0。
- 跨分支并行改同文档：版本号按合并顺序预留，理由写进变更日志（不只在 PR 描述）。
- 重编号后必须全仓扫引用点（契约索引表/各线 README/规范文档/openspec/**/已发 PR 描述）。

## 5. 周报模板（硬规矩）

- 命名 `工作周报-日期`，每周五晚交；模板结构不得改（不增删表/改表头/改列/加章/改说明/换块类型）。
- 比对基线：`docs/common/templates.md`（原 `docs/templates/weekly-report-template.md`）；合并前六项打勾全过，留痕结论。
- 三张表：本周计划（细到谁做哪件事）/ 本周总结（实测值，没做完写进待改进）/ 下周计划（粗到方向）。
- 禁止：当聊天记录、只写自己部分、改模板、漏交、全文粘仓库文档。
