# OpenSpec `tasks.md` 统一模板

适用新建和正在推进的 `openspec/changes/<change-id>/tasks.md`。完整协作规则与目录入口见 [`../../openspec/README.md`](../../openspec/README.md)。`changes/archive/` 保留历史原貌，不为统一排版回改。

## 文件头

```markdown
# <change-id> — 任务清单

> 提案：`proposal.md` ｜ 设计决策：`design.md` 或“无（原因）” ｜ 规格：`specs/<capability>/spec.md` 或“无（纯重构）”
> 负责人：<模块与姓名> ｜ 创建：<YYYY-MM-DD> ｜ 状态：未开始 / 进行中 / 已验收 / 已归档
> 关联需求：<飞书需求或用户故事链接/编号；纯工程化写“无（工程化）”>
> 统一格式：`docs/common/openspec-task-template.md`；末尾“测试与验证”必须保留。
```

## 任务正文

```markdown
## 1. <阶段或交付主题>

- [ ] 1.1 <可验证的动作> — <仓库相对路径、接口或其他交付物>；验收：<检查方法与预期结果>
- [ ] 1.2 <跨线动作> — 交给 <模块/负责人> 的 <文件或接口>；验收：<双方核对方法>

## 2. <下一阶段>

- [ ] 2.1 ...
```

阶段号从 1 连续，任务编号在阶段内连续。`[x]` 表示任务交付物已完成，**不代表验证或验收通过**。任务范围变化时在对应项说明原因；不要倒填已经发生但没有证据的结果。

## 测试与验证（放在 `tasks.md` 最后）

复制以下五节，再把占位符改为真实内容。未执行时写清原因、负责人及后续计划，不写“已通过”。纯文档或纯重构可写“不适用”及理由，但五个标题仍保留。

```markdown
## 测试与验证（强制板块）

### 1. 单元测试
- 覆盖对象与测试文件：`<仓库相对路径>`
- 前置条件与复现命令：`<实际可运行命令>`
- 结果与关键断言：<正常、边界或异常场景；实际 passed/failed 数>

### 2. 集成测试
- 对接范围与测试文件：`<仓库相对路径>`
- 前置条件与复现命令：`<实际可运行命令>`
- 结果与跨模块断言：<接口、字段、错误码、数据库或模型行为>

### 3. 验收测试
- 对应 Requirement / Scenario：`<change 内规格路径与标题>`
- 步骤或命令：`<可复现步骤>`
- 实际结果与证据：`<仓库相对路径或 PR/CI 链接>`

### 4. 非功能验证
- 性能 / 安全 / 可靠性 / 易用性：<触及项的测试和证据；不触及项写理由>

### 5. 已知缺口与后续计划
- 缺口：<未覆盖或未通过的具体项；确无缺口写“无”>
- 原因、负责人、计划时间：<逐项对应>
```

## PR 自检

1. 任务与 proposal 的范围一致；行为变更对应的 Requirement/Scenario 可追到任务和验证。
2. 命令、前置条件和证据路径可复现；`[x]` 与实际结果一致。
3. 跨线交付有接收方和交付物；未完成项未被写成已验收。
4. 格式小差异作为评审建议；缺少验证路径、虚假证据、契约冲突或可复现的运行故障才阻断合入。
